# 个人对话智能体

完整对话执行使用 LangGraph `StateGraph` 编排工具决策、上下文准备、长期记忆召回、附件清单与按需读取、最终回答和消息终态。同步与流式入口共享同一张完整回答图。LangGraph 是应用编排层；Mem0 仍通过独立 Docker API 管理长期记忆，业务 PostgreSQL 继续保存会话、授权、用量和外部操作的幂等事实。架构边界见 [ADR 0007](docs/adr/0007-langgraph-agent-orchestration.md) 与 [ADR 0011](docs/adr/0011-conversation-document-tools.md)。

交接说明见 [LangGraph 重构交接文档](docs/handoff-langgraph.md)。

回答流程为 `prepare_context → agent → finalize`；内部由模型决定是否进入工具循环。后端不按“记住、忘记、修改记忆”等关键词分类请求或隐藏图片，统一提供当前会话的有效文档清单、图片 file_id 和可用工具。附件所属账号、会话及有效期仍在读取时核验。

各节点通过 State 返回并共享消息、材料来源、工具结果、回答及错误；`runtime.context` 只保存本次运行固定的身份、模型配置和传输方式。外层图不再挂 PostgreSQL checkpointer；迁移 052 已删除旧 `langgraph` schema。聊天正文、流式增量、操作幂等及用量仍保存在现有业务表。运行与持久化的边界见 [ADR 0012](docs/adr/0012-state-based-conversation-flow.md)。

2026-10-17：附件只用于当前会话的问答和资料处理，不再从附件提取长期记忆。聊天记忆仍使用 Mem0 原生自动记忆和对话记忆工具；详见 [ADR 0005](docs/adr/0005-native-automatic-memory.md) 与 [ADR 0006](docs/adr/0006-attachments-do-not-create-memories.md)。

当前已实现本机 Web 对话、预创建多账号登录、独立管理端、模型配置与独立嵌入、会话持久化、流式回答、停止与失败重试、逐次调用用量、通过独立 Mem0 服务自动提取、更新、删除和召回长期记忆，以及会话 TXT / Markdown / PDF / DOCX 文档集合与工具读取、PNG / JPEG 文件上传与视觉问答和模型工具联网搜索。任务 16 的历史聊天检索已按任务 20 移除；附件不提供独立总结任务；模型通过两个工具自主检索和读取。附件不会生成长期记忆，切片关键词索引保存在业务 PostgreSQL，独立于 Mem0。

主智能体现可在一次回答内按需创建最多六个子智能体，通过 `wait_agents`、`send_agent_message` 和 `cancel_agent` 等待、追加或取消任务。`spawn_agent` 可提供任务级 `instructions`，只用于细化方法、重点和交付方式；固定安全规则由后端持有。子智能体复用时间、附件、知识库和网页公共工具，但不继承记忆写入或编排权限，也不能继续创建下一层；主智能体只汇总实际交付的结果与来源。实现与验收边界见[主从 Agent 规格](.scratch/multi-agent/spec.md)及 [ADR 0017](docs/adr/0017-main-and-subagent-orchestration.md)。

独立知识库已于 2026-10-23 接入：从侧栏“知识库”创建资料库，上传 PDF／Word／TXT／Markdown 并查看解析、图片描述、切片和索引进度；回到会话，在输入区绑定一个或多个知识库后提问，模型只自主决定是否调用 `search_knowledge(query)`，后端固定使用会话绑定范围召回。知识库使用独立的文档、图片和切片表，复用现有处理与召回算法，详见[知识库规格与任务](.scratch/knowledge-base/spec.md)及 [ADR 0015](docs/adr/0015-independent-knowledge-bases.md)。现有附件仍属于原会话并保留 30 天。

知识库召回先按相关性选出切片，再按原文顺序交给模型。模型依据切片回答时使用实际返回的 `[K编号]`；回答下保留实际引用的知识库、文档和原文位置。普通正文显示摘录，表格引用渲染为可视化表格，图片引用只显示受保护的账号原图；图片描述仅用于检索和模型理解。未知编号不会显示为可信来源。

遇到图片时，以“图 03 …”一类图号开头的图注会绑定到同段或最近相邻图片，并从普通文字切片中排除。视觉模型同时接收图注和原图后生成描述，图片切片保留原文位置与图注，避免图注被拆到其他切片。

知识引用和媒体展示使用两套标记：`[K编号]` 表示回答使用了对应切片；如果模型判断直接展示本次召回的图片或表格更方便理解，可以另起一段写 `[[MEDIA:K编号]]`。前端把图片或表格插入该段之后，并在文末为所有实际引用生成去重后的原文来源链接。

正文中的知识引用显示为小号右上标 `[1]`；文末参考来源只展示文件名、位置和定位链接，不再重复切片正文。长回答要求使用清晰的 Markdown 章节层级、段落空行、列表和表格间距。

行内图片采用与正文一致的宽度和留白，不显示卡片边框或图片下方说明。参考来源中只有普通文字切片会显示一行省略摘要；图片和表格来源仍只显示文件与位置。

知识库原件及图片保存在 `APP_DATA_DIR/knowledge/<文档 UUID>/`，长期保存至用户删除；备份时需与业务 PostgreSQL 一起保留。向量在入库时生成，未配置或生成失败时显示告警并使用关键词检索，可点击“重试处理”；单张图片失败不影响已有正文。切换嵌入、切片、解析或视觉版本后，启动会重建对应索引，失败重试复用已完成的图片描述与当前版本向量。清理失败的对象保留“重试清理”入口。

此前任务 01–18 整合版通过 179 项 Python 测试及 23 项浏览器测试，真实服务待验范围、审查修复和数据保留检查见 [整体交付验证](docs/verification-final.md)。

## 启动

需要 Docker Desktop（已启动）、Python 3.12+、uv、Node.js 22.12+ 和 pnpm 11.25.0。项目锁定 Python、前端依赖及 PostgreSQL 基础镜像摘要。首次启动需要访问 Docker 和 GitHub。

在项目根目录执行：

```sh
bash scripts/start.sh
```

脚本安装锁定的依赖、构建前端，启动业务 PostgreSQL、独立 Mem0 PostgreSQL 和官方 Mem0 API，随后在前台启动应用。若电脑安装了 Codex 自带运行时，脚本也会尝试使用它；可通过 `GENERAL_AGENT_PYTHON` 指定其他 Python。浏览器打开 [本机应用](http://127.0.0.1:8000)，Mem0 API 仅监听 `127.0.0.1:8888`。

在设置中输入服务商提供的 API 基础地址（通常以 `/v1` 结尾）、文字模型名称和 API 密钥，然后新建会话并发送消息。接口使用 OpenAI 兼容的 Chat Completions；保存配置只表示连接信息已写入本机，实际可用性由后续调用结果反馈。云端地址使用 HTTPS，本机服务允许回环 HTTP。更换服务地址需重新填写密钥；同一地址留空密钥会保留原密钥。

回答会逐段显示，页面和 PostgreSQL 都保留生成中、完成、已停止或失败状态。点击“停止生成”会冻结当前回答，不再追加后续文字；已经发出的模型请求会继续接收可返回的用量，因此停止不保证撤销服务商费用。浏览器断开或切换会话不会自动停止后端生成，重新进入后会恢复进度。

最新失败或停止的回答可点击“重试回答”；重试保留旧尝试及部分内容，创建新的调用记录，不重复插入用户消息。模型流式连接中断或响应超时会在同一回答内自动尝试最多三次，每次真实请求独立记录用量；已有正文会作为 assistant 前缀连同原上下文重新发送，并用临时用户指令要求模型从断点直接续写。恢复成功后在正文断点显示“连接中断 · 已自动恢复并继续”，刷新后仍保留；连续恢复失败才标记为未完成。输出长度限制、认证和参数错误不自动重试。服务必须支持 Chat Completions 的 SSE 流式响应、结束标记与 stream_options.include_usage。

设置页展示最近 100 次调用的状态以及服务返回的 token 或 credits。服务未返回用量时保留空值；重试产生新的实际调用记录。应用不维护价格、不估算费用，真实计费以服务商账单为准。

按 Ctrl+C 停止应用。停止数据库可执行 `docker compose stop`；再次启动后数据仍保留。数据库默认仅监听 `127.0.0.1:15432`，应用仅监听 `127.0.0.1:8000`。

## 登录与账号

系统不开放注册。首次启动预置管理员 `admin / 123456`，第一次登录会强制设置至少 10 个字符的新密码。普通用户从 `/` 登录聊天，管理员从 `/admin` 登录独立管理端；管理员账号只用于管理，不进入用户聊天界面。

系统只有一个固定的 `admin` 管理员账号。管理端可以创建、停用或启用普通用户，生成仅显示一次的临时密码，并查看普通用户仍有效的会话、消息、附件、记忆、搜索记录和调用用量；不能代发消息或修改用户内容。管理端提供会话检索、图片与 PDF 附件预览，以及可筛选的访问审计。模型、嵌入和搜索配置只在管理端的“系统配置”中修改。

管理员与普通用户的凭据分表保存，两个入口使用独立登录会话和 Cookie，可以在同一浏览器同时登录。Cookie 为 `HttpOnly`、`SameSite=Lax`，有效期 7 天；HTTPS 访问时自动加 `Secure`。退出、改密、重置密码或停用普通用户账号会吊销相应旧会话。本期不提供登录失败次数限制或账号锁定，这是已接受的个人项目风险。

唯一管理员忘记密码时，在服务器本机设置 `DATABASE_URL` 后运行 `uv run python scripts/recover_admin.py`，按提示输入两次新密码。命令会吊销旧管理员会话并留下恢复审计；网页不提供管理员密码找回。

`.local/`、环境文件、依赖和构建产物均已排除 Git。业务后端只通过 `MEM0_API_URL` 调用官方 Mem0 REST API，不导入 Mem0 SDK、不直接访问 Mem0 数据库，也不在业务库复制记忆正文或向量。附件原文件与业务 PostgreSQL 中的派生文本分别保存。密钥仅由后端和一次性配置容器读取，配置接口不回传完整密钥；模型错误正文不会直接展示。

可用环境变量：`DATABASE_URL` 指定业务 PostgreSQL；`MEM0_API_URL` 指定 Mem0 API；`MEM0_API_KEY` 设置可选认证；`APP_DATA_DIR` 指定本机配置目录；`POSTGRES_PORT` 修改业务数据库宿主端口；`PUBLIC_HOST` 指定公网临时主机名；`COOKIE_SECURE=true` 可强制登录 Cookie 使用 `Secure`（HTTPS 反向代理下会自动启用）。Mem0 使用账号 UUID 作为用户空间，不再使用固定 `MEM0_USER_ID`。

LangSmith 追踪读取应用数据目录中的 `langsmith.json`（默认 `.local/langsmith.json`，已排除 Git），也支持同名环境变量且环境变量优先：

```json
{
  "LANGSMITH_TRACING": "true",
  "LANGSMITH_AGENT_ID": "general-agent",
  "LANGSMITH_AGENT_ENVIRONMENT": "local",
  "LANGSMITH_ENDPOINT": "https://api.smith.langchain.com",
  "LANGSMITH_API_KEY": "填写自己的密钥"
}
```

配置文件应使用 `chmod 600 .local/langsmith.json` 限制访问，修改后重启后端生效；Docker 部署需将该文件放入服务器挂载的 `.local/`。上述配置绑定 LangSmith 智能体 `general-agent` 的 Local 环境；独立追踪项目则改用 `LANGSMITH_PROJECT`，不要与两个 `LANGSMITH_AGENT_*` 同时设置，同名独立项目与智能体环境并非同一追踪目标。未配置时不开启追踪。启用后，LangGraph 节点及自定义模型调用会嵌套上报到目标环境，包含模型输入消息、工具参数、输出及真实 token 用量；模型连接密钥和客户端对象不进入模型追踪输入。追踪元数据使用会话 ID 和回答尝试 ID 关联，各节点输出可直接观察 State 更新；模型配置和凭据不放入 State。Mem0 独立服务内部的模型与嵌入调用不在本应用追踪范围内。接入方式遵循 [LangSmith 官方 LangGraph 追踪说明](https://docs.langchain.com/langsmith/trace-with-langgraph)。

数据库结构在应用启动时按版本迁移，已应用的迁移不会重复执行。应用使用单个后端进程运行；启动时会将上次进程中断的生成记录标为失败并保留已提交的内容与用量，请勿用多个 worker 共用同一业务库。请保留数据库卷；`docker compose down -v` 会删除其数据。

## 独立嵌入配置（任务 03）

设置页提供独立嵌入连接。保存配置只更新本机文件，不会发出云端请求，也不会预先探测文字、图片或工具调用能力；这些能力由真实对话、图片请求和工具回合直接反馈。

嵌入连接单独保存 API 地址、模型名称、密钥和预期维度。可以显式选择复用已保存聊天服务的地址与密钥，嵌入模型和维度仍需独立填写；复制后两套连接各自管理。嵌入服务由 Mem0 在后续记忆调用中使用；地址、密钥、模型或维度不匹配时，错误会在实际调用中反馈。若服务使用别名，请填写实际可用的模型标识，不能仅凭文字调用成功认定嵌入可用。

嵌入配置保存在 `.local/embedding.json`，与 `.local/model.json` 一样由本机后端以仅当前用户可读写的权限原子保存。配置版本随连接实际变更更新。重启 Mem0 Compose 后，一次性 `mem0-config` 容器会把聊天模型与嵌入配置提交给官方 `/configure`。完整密钥不出现在读取响应或应用日志中。

业务应用不拥有 Mem0 的向量空间。更换嵌入服务、模型或维度后，应重启 Mem0 服务，由 Mem0 自己管理其索引；本项目不提供本地重建、代次表或向量迁移接口。实际可用性和相关性质量需要通过真实记忆调用验收。

`pnpm --dir frontend test:e2e` 运行当前保留的会话、资料、图片、搜索和来源删除浏览器流程。实现边界、接口与历史测试证据见 [任务 03 验收记录](docs/verification-03.md)。


## 调用用量

同步与流式聊天、记忆工具和搜索通过应用调用网关；Mem0 内部模型与嵌入调用由独立服务负责。业务 PostgreSQL 保存稳定操作身份、调用状态和应用侧可取得的 token 或 credits。应用不维护价格、费用估算或月度消费额度。


## 自动记忆、查看和对话工具

本次策略变更、受控测试与真实服务待验范围见[原生记忆验证记录](docs/verification-native-memory.md)。

先在设置中填写独立嵌入服务、模型与维度。聊天服务支持文字对话不表示它提供嵌入；缺少嵌入时普通聊天可用，自动记忆会明确提示缺少配置，补齐后可独立重试。

普通用户事实由 Mem0 原生 `infer=True` 流程提取和维护，不再逐条确认。纯提问、资料操作和不保存指令不会触发自动提取，不回填旧聊天。前端不展示长期记忆管理页；真实记忆正文、向量和历史应从独立 Mem0 存储核对，业务 PostgreSQL 只保留来源、动作和恢复状态。明确的“请记住：具体事实”仍可原样直接保存。

自动整理、嵌入和内部历史都由 Mem0 服务处理。应用按稳定动作身份先查询再写入，重试会核对 Mem0 返回的正式 ID，避免重复记忆。停止不会撤销 Mem0 已完成的保存，但会阻止应用尚未发出的后续动作。

Mem0 由 `mem0/` 下的官方源码 Docker 服务运行，业务后端只使用 REST API。Mem0 PostgreSQL 与业务 PostgreSQL 物理分离，应用不实现 `add`、`delete`、history 或 pgvector 适配层。默认遥测已关闭，配置由一次性容器通过官方 `/configure` 注入。

已有数据库卷从旧镜像切换时先停止应用并备份数据库，再执行 `docker compose up -d --build --wait`；保持现有卷和 PostgreSQL 主版本，不使用 `down -v`。业务库使用官方 PostgreSQL 17 Alpine 基础，不再安装 pgvector；向量扩展仅属于独立 Mem0 数据库。正式库升级仍应核对原会话和记忆。浏览器专项均可用 `TEST_APP_PORT`、`TEST_MODEL_PORT` 隔离端口；测试 PostgreSQL 可使用普通 PostgreSQL 17。

## 相关长期记忆召回（任务 06）

保存成功的记忆可以在新会话回答中使用。普通问题只检索个人身份下相关且仍有效的正式记忆，不会自动读取其他会话消息或附件；未被 Mem0 保存的聊天内容、未完整提交的记忆不会进入跨会话记忆召回。召回材料不会再次自动保存，明确保存操作仍按任务 05 的独立回执处理。

存在正式记忆时，每次普通问题先执行一次嵌入检索，再按需发送回答请求，两次调用分别记录用量。恢复执行会重新核验结果标识及版本，且不会重复已经完成的嵌入。检查点只保存标识和版本，不复制事实正文；已变更或移除的条目不会沿旧结果使用。没有正式记忆时普通聊天不增加嵌入调用。

嵌入未配置、未验证或召回失败时，应用会继续尝试基于当前会话回答。每次最多采用五条有效记忆，相关性和排序由 Mem0 服务内部检索决定，应用不额外设置本地相似度阈值；真实语义质量仍需用你选择的嵌入模型验收。

召回状态及标识检查点保存在 PostgreSQL，无新增本机配置文件或启动步骤。受控接口、重启和停止证据见 [任务 06 验收记录](docs/verification-06.md)；真实云端嵌入兼容性、相关性与账单仍待验。

## 编辑和对话记忆工具

智能体可使用 `add_memory`、`search_memories`、`update_memory`、`delete_memory` 四种真实函数工具，例如“你记得我的住址吗”“把我的居住地改成苏州”“忘掉我的咖啡偏好”。工具调用由模型自主选择；更新或删除时核对已查找条目的身份及版本。工具沿用当前聊天模型，不另设 LLM，不按关键词匹配本地快捷命令。

## 编辑与明确更正长期记忆（任务 07）

在聊天中发送“请把记忆中的住址改成苏州”等自然语言，模型通过记忆工具查找目标并执行更新，不要求固定命令格式，也不由后端正则识别。工具读取实际记忆标识和版本，目标不明确时由模型澄清。

接受明确更正后，旧事实立即停止作为长期记忆召回。新的向量和历史同步完整成功后，聊天状态才显示更正完成；暂停、停止、配置缺失或同步失败都不会提前报告成功。未完成时可沿原回答恢复或重试。

更正保持同一记忆标识，原消息来源继续保留，每次更正另外记录聊天来源。精确命令同步通常只需要一次嵌入请求；自然语言工具及自动整理另有模型调用。重复提交及部分提交后的恢复不会重复修改或多增一个版本。源聊天中的原文字仍保留，相关召回只采用当前完整成功的事实。

更正记录及所有尝试关联均保存在 PostgreSQL，应用启动自动迁移，无新增配置文件。更正、来源、失败恢复和适配验证，以及后续删除需清理的数据合同见 [任务 07 验收记录](docs/verification-07.md)。真实云端嵌入兼容性和账单仍待验。

## 自动记忆与旧候选兼容

聊天中的新事实由 Mem0 原生自动整理，并显示处理状态。应用不创建待确认卡片，也不保留候选记忆接口或兼容数据。附件不会进入自动记忆输入，也不会被当作个人事实。

原生推理、每次嵌入与对话工具均单独记录用量。失败状态保存在 PostgreSQL；已完成步骤与部分写入先核对再恢复。

## 忘记长期记忆（任务 09）

发送“删除记忆：完整事实”“忘记记忆 UUID”或使用对话记忆工具删除。完整事实必须唯一；不明确时会先澄清。删除立即停止业务召回，再调用 Mem0 官方删除接口；失败会保留可重试状态，重启不会恢复被停用的事实。

忘记会清除历次更正正文、派生搜索和最终资料缓存，并使旧操作失效。原聊天及原附件仍保留，原聊天中相同信息仍可主动回看；删除原文属于独立的来源删除功能。最小防恢复标记只保存身份，不保存被删事实。新用户消息重新明确保存属于新授权。

直接删除是本地 PostgreSQL / Mem0 操作，不调用云端，也不要求当前嵌入连接可用；自然语言工具在找到目标前的模型规划和语义查找仍会产生模型调用。界面需要重试时只继续清理同一标识，不删除其他独立条目。详见 [任务 09 验证记录](docs/verification-09.md)。

## 会话附件与知识库

在聊天框“添加资料”上传 UTF-8（含 BOM）的 TXT / Markdown、PDF（含扫描图片页）、DOCX 或 PNG / JPEG。每次最多五个文件，每个最多 20 MB（20,000,000 字节）。所有附件只属于原会话，上传登记成功后保留 30 天，访问不会续期；新会话需要重新上传。

文字附件无论大小均不自动发送正文。每轮只发送文档 ID、文件名和页数／段落数清单，不附带状态或解析缺口。模型自主选择是否调用以下工具及其参数，没有前置检索、任务分类或固定读取顺序：

- `search_documents(query, document_ids?)`：检索当前会话切片，返回完整正文、位置及可选 `image_id`。按自然段→句子→分句→空白→字符递归切分，默认目标 800 Token，为保留完整段落、句子或表格行可使用 200 Token 容差，绝对上限 1000 Token（包含重叠、Markdown 语法和重复表头）；正文重叠最多 160 Token，始终不超过目标的 20%。环境变量 `DOCUMENT_CHUNK_TOKENS`（100–10000）、`DOCUMENT_CHUNK_OVERFLOW_TOKENS`（0–200）、`DOCUMENT_CHUNK_OVERLAP_TOKENS`（0–10000，0 禁用，超过目标 20% 时自动收敛）与 `DOCUMENT_SEARCH_RESULTS`（1–50，默认五片）分别配置预算和片数；检索返回完整切片。检索方案升级为 BM25 + 向量语义混合召回，复用管理端既有嵌入配置；两路默认各取 30 片，经等权 RRF（k=60）去重融合取前 30 片，交给智谱 rerank，最终默认返回最多五片。若返回片数配置大于 30，候选上限同步提高。向量首次检索时分批生成并持久缓存，配置变更后按版本重建；首次检索可能较慢。向量不可用时降级为 BM25，重排不可用时使用融合排名，工具结果标明降级。详见 [混合召回规格](.scratch/attachment-hybrid-retrieval/spec.md)（实现状态以规格为准）。
- `read_document(document_id, start_page?, end_page?, start_paragraph?, end_paragraph?, cursor?)`：PDF／Word 按页范围、TXT／Markdown 按段落范围定位与所选范围有交集的全部检索切片，按原文顺序返回完整正文及可选 `image_id`。省略范围则读取全部切片，不受检索返回片数限制；跨页、重叠和重复表头直接保留，不再裁剪或拆分。结果 `content` 中每项包含 `chunk_id`、`content` 和图片切片的 `image_id`；超限按整片分页，返回 `next_cursor: {"chunk_id": 下一片编号}`，续读保留原范围。预算不足以放入一整片时返回 `context_budget_exhausted`。

TXT／Markdown 自然段按空行识别，段内单换行保留；短段顺序合并，长段按完整句子细分。Word 直接读取原件中的段落、标题和表格行，保留所属章节，表格转为标准 Markdown；长表按完整行分片，各片重复表头，表头计入预算，数据行不重叠；超长单行按单元格续片并保留列位置；不再从分页 PDF 反向提取 Word 正文。重叠优先取末尾完整句子，超出硬上限的整句不再重复；放不下新句时减少重叠，超长句才退到分句或字符。Markdown `#` 标题及“第…章／节／篇／部”边界不跨片或重叠，物理页边界允许跨越；切片自身保存起止页、段落及章节／表格结构。单栏文字型 PDF 按页面坐标恢复标题、自然段和列表，清理跨页重复页眉页脚，并保留全部内容块的物理页及 point 区域。表格先识别有框候选，再以稳定文字对齐和列间隙保守补充无框候选；保留跨行跨列、多级表头、表题与真实行坐标。长表按完整行切分并在每片携带表头及实际召回行，只有前页抵近页底、后页从页顶继续且重复相同表头时才合并为跨页续表。无法可靠判断表头的数据矩阵使用原区域截图兜底。

PDF 会按页面渲染还原完整图区域，使栅格、矢量线条、箭头和图内文字一起保留；Word 提取内嵌栅格图片。图注按页面距离与绘制顺序绑定，并和图一起交给当前视觉模型（当前为 `deepseek-flash`）生成纯文字描述。描述形成绑定 `image_id` 的独立切片，正文切片在图片位置断开，正文、表格与图片统一按原文顺序入库。检索或按页读取命中后，后端在下一轮模型请求中发送对应原图；同一回答中每张图片只发送一次，单批最多五张。扫描 PDF 使用独立 PP-StructureV3 版面 OCR：正文和表格进入原有结构切片，插图裁剪后单独生成视觉描述；完整流程与实施状态见[扫描 PDF OCR 规格](.scratch/pdf-scan-ocr/spec.md)，部署见[OCR 运行时](ocr/README.md)。

当前不解析 Word SmartArt、EMF、WMF 和 Markdown 外部图片引用；文字型 PDF 的结构解析仍面向单栏；扫描页 OCR 的实施范围见上述规格。每份 Word／PDF 最多处理 50 张图片或表格兜底截图。视觉服务失败只标记对应图片并保留可读正文。

每个文档工具每轮分别最多调用五次，正常、失败、重试和续读均计数。切片阅读连同结果包装最多 10,000 Token，且不超过执行点的剩余上下文预算；包装和调用计数字段会预留空间。管理端模型配置中填写实际上下文窗口与回答预留，默认 32,768／4,096 Token；当前本机 `deepseek-flash` 按官方模型列表配置为 1,048,576／4,096 Token。已有模型请求用量可用于核对图片等实际占用；没有用量时文字消息使用本地估算；含图片且缺少实际用量时，阅读工具返回预算不足，不能把短 file_id 当作图片的 Token 开销。切片检索没有额外 Token 预算。

原文计数通过统一 `TokenCounter` 接口选择当前回答 LLM 的官方分词器。应用数据目录的 `tokenizers.json` 按服务地址与模型精确注册官方文件并校验 SHA-256，兼容旧 `MODEL_TOKENIZERS` 显式映射；未配置对应实现时，按 UTF-8 字节数保守估算并标记 `character_estimate`。DeepSeek 官方数据安装命令及其他服务商配置见 [统一 Token 计数](docs/tokenization.md)。本次不新增滑动窗口或摘要机制；后续压缩移除工具正文后，仍可通过每轮清单重新读取持久切片。

原文件保存在 `APP_DATA_DIR/attachments/<UUID>`，Word 分页副本为 `<UUID>.pdf`，文档图片保存在 `<UUID>.images/`。处理状态、TTL、解析范围在 `attachments`；文字、表格及图片描述切片在 `document_chunks`，图片身份、位置、纯文字描述和文件记录在 `document_images`。解析段落仅作生成切片的临时输入。迁移 046 将旧原文的位置和结构搬入已有切片；迁移 048 增加文档图片与 `image_id` 绑定。原件与业务数据库均需备份；旧文字附件（knowledge_version 0／1）启动时从原件重建递归重叠知识库；Word、PDF 的解析版本、切片配置或图片描述模型版本变化时，启动从原件重建对应索引，旧向量随旧切片清理，不延长原有效期。

到期后立即停止下载、清单展示、图片引用和工具访问。启动时及每分钟清理原件、分页副本、派生图片、图片记录、切片和索引；图片同时清理远端文件。失败保留到期身份并自动重试，不恢复访问；已生成聊天正文保留。主动删除附件和会话沿用现有来源清理入口。

## PDF 与 Word 文档

PDF 使用真实物理分页；Word 先检查 DOCX 包，再通过 LibreOffice 自动排版为固定 PDF 副本，页码以该副本为准，两者统一按页定位完整切片读取。后台字体和排版环境与用户电脑不同时，Word 页码可能存在差异。PDF 与 Word 分页副本均最多 200 页。

本机运行需安装 LibreOffice 和中文字体，并确保 `soffice` 位于 PATH，或通过 `LIBREOFFICE_BINARY` 指定可执行文件。Docker 镜像已包含 Writer 和 Noto CJK 字体。Word 转换限时 60 秒、副本最多 80 MB；缺少运行时或转换失败时明确显示失败，不伪造页码。

空白、加密、损坏或超限文件明确失败。双栏 PDF 和特殊排版不保证完全恢复；单栏 PDF 的复杂矢量图保留原图供视觉理解。Word 原件仍保留，正文直接来自原生段落和表格，固定副本只提供页码。具体没有可提取文字的位置由读取工具返回，清单不展开解析说明。

文字提取在受限独立进程执行：每次最长 20 秒、内存监测 512 MiB、最多 2,000,000 字符；临时结构块最多 20,000 个段落或表格行，避免大量短行耗尽索引资源；DOCX 展开最多 2000 个条目、单项 10 MB、合计 50 MB。方案见 [ADR 0011](docs/adr/0011-conversation-document-tools.md)，验证见 [文档工具验证记录](docs/verification-document-tools.md)。

## 会话图片与视觉问答

在“添加资料”选择 PNG、JPG 或 JPEG；图片沿用每次上传五个、每个 20 MB 的限制。后台核验真实格式、完整性与解码，显示可用或失败以及实际尺寸。为控制解码资源，图片最多 4,000 万像素；多帧 PNG 需单独导出要分析的帧。Word 内嵌栅格图片会提取并生成视觉描述；PDF 完整图按页面区域裁剪，包含矢量线条、箭头和图内文字。不再要求先手工另存，Word SmartArt、EMF 和 WMF 暂不支持。

上传成功的独立图片会自动加入原会话后续回答，不需要勾选。文档内嵌图片只在其描述切片被工具召回或读取范围包含该图片时发送。图片只属于原会话，新会话需要重新上传。明确记忆操作不自动读取图片；其他回答会把当前会话所有可用独立图片的 DeepSeek `file_id` 发送给模型。同一服务可继续使用已上传的文件身份；服务地址变化后，独立图片需要重新上传，文档派生图片会从本机副本重新上传。

上传时，后端复用当前 LLM 地址与密钥，向 DeepSeek `POST /files` 发送 multipart 原图，使用 `purpose=user_data` 并显式设置 30 天 TTL（`expires_after[anchor]=created_at`、`expires_after[seconds]=2592000`）。取得 `file_id` 后才发送给模型。实际读图时，后端使用 `{"type":"file","file_id":"…"}` 提供原图，继续使用统一调用、用量、停止与重试。独立图片和文档片段图片都会保存远端文件身份及到期时间，重启或追问不会重复上传；旧版本本机图片首次使用时补上传，文档派生图片在服务变化或远端到期后从本机副本重传。文件有效期最长为 30 天，过期后不自动续期。本机原文件在应用层 30 天有效期内可下载；到期、删除附件或会话同时清理远端图片，失败可重试原删除操作。文档图片切片提供真实 `image_id`、页码或段落位置；独立图片仍不会伪造页码或文字摘录。服务可能拒绝大图片或多图请求，失败不会被显示成已经理解。

运行 `pnpm --dir frontend test:images` 可验证上传和视觉回答；支持测试端口环境变量。已用程序生成测试图验证真实 Files 上传、30 天 TTL 和删除；真实视觉回答质量仍待验，详见 [DeepSeek 文件上传验证](docs/verification-deepseek-files.md)。

## 当前北京时间

模型可在现有工具循环中自主调用 `get_current_time()`，无需参数或额外配置。工具每次执行实时读取系统时钟，固定转换为 `Asia/Shanghai` 北京时间（UTC+8），不受服务器本地时区影响，也不需要联网。返回包含 UTC 偏移的日期时间（精确到秒）、时区和中文星期；时间结果不复用工具步骤缓存。

## 主智能体与子智能体

子智能体完成后可打开只读聊天线程，查看主智能体派工、系统状态、历次执行结果和实际来源。子线程属于当前回答而不是独立用户会话，没有输入框；用户通过主智能体继续任务，并可随时停止整个回答。


主智能体会先做轻量拆分判断：两个以上独立调查、比较、核验或审查分支默认并行创建 2～3 个子智能体；简单问题、强依赖流程和共享状态操作仍由主智能体直接完成。创建工具立即返回 `agent_id` 和 `run_id`，子任务在后台执行，主智能体可以继续使用自己的工具或创建其他任务。主智能体可通过 `instructions` 指定子任务方法和重点，但不能覆盖后端固定规则；子智能体使用独立上下文和公共工具集。子任务结束会自动投递到本次回答的结果信箱，主模型每轮请求前被动接收新结果；暂时无其他工作时调用零参数 `wait_agents()`，由后端挂起等待任意新终态。等待不反复调用模型，也不计工具失败重试；没有活动任务时立即返回。主动与被动交付共用持久化批次去重。

已完成的子智能体可通过 `send_agent_message` 接受补充任务，保留原上下文并创建新执行轮次；执行中的追加返回 `agent_busy`。不再需要的任务可用 `cancel_agent` 取消。最终回答提交前会先处理未读结果并等待活动任务，不需要的任务可提前取消；每轮草稿通过现有 SSE 快照替换。用户停止、资料撤销、超时或服务重启都会关闭后续分派，迟到结果不能覆盖终态。

界面只展示子任务标题、状态和公开交付，不混入子智能体流式正文或推理内容。展开详情会按当前账号、会话和回答重新授权；资料范围变化后详情显示为已撤销，不重新暴露旧正文。

## 模型自主联网与来源核验

管理端“系统配置 → 联网搜索”填写 DeepSeek API 密钥，默认 API 地址为 `https://api.deepseek.com`，也支持以 `/v1` 结尾的地址。搜索与抓取共用这份独立配置，不自动复用聊天密钥；旧智谱配置不会作为 DeepSeek 凭据使用，需要重新填写密钥。保存配置不会联网，未配置时仍可聊天。

模型在同一个工具循环中自主调用两个工具，无需额外确认：

- `search_web(query, ori_question)`：模型分别生成关键词化查询和不超过 128 字符的原始搜索意图。应用调用 `POST /v1/tools/search` 时请求 15 条候选，保留官方相关性、权威度和发布时间，过滤低质量结果、限制单域名数量后最多向模型提供 8 条。摘要使用 `summary`（缺少时使用 `snippet`）。支持官方 `site:`、`lang:`、`after:`、`before:` 等查询语法。
- `fetch_web(url)`：调用 `POST /v1/tools/fetch`，读取用户提供或搜索结果中的网页，URL 最长 8192 字符，要求 HTTP(S)、有主机且不含用户名密码。将接口返回的 Markdown 正文交给模型；网页的可用性和访问策略可能导致抓取失败。

搜索和抓取结果均为不可信工具资料，不执行网页中的指令。查询或抓取地址可能包含当前会话附件及长期记忆中的个人信息，直接发送给 DeepSeek。模型只可使用实际返回的 `[W编号]` 来源；未核验编号会被替换，缺少引用时提供来源核对提示。引用核对不代表网页内容已被独立证实。

模型可在同一次回答中自主使用多个搜索词，结果不足时可换词继续搜索，也可抓取多个网页。每个查询独立缓存成功结果（包括空结果），相同查询及已成功抓取的同一 URL 在本轮复用，不同查询不会串用结果；各次搜索和抓取来源累计保留。搜索与抓取共享回答的停止和来源删除状态；停止后的迟到结果不会继续使用。已取得的搜索来源在后续请求失败时仍可引用。

联网请求采用后端错误分级：400、403、404、413 等非临时错误直接返回，当前智能体执行内相同工具参数再次出现时只返回缓存失败，不再外发，换 URL 或搜索条件仍可使用工具。401、402 表示密钥或余额问题，当前执行的搜索与抓取均禁用。408、429、5xx 及连接／读取超时由后端最多尝试 3 次（初次加 2 次重试），按 0.5、1 秒基础间隔加随机抖动退避，并尊重 `Retry-After`；要求等待超过 10 秒时结束本次请求，不提前重试。最终失败带 `retryable: false`、`retry_managed_by: backend`、实际尝试次数、HTTP 状态及格式校验后的错误代码／请求 ID，不传供应商原始错误正文。临时错误耗尽时另带 `request_retry_exhausted: true`，模型不能开启新一轮相同请求。失败缓存按执行及回答身份隔离，新回答和新的子执行重新判断。

DeepSeek 不返回 token usage。项目用 `credits` 记录官方规则下的计费成功次数：HTTP 200 且搜索结果非空或抓取正文非空记 1；明确的 HTTP 错误及空搜索结果记 0；超时、连接中断或无效响应无法确定时保持未知。不估算金额，实际计费以服务商账单为准。每次真实请求（包括后端自动重试）单独保留调用记录，并重新核验停止状态与执行时限。主智能体和每个子智能体分别最多搜索 5 次、抓取网页 10 次，两类额度独立计算，后端自动重试逐次计入对应额度；耗尽后只禁用对应工具，另一工具仍可在其剩余额度内使用。同一子智能体的补充执行沿用原额度。预算拒绝后终结预留为 cancelled，不遗留 reserved 记录；明确未外发的联网请求记零 credits。

除上述联网错误分级和已有文档次数限制外，其他工具在每次智能体执行中独立累计失败次数，统一上限由 `AgentLimits.tool_retries = 5` 配置：首次调用失败后最多再重试 5 次（最多 6 次失败），由模型决定是否重试。第 5 次重试仍失败时，工具结果返回 `retry_count: 5`、`retry_limit: 5`、`retry_exhausted: true` 及本次回答已禁用的说明；后续模型请求移除该工具定义，后端同时拦截再次调用。历史工具消息保留，其他工具仍可使用。成功调用不消耗失败额度，也不重置已有失败次数；更换参数不能绕过该工具的额度。新一次回答重新计数，同一回答恢复时复用已完成步骤。主智能体最多 24 轮、子智能体最多 12 轮模型决策。

官方协议见 [Search & Fetch 指南](https://api-docs.deepseek.com/guides/search/)、[Search API](https://api-docs.deepseek.com/api/search/) 和 [Fetch API](https://api-docs.deepseek.com/api/fetch/)。核对日期为 2026-10-20，字段及错误规则记录在 [接口研究笔记](docs/research-deepseek-search-fetch.md)。这次替换使用独立 JSON API，由应用执行工具；模型侧仍使用现有 Chat Completions 流式工具循环。

验证命令：`uv run pytest tests/search/test_search.py -q`、`pnpm --dir frontend test:search`。浏览器验证使用隔离端口 18102 / 18103 / 18104 和受控接口，不读取真实搜索密钥。历史智谱验收记录仅供历史追溯，不代表当前 DeepSeek 接入已通过真实服务验收。


## 附件与长期记忆边界

附件只用于当前会话的阅读、问答、比较和图片理解。附件正文不会进入 Mem0；输入“请从附件提取长期记忆”不会启动独立提取流程。需要保存的事实应由用户在聊天消息中直接说出，再由聊天记忆流程处理。项目不保留附件记忆表或旧数据兼容逻辑。

## 删除会话或附件（任务 15）

点击“删除当前会话”时，先查看全部关联长期记忆。列表默认勾选一起删除；取消勾选可明确保留已完整保存、实际可读取的事实。保留项在长期记忆页标记“来源已删除”，仍可召回、编辑和忘记。删除附件没有记忆选择步骤，因为附件不会生成长期记忆。

删除会话会移除其消息和附件；单独删除附件会清原文件、完整解析文字和搜索来源关联。单附件删除保留已经完成的聊天正文，其他会话独立上传的同名或同内容文件不受影响。正在处理的来源先停用，晚到解析或模型结果不能恢复正文；旧请求不能通过重试改用别的文件，需要重新发送。

若部分本机清理失败，会明确显示未完成，并保留“重试来源清理”入口；刷新或重启后仍沿原删除决定继续。删除本身不调用模型，已经发生的调用记录保留。迁移由应用启动执行，删除状态保存在 PostgreSQL，原附件仍位于 `APP_DATA_DIR/attachments/<UUID>`，无需新增服务或密钥。

专项浏览器命令 `pnpm --dir frontend test:source-deletion` 默认使用 18116/18117，支持 `TEST_APP_PORT` / `TEST_MODEL_PORT`；完整 `test:e2e` 已包含。来源冻结与保留规则见 [任务 15 验收记录](docs/verification-15.md)。


## 更换 Mem0 模型配置

在设置中保存聊天模型和嵌入模型后，重启 `mem0` Compose。一次性 `mem0-config` 容器会读取 `.local/model.json` 与 `.local/embedding.json` 并调用官方 `/configure`。业务应用不扫描、复制或重建 Mem0 向量；需要迁移已有记忆空间时，应使用 Mem0 官方提供的运维能力，并在操作前备份独立 Mem0 数据卷。

## 系统提示词

所有发送给模型的稳定系统提示词、工具描述、资料信任边界和网页来源规则集中在 `backend/general_agent/prompts/`。附件、长期记忆和网页搜索模块只传入结构化动态资料，不再各自维护提示正文。

切片计数器默认跟随当前回答 LLM，当前使用 DeepSeek 官方 tokenizer.json；嵌入模型不决定切片计数。每个新任务固定计数快照并保存模型、方法及指纹，切换 LLM 后不单独重切已有资料，文档读取按当前 LLM 重新核算预算。切片结构预算、解析和视觉规则变化仍可启动升级；人工清空标记阻止从原件自动恢复。未配置对应分词器时明确标记 `character_estimate`。`context_prefix`／`context_suffix` 保存重复表头等结构包装；详细配置见 [统一 Token 计数](docs/tokenization.md)。

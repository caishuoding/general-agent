## 启动

需要 Docker Desktop（已启动）、Python 3.12+、uv、Node.js 22.12+ 和 pnpm 11.25.0。项目锁定 Python、前端依赖及 PostgreSQL 基础镜像摘要。首次启动需要访问 Docker 和 GitHub。

在项目根目录执行：

```sh
bash scripts/start.sh
```

脚本安装锁定的依赖、构建前端，启动业务 PostgreSQL、独立 Mem0 PostgreSQL 和官方 Mem0 API，随后在前台启动应用。若电脑安装了 Codex 自带运行时，脚本也会尝试使用它；可通过 `GENERAL_AGENT_PYTHON` 指定其他 Python。浏览器打开 [本机应用](http://127.0.0.1:8000)，Mem0 API 仅监听 `127.0.0.1:8888`。

在设置中输入服务商提供的 API 基础地址（通常以 `/v1` 结尾）、文字模型名称和 API 密钥，然后新建会话并发送消息。接口使用 OpenAI 兼容的 Chat Completions；保存配置只表示连接信息已写入本机，实际可用性由后续调用结果反馈。云端地址使用 HTTPS，本机服务允许回环 HTTP。更换服务地址需重新填写密钥；同一地址留空密钥会保留原密钥。

回答会逐段显示，页面和 PostgreSQL 都保留生成中、完成、已停止或失败状态。点击“停止生成”会冻结当前回答，不再追加后续文字；已经发出的模型请求会继续接收可返回的用量，因此停止不保证撤销服务商费用。浏览器断开或切换会话不会自动停止后端生成，重新进入后会恢复进度。

最新失败或停止的回答可点击“重试回答”；重试保留旧尝试及部分内容，创建新的调用记录，不重复插入用户消息。模型断流、输出长度限制和不支持流式接口都会明确显示为未完成。服务必须支持 Chat Completions 的 SSE 流式响应、结束标记与 stream_options.include_usage；本版本不会自动重发请求或回退成另一次调用。

设置页展示最近 100 次调用的状态以及服务返回的 token 或 credits。服务未返回用量时保留空值；重试产生新的实际调用记录。应用不维护价格、不估算费用，真实计费以服务商账单为准。

按 Ctrl+C 停止应用。停止数据库可执行 `docker compose stop`；再次启动后数据仍保留。数据库默认仅监听 `127.0.0.1:15432`，应用仅监听 `127.0.0.1:8000`。

## 登录与账号

系统不开放注册。首次启动预置管理员 `admin / 123456`，第一次登录会强制设置至少 10 个字符的新密码。普通用户从 `/` 登录聊天，管理员从 `/admin` 登录独立管理端；管理员账号只用于管理，不进入用户聊天界面。

管理端可以创建普通用户或其他管理员、停用或启用账号、重置临时密码，并只读查看所有账号的会话、消息、附件、记忆、搜索记录和调用用量，下载附件；不能代替用户发消息、修改记忆或删除内容，查看他人内容会写入审计记录。模型、嵌入和搜索配置只在管理端的“系统配置”中修改。

登录会话保存在业务 PostgreSQL，浏览器 Cookie 为 `HttpOnly`、`SameSite=Lax`，有效期 7 天；HTTPS 访问时自动加 `Secure`。退出、改密、重置密码或停用账号会吊销旧会话。本期不提供登录失败次数限制或账号锁定，这是已接受的个人项目风险。

## 独立嵌入配置（任务 03）

设置页提供独立嵌入连接。保存配置只更新本机文件，不会发出云端请求，也不会预先探测文字、图片或工具调用能力；这些能力由真实对话、图片请求和工具回合直接反馈。

嵌入连接单独保存 API 地址、模型名称、密钥和预期维度。可以显式选择复用已保存聊天服务的地址与密钥，嵌入模型和维度仍需独立填写；复制后两套连接各自管理。嵌入服务由 Mem0 在后续记忆调用中使用；地址、密钥、模型或维度不匹配时，错误会在实际调用中反馈。若服务使用别名，请填写实际可用的模型标识，不能仅凭文字调用成功认定嵌入可用。

嵌入配置保存在 `.local/embedding.json`，与 `.local/model.json` 一样由本机后端以仅当前用户可读写的权限原子保存。配置版本随连接实际变更更新。重启 Mem0 Compose 后，一次性 `mem0-config` 容器会把聊天模型与嵌入配置提交给官方 `/configure`。完整密钥不出现在读取响应或应用日志中。

业务应用不拥有 Mem0 的向量空间。更换嵌入服务、模型或维度后，应重启 Mem0 服务，由 Mem0 自己管理其索引；本项目不提供本地重建、代次表或向量迁移接口。实际可用性和相关性质量需要通过真实记忆调用验收。

`pnpm --dir frontend test:e2e` 运行当前保留的会话、资料、图片、搜索和来源删除浏览器流程。实现边界、接口与历史测试证据见 [任务 03 验收记录](docs/verification-03.md)。

## 自动记忆、查看和对话工具

本次策略变更、受控测试与真实服务待验范围见[原生记忆验证记录](docs/verification-native-memory.md)。

先在设置中填写独立嵌入服务、模型与维度。聊天服务支持文字对话不表示它提供嵌入；缺少嵌入时普通聊天可用，自动记忆会明确提示缺少配置，补齐后可独立重试。

普通用户事实由 Mem0 原生 `infer=True` 流程提取和维护，不再逐条确认。纯提问、资料操作和不保存指令不会触发自动提取，不回填旧聊天。前端不展示长期记忆管理页；真实记忆正文、向量和历史应从独立 Mem0 存储核对，业务 PostgreSQL 只保留来源、动作和恢复状态。明确的“请记住：具体事实”仍可原样直接保存。

自动整理、嵌入和内部历史都由 Mem0 服务处理。应用按稳定动作身份先查询再写入，重试会核对 Mem0 返回的正式 ID，避免重复记忆。停止不会撤销 Mem0 已完成的保存，但会阻止应用尚未发出的后续动作。

Mem0 由 `mem0/` 下的官方源码 Docker 服务运行，业务后端只使用 REST API。Mem0 PostgreSQL 与业务 PostgreSQL 物理分离，应用不实现 `add`、`delete`、history 或 pgvector 适配层。默认遥测已关闭，配置由一次性容器通过官方 `/configure` 注入。

已有数据库卷从旧镜像切换时先停止应用并备份数据库，再执行 `docker compose up -d --build --wait`；保持现有卷和 PostgreSQL 主版本，不使用 `down -v`。业务库使用官方 PostgreSQL 17 Alpine 基础，不再安装 pgvector；向量扩展仅属于独立 Mem0 数据库。正式库升级仍应核对原会话和记忆。浏览器专项均可用 `TEST_APP_PORT`、`TEST_MODEL_PORT` 隔离端口；测试 PostgreSQL 可使用普通 PostgreSQL 17。

## 相关长期记忆召回（任务 06）

保存成功的记忆可以在新会话回答中使用。普通问题只检索个人身份下相关且仍有效的正式记忆，不会自动读取其他会话消息或附件；未被 Mem0 保存的聊天内容、未完整提交的记忆不会进入跨会话记忆召回。召回材料不会再次自动保存，明确保存操作仍按任务 05 的独立回执处理。

存在正式记忆时，每次普通问题先执行一次嵌入检索，再按需发送回答请求，两次调用分别记录用量。恢复执行会重新核验结果标识及版本，且不会重复已经完成的嵌入。检查点只保存标识和版本，不复制事实正文；已变更或移除的条目不会沿旧结果使用。没有正式记忆时普通聊天不增加嵌入调用。

嵌入未配置、未验证或召回失败时，应用会继续尝试基于当前会话回答。每次最多采用五条有效记忆，相关性和排序由 Mem0 服务内部检索决定，应用不额外设置本地相似度阈值；真实语义质量仍需用你选择的嵌入模型验收。

召回状态及标识检查点保存在 PostgreSQL，无新增本机配置文件或启动步骤。受控接口、重启和停止证据见 [任务 06 验收记录](docs/verification-06.md)；真实云端嵌入兼容性、相关性与账单仍待验。

## 编辑和对话记忆工具

智能体可使用 `search_memories`、`update_memory`、`delete_memory` 三种真实函数工具，例如“你记得我的住址吗”“把我的居住地改成苏州”“忘掉我的咖啡偏好”。先查找有效条目，再按当前用户意图及版本操作；目标不明确时澄清。当前每次对话请求更新或删除一条具体记忆。旧格式的精确更正、删除命令仍保留本地快捷路径。工具沿用当前聊天模型，不另设 LLM。

## 编辑与明确更正长期记忆（任务 07）

在聊天中发送`更正记忆：我住在杭州 => 我住在苏州`，或 `请把记忆中的“我住在杭州”改为“我住在苏州”`。完整旧事实必须唯一；也可从 PostgreSQL 查询记忆标识后使用“更正记忆 标识：新事实”。无法确定具体条目或内容时会先澄清，不会猜测另一个目标，附件和转述不会授权这条快捷命令；普通用户事实另由 Mem0 自动判断变更。

接受明确更正后，旧事实立即停止作为长期记忆召回。新的向量和历史同步完整成功后，聊天状态才显示更正完成；暂停、停止、配置缺失或同步失败都不会提前报告成功。未完成时可沿原回答恢复或重试。

更正保持同一记忆标识，原消息来源继续保留，每次更正另外记录聊天来源。精确命令同步通常只需要一次嵌入请求；自然语言工具及自动整理另有模型调用。重复提交及部分提交后的恢复不会重复修改或多增一个版本。源聊天中的原文字仍保留，相关召回只采用当前完整成功的事实。

更正记录及所有尝试关联均保存在 PostgreSQL，应用启动自动迁移，无新增配置文件。更正、来源、失败恢复和适配验证，以及后续删除需清理的数据合同见 [任务 07 验收记录](docs/verification-07.md)。真实云端嵌入兼容性和账单仍待验。

## 自动记忆与旧候选兼容

聊天中的新事实由 Mem0 原生自动整理，并显示处理状态。应用不创建待确认卡片，也不保留候选记忆接口或兼容数据。附件不会进入自动记忆输入，也不会被当作个人事实。

原生推理、每次嵌入与对话工具均单独记录用量。失败状态保存在 PostgreSQL；已完成步骤与部分写入先核对再恢复。

## 忘记长期记忆（任务 09）

发送“删除记忆：完整事实”“忘记记忆 UUID”或使用对话记忆工具删除。完整事实必须唯一；不明确时会先澄清。删除立即停止业务召回，再调用 Mem0 官方删除接口；失败会保留可重试状态，重启不会恢复被停用的事实。

忘记会清除历次更正正文、派生搜索和最终资料缓存，并使旧操作失效。原聊天及原附件仍保留，原聊天中相同信息仍可主动回看；删除原文属于独立的来源删除功能。最小防恢复标记只保存身份，不保存被删事实。新用户消息重新明确保存属于新授权。

直接删除是本地 PostgreSQL / Mem0 操作，不调用云端，也不要求当前嵌入连接可用；自然语言工具在找到目标前的模型规划和语义查找仍会产生模型调用。界面需要重试时只继续清理同一标识，不删除其他独立条目。详见 [任务 09 验证记录](docs/verification-09.md)。

## 会话附件（最小全文上下文）

新建或进入会话后，在聊天框“添加资料”上传 UTF-8（含 BOM）的 TXT / Markdown。每次上传最多五个文件，每个最多 20 MB（20,000,000 字节）。上传成功后，当前会话所有可读附件自动用于后续回答，不需要逐条勾选或绑定消息。

上传后显示处理中、可用或失败；发送消息后，附件名称和状态也会显示在该条用户消息中，刷新或重新进入会话仍可回看和下载。失败文件不会进入模型材料，但可以继续编辑其他附件或删除它。原会话刷新、重启或重新进入后仍能使用已解析附件，新会话需要重新上传。同一原文件每次上传均独立保存，不存在跨会话文件库。上传及文字解析在本机完成；完整文字会发送给你配置的云端模型，回答请求使用统一调用和用量记录。

当前版本把完整可提取文字直接放进模型上下文，不再生成文件引用、摘录或引用核验提示。PDF、DOCX、PNG / JPEG 已支持，Excel、音视频和扫描 OCR 不在本期范围。附件较多或文档很长时，完整上下文可能超过模型窗口或产生较高用量；当前不自动分页、摘要或裁剪。

原文件保存于 `APP_DATA_DIR/attachments/`，原文件名只用于显示，不用于构造磁盘路径。处理状态、解析范围和完整可读文字保存在 PostgreSQL 的 `attachments` 表，独立于长期记忆。原文件与数据库都需要保留；手工删文件夹不会同步清理数据库。进程重启中断解析时显示失败并提示重新上传，不会把部分解析标作成功。

附件方案与删除清理合同见 [ADR 0009](docs/adr/0009-conversation-attachment-full-context.md)。当前测试没有把个人文件发往真实外部服务。

## PDF 与 Word 文字资料

同一上传入口支持文本型 PDF 和 DOCX，继续限制每次五个文件、每个 20 MB。PDF 最多 200 页，完整文字中保留实际物理页标记；Word 支持正文段落与表格，以段落、表格行列标记。上传卡片展示提取页数或段落数、缺口和限制，部分可读不会显示为完整阅读。

扫描 PDF 不做 OCR；空白、加密、损坏或超限文件会明确失败。复杂图表、内嵌图片和特殊排版需要将相关图像单独上传。Word 修订、文本框、页眉页脚等内容不在当前文字提取范围，存在时会说明缺口；请处理修订或将需要的内容放入正文再上传。这里的文字可用不代表已理解全部图像。

解析在本机受资源限制的独立进程执行：最长 20 秒、内存监测 512 MiB、最多提取 2,000,000 字符；DOCX 展开最多 2000 个条目、单项 10 MB、合计 50 MB。达到限制需拆分或简化文档。范围说明持久保存在 PostgreSQL 的附件元信息，原文件位置和现有启动方式不变。接口、格式样本、浏览器及真实服务待验记录见 [任务 11 验收记录](docs/verification-11.md)。

## 会话图片与视觉问答

在“添加资料”选择 PNG、JPG 或 JPEG；图片沿用每次上传五个、每个 20 MB 的限制。后台核验真实格式、完整性与解码，显示可用或失败以及实际尺寸。为控制解码资源，图片最多 4,000 万像素；多帧 PNG 需单独导出要分析的帧。文档图表或截图可另存为图片上传，本功能不自动理解 PDF / DOCX 内嵌图片，也不提供扫描 OCR。

上传成功的图片会自动加入原会话后续回答，不需要勾选。图片只属于原会话，新会话需要重新上传。明确记忆操作不读取附件；其他回答会把当前会话所有可用图片原字节发送给模型。改变模型、服务或密钥后直接使用新连接，是否支持视觉输入由实际图片调用结果反馈。

实际读图时，后端把图片原字节发送给配置的模型，继续使用统一调用、用量、停止与重试。当前不生成图片文件引用，也不会标造页码或假文字摘录。服务可能拒绝大图片或多图请求，失败不会被显示成已经理解；已取得的用量仍记录。真实识图和图表理解质量仍需实际服务验收。

运行 `pnpm --dir frontend test:images` 可验证上传和视觉回答；支持测试端口环境变量。真实视觉服务验收待验，本轮没有把个人图片发往真实云端服务。

### 完整上下文与长文档

当前版本没有独立的全文总结、分段调用或最终汇总流程。用户要求总结或比较时，模型直接基于完整可提取文字回答；解析缺口会显示在附件卡片中，但当前不会自动分页。超过模型上下文的内容会让模型请求失败，应用不会把它伪装成完整阅读，也不会静默截断。后续若要恢复长文档能力，需要另行设计工具读取或分页，不会重新引入旧的总结任务表。


## 模型自主联网与来源核验

设置页“联网搜索”可填写独立智谱密钥，默认 API 地址为 `https://open.bigmodel.cn/api/paas/v4`；也可改为自己的兼容端点。搜索配置独立保存、掩码读取和移除，不复用聊天密钥。保存不会发出搜索请求，未配置仍可使用普通聊天、附件与记忆；模型调用搜索工具时会得到配置提示。旧 Tavily 配置不会被自动复用为智谱配置。

模型根据当前请求自主决定是否调用搜索工具，可以在回答普通问题时按需联网。搜索采用智谱 `search_std` 基础引擎，每次最多五条结果，查询最多 70 字符；回答显示本次实际结果中的可打开链接，无法核验的标记会提示未核验。未执行、超时和失败都显示真实状态。工具返回的网页标题、摘要和链接只作为不可信资料，不执行其中的命令。

查询直接执行，不展示编辑或批准卡片。即使模型生成的查询包含当前会话附件或长期记忆中的个人信息，也不会增加额外确认步骤。搜索结果仍会保存操作记录、实际请求用量和可核验来源；来源删除或操作停止后，迟到的结果不会继续使用。

搜索与最终回答分别记录调用。搜索请求成功发出并收到 HTTP 响应后记录一次 credit；连接中断或超时时 credit 可能为空。搜索结束不代表回答也已完成，已发请求在停止后仍可能由服务商计费。

搜索设置不需要新增启动步骤。`pnpm --dir frontend test:search` 默认使用隔离端口 18102 / 18103 / 18104；可用 `TEST_APP_PORT`、`TEST_MODEL_PORT`、`TEST_SEARCH_PORT` 覆盖。搜索结果、失败、停止和来源核验见 [智谱搜索验证](docs/verification-zhipu-search.md)；当前工具化决策见 [ADR 0008](docs/adr/0008-tool-driven-web-search-and-prompt-composition.md)。


## 附件与长期记忆边界

附件只用于当前会话的阅读、问答、比较和图片理解。附件正文不会进入 Mem0；输入“请从附件提取长期记忆”不会启动独立提取流程。需要保存的事实应由用户在聊天消息中直接说出，再由聊天记忆流程处理。项目不保留附件记忆表或旧数据兼容逻辑。

## 删除会话或附件（任务 15）

点击“删除当前会话”时，先查看全部关联长期记忆。列表默认勾选一起删除；取消勾选可明确保留已完整保存、实际可读取的事实。保留项在长期记忆页标记“来源已删除”，仍可召回、编辑和忘记。删除附件没有记忆选择步骤，因为附件不会生成长期记忆。

删除会话会移除其消息和附件；单独删除附件会清原文件、完整解析文字和搜索来源关联。单附件删除保留已经完成的聊天正文，其他会话独立上传的同名或同内容文件不受影响。正在处理的来源先停用，晚到解析或模型结果不能恢复正文；旧请求不能通过重试改用别的文件，需要重新发送。

若部分本机清理失败，会明确显示未完成，并保留“重试来源清理”入口；刷新或重启后仍沿原删除决定继续。删除本身不调用模型，已经发生的调用记录保留。迁移由应用启动执行，删除状态保存在 PostgreSQL，原附件仍位于 `APP_DATA_DIR/attachments/<UUID>`，无需新增服务或密钥。

专项浏览器命令 `pnpm --dir frontend test:source-deletion` 默认使用 18116/18117，支持 `TEST_APP_PORT` / `TEST_MODEL_PORT`；完整 `test:e2e` 已包含。来源冻结与保留规则见 [任务 15 验收记录](docs/verification-15.md)。


## 更换 Mem0 模型配置

在设置中保存聊天模型和嵌入模型后，重启 `mem0` Compose。一次性 `mem0-config` 容器会读取 `.local/model.json` 与 `.local/embedding.json` 并调用官方 `/configure`。业务应用不扫描、复制或重建 Mem0 向量；需要迁移已有记忆空间时，应使用 Mem0 官方提供的运维能力，并在操作前备份独立 Mem0 数据卷。

## 系统提示词

所有发送给模型的稳定系统提示词、工具描述、资料信任边界和网页来源规则集中在 `backend/general_agent/prompts/`。附件、长期记忆和网页搜索模块只传入结构化动态资料，不再各自维护提示正文。

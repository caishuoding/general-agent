# 个人对话智能体

当前已实现任务 01–18：本机 Web 对话、独立聊天与嵌入配置、能力验证、会话持久化、流式回答、停止与失败重试、逐次用量与月度预算、通过 Mem0 明确保存、查看、更正和召回相关长期记忆，以及会话 TXT / Markdown / PDF / DOCX 资料、PNG / JPEG 视觉问答、可恢复的全文总结、多文件比较、明确要求时查找旧聊天和明确授权的 Tavily 联网搜索。支持忘记指定长期记忆、预览并删除会话或附件，以及更换嵌入模型后重建索引。

## 启动

需要 Docker Desktop（已启动）、Python 3.12+、uv、Node.js 22.12+ 和 pnpm 11.25.0。项目锁定 Python、前端依赖及 PostgreSQL 基础镜像摘要，并从固定版本、校验和的源码构建 pgvector 0.8.7。首次构建需要访问 Docker、Alpine 软件源与 GitHub。

在项目根目录执行：

```sh
bash scripts/start.sh
```

脚本安装锁定的依赖、构建前端、启动 PostgreSQL，随后在前台启动应用。若电脑安装了 Codex 自带运行时，脚本也会尝试使用它；可通过 `GENERAL_AGENT_PYTHON` 指定其他 Python。浏览器打开 [本机应用](http://127.0.0.1:8000)。

在设置中输入服务商提供的 API 基础地址（通常以 `/v1` 结尾）、文字模型名称和 API 密钥，然后新建会话并发送消息。接口使用 OpenAI 兼容的 Chat Completions；保存配置仅表示已保存，不代表服务能力已验证。云端地址使用 HTTPS，本机服务允许回环 HTTP。更换服务地址需重新填写密钥；同一地址留空密钥会保留原密钥。

回答会逐段显示，页面和 PostgreSQL 都保留生成中、完成、已停止或失败状态。点击“停止生成”会冻结当前回答，不再追加后续文字；已经发出的模型请求会继续接收可返回的用量，因此停止不保证撤销服务商费用。浏览器断开或切换会话不会自动停止后端生成，重新进入后会恢复进度。

最新失败或停止的回答可点击“重试回答”；重试保留旧尝试及部分内容，创建新的调用记录，不重复插入用户消息。模型断流、输出长度限制和不支持流式接口都会明确显示为未完成。服务必须支持 Chat Completions 的 SSE 流式响应、结束标记与 stream_options.include_usage；本版本不会自动重发请求或回退成另一次调用。

设置页展示最近100次调用的状态、服务返回 token 与费用估算，并按全部记录汇总上海时区当前自然月。用量或费用缺失显示为未知；可设置月度预算及按服务、模型绑定的单价。重试按新的实际调用计费。真实调用按你的服务商规则计费。

按 Ctrl+C 停止应用。停止数据库可执行 `docker compose stop`；再次启动后数据仍保留。数据库默认仅监听 `127.0.0.1:15432`，应用仅监听 `127.0.0.1:8000`。

## 数据与配置

| 内容 | 位置 |
| --- | --- |
| 会话、消息、调用记录、预算、单价、操作批准、Mem0 向量与历史、记忆来源及操作状态、结构版本 | PostgreSQL 的 `general-agent_postgres_data` 持久化卷 |
| 搜索地址与独立 Tavily 密钥 | `.local/search.json`，或 `APP_DATA_DIR/search.json`，仅当前用户可读写 |
| 搜索具体查询、来源版本、单次批准、实际结果和回答引用 | PostgreSQL 的 `search_requests` 与消息记录 |
| 历史聊天查询与出处标识、消息内容指纹（不另存摘录正文） | PostgreSQL 的 `history_queries` / `history_hits`；原文仍为 `messages.content` |
| 模型地址、名称、密钥 | 项目内 `.local/model.json`，新建文件权限为仅当前用户可读写 |
| 嵌入配置、未完成重建的目标凭据 | `.local/embedding.json` 与 `.local/embedding-rebuilds/<任务 UUID>.json`；可由 `APP_DATA_DIR` 改变根目录，目标文件在完成或取消后移除 |
| 附件归属、处理状态、文字提取范围与缺口、文字片段与消息引用 | PostgreSQL 同一业务库中的独立附件表 |
| 附件原文件 | `.local/attachments/<附件 UUID>`，或 `APP_DATA_DIR/attachments/` |
| 前端构建 | `frontend/dist/`，可重新生成 |
| 规格与任务 | `.scratch/general-agent/` |

`.local/`、环境文件、依赖和构建产物均已排除 Git。Mem0 正式事实、向量及内部历史均在 PostgreSQL；首次保存会创建 personal_memories 集合；重建后由 PostgreSQL 登记的活动代次指向新的 memory_space_<UUID> 集合。`.local/mem0-runtime/` 仅是禁用遥测后 SDK 要求存在的辅助目录，不存放记忆数据库。附件原文件与 PostgreSQL 中的派生文本分别保存。密钥仅由后端读取，配置接口不回传完整密钥；模型错误正文不会直接展示。

可用环境变量：`DATABASE_URL` 指定 PostgreSQL；`APP_DATA_DIR` 指定本机配置目录；`POSTGRES_PORT` 修改 Compose 的宿主端口。修改数据库端口时，同步设置 `DATABASE_URL`。Compose 内的密码仅用于这个本机开发实例。

数据库结构在应用启动时按版本迁移，已应用的迁移不会重复执行。应用使用单个后端进程运行；启动时会将上次进程中断的生成记录标为失败并保留已提交的内容与用量，请勿用多个 worker 共用同一业务库。请保留数据库卷；`docker compose down -v` 会删除其数据。

## 模型能力与独立嵌入配置（任务 03）

设置页分别提供文字、图片、工具调用与嵌入检查。每个按钮都会对已保存配置发出真实请求，可能产生费用；记录可获取的用量，服务缺失用量时显示未知。保存配置本身不验证能力。各项结果独立显示，修改连接地址、模型或密钥后旧结果失效；仅保存相同值会保留结果。检查使用固定测试内容，不发送会话或附件正文。

嵌入连接单独保存 API 地址、模型名称、密钥和预期维度。可以显式选择复用已保存聊天服务的地址与密钥，嵌入模型和维度仍需独立填写；复制后两套连接各自管理。嵌入检查请求 `/embeddings`，要求服务返回的模型标识与填写值一致、维度一致、向量为有限数值。若服务使用别名，请填写响应实际返回的模型标识，不能仅凭文字调用成功认定嵌入可用。

嵌入配置保存在 `.local/embedding.json`，与 `.local/model.json` 一样由本机后端以仅当前用户可读写的权限原子保存。配置版本随连接实际变更更新。能力结果和索引身份登记保存在 PostgreSQL。完整密钥不出现在读取响应、能力错误或应用日志中。

检索消费者登记所用嵌入空间。已有索引时，更换服务地址、模型或维度先展示影响，需要明确确认重建；完整验证目标后才切换，不能直接保存而混用空间。轮换相同空间的密钥仍可保存，但必须重新验证。检查通过仅表示本次基础协议验证通过，不保证服务支持全部图片任务，也不代表任意资料处理或相关性质量已验收。

`pnpm --dir frontend test:e2e` 依次运行会话、资料、记忆、确认、搜索、来源删除、设置和重建的全部浏览器流程。能力设置专项使用隔离端口 18084/18085，也可单独运行 `pnpm --dir frontend test:capabilities`。任务 03 的四项真实服务验收目前均待验；本任务没有读取或复制真实凭据，也没有发起付费请求。实现边界、接口与测试证据见 [任务 03 验收记录](docs/verification-03.md)。


## 用量与月度预算（任务 04）

预算和价格均以人民币元表示，模型输入/输出价格单位为元 / 百万 token；其他币种需自行换算。预算留空时不限制使用，填 0 时每次请求前暂停。达到额度、缺少单价、本月已有费用未知或仍有请求等待用量时，暂停新的云端调用。估算不等于服务商实际账单，也不是服务商扣费上限；单次已允许的请求仍可能超过额度。

暂停提示说明原因，可打开设置补价/调整预算后重新检查，也可取消或明确“仅允许下一次云端调用”。此批准绑定原操作和配置，不会永久放行或转移到别的会话。后续多轮执行每次调用仍需检查。补齐价格会为之前完整用量补算费用，已知费用保留调用时单价；缺失 usage 和缺少服务身份的旧记录无法安全补算。停止仍保留后续返回的用量，重试按新实际请求计量。

预算、单价、暂停挑战和幂等操作结果保存在 PostgreSQL。同步与流式聊天、能力检查、Mem0 保存与召回、候选提取、资料总结、搜索及索引重建全部通过同一调用网关。显式跨线程上下文、批准、取消、缓存失效与多步骤续跑约束见 [任务04验收与公共接口合同](docs/verification-04.md)。当前仍按单个后端进程运行。

`pnpm --dir frontend test:budget` 使用独立端口18086/18087、临时配置与随机测试数据库；完整 `test:e2e` 也包含该流程。真实云端价格、usage 与账单对应尚待验，本任务没有读取真实凭据或发起付费请求。


## 明确保存与查看长期记忆（任务 05）

先在设置中填写独立嵌入服务、模型与维度，并运行“检查嵌入”。聊天服务支持文字对话不表示它提供嵌入；缺少嵌入时普通聊天可用，保存会明确失败，配置补齐后可重试原回答。

在聊天中输入“请记住：我喜欢简洁的中文回答”，成功后会显示“已保存长期记忆”。“长期记忆”页面展示事实、真实状态及“查看原消息”。具体事实直接保存，无需再确认；普通陈述、否定、他人的转述、虚构写作及对象不明的“记住这个”不会自动保存。可用分号分开保存与其他请求，例如“请记住：我喜欢茶；再给我一个泡茶建议”。本阶段采用明确句式，不用模型推测未明确授权的保存对象。

记忆保存需要一次可计量的嵌入请求。保存成功后若后续回答受预算限制，聊天会保留“已保存”并显示暂停卡片；刷新后仍可批准下一次调用、补价后重新检查或取消回答。重试保留原用户消息与动作身份；内部历史写入失败时会先核对实际向量，避免重复记忆。停止不会撤销已完成的保存，但会阻止尚未发出的后续调用。

使用 Mem0 OSS **1.0.11**，以应用自定义的 PostgreSQL 历史、初始化、关闭、重置兼容层满足本机持久化要求。这不是 SDK 官方现成的历史插件。明确保存使用 `infer=False`，不把全部聊天或附件送入自动提取；默认遥测已关闭。版本选择与升级约束、预算续跑接缝、受控测试证据见 [任务 05 验收记录](docs/verification-05.md)。真实嵌入服务兼容性仍待验。

已有数据库卷从旧镜像切换时先停止应用并备份数据库，再执行 `docker compose up -d --build --wait`；保持现有卷和 PostgreSQL 主版本，不使用 `down -v`。此构建保持相同 PostgreSQL 17 Alpine 基础，安装 pgvector 扩展；正式库升级仍应核对原会话和记忆。`pnpm --dir frontend test:memory` 默认使用 18088/18089，所有浏览器专项均可用 `TEST_APP_PORT`、`TEST_MODEL_PORT` 隔离端口；测试 PostgreSQL 也必须提供 pgvector。

## 相关长期记忆召回（任务 06）

保存成功的记忆可以在新会话回答中使用。普通问题只检索个人身份下相关且仍有效的正式记忆，不会自动读取其他会话消息或附件；未明确保存的聊天内容、未完整提交的记忆不会进入回答。召回材料不会再次自动保存，明确保存操作仍按任务 05 的独立回执处理。

存在正式记忆时，每次普通问题先执行一次嵌入检索，再按需发送回答请求，两次调用分别检查预算和记录用量。若检索完成后回答暂停，恢复会重新核验结果标识及版本，继续回答时不重复嵌入。检查点只保存标识和版本，不复制事实正文；已变更或移除的条目不会沿旧结果使用。没有正式记忆时普通聊天不增加嵌入调用。

回答旁会显示实际召回状态及参考数量。嵌入未配置、未验证或召回失败时会明确提示未读取记忆，并继续尝试基于当前会话回答；回答调用仍受预算限制。当前使用相似度阈值 0.72、最多五条有效记忆，该工程默认值的真实语义质量仍需用你选择的嵌入模型验收。

召回状态及标识检查点保存在 PostgreSQL，无新增本机配置文件或启动步骤。`pnpm --dir frontend test:recall` 默认使用 18092/18093，也支持 `TEST_APP_PORT`、`TEST_MODEL_PORT` 覆盖。受控接口、重启、预算、停止和浏览器证据见 [任务 06 验收记录](docs/verification-06.md)；真实云端嵌入兼容性、相关性与账单仍待验。

## 编辑与明确更正长期记忆（任务 07）

在“长期记忆”页面选择“编辑记忆”，填写新事实并保存即可直接更正。也可在聊天中发送`更正记忆：我住在杭州 => 我住在苏州`，或 `请把记忆中的“我住在杭州”改为“我住在苏州”`。完整旧事实必须唯一；也可复制管理页的记忆标识，使用“更正记忆 标识：新事实”。无法确定具体条目或内容时会先澄清，不会猜测另一个目标，也不会根据附件、转述或普通事实自行更正。

接受明确更正后，旧事实立即停止作为长期记忆召回。新的向量和历史同步完整成功后，页面才显示更正完成；暂停、停止、配置缺失或同步失败都不会提前报告成功。未完成时管理页显示目标事实及“重试更正”，聊天可沿原回答恢复或重试；已修改过的旧页面需要刷新，避免覆盖较新内容。

更正保持同一记忆标识，原消息来源继续保留，每次更正另外标注管理页或聊天来源。同步通常只需要一次受预算控制的嵌入请求，不调用模型推测修改对象；重复提交、部分提交后的核对和预算恢复不会重复修改或多增一个版本。源聊天中的原文字仍保留，相关召回只采用当前完整成功的事实。

更正记录及所有尝试关联均保存在 PostgreSQL，应用启动自动迁移，无新增配置文件。`pnpm --dir frontend test:correction` 默认使用 18098/18099，支持测试端口环境变量覆盖。更正、来源、失败恢复和适配验证，以及后续删除需清理的数据合同见 [任务 07 验收记录](docs/verification-07.md)。真实云端嵌入兼容性和账单仍待验。

## 候选记忆确认（任务 08）

当前个人表达如“我喜欢简洁的中文回答”可以出现候选卡片，展示具体事实、归属和原消息。“最近在杭州”等可能变更还展示准备更新的旧条目。点击确认后才写入正式长期记忆；拒绝、过期或目标已经变化的卡片不会覆盖当前事实。卡片有效期为七天，刷新及重启保留真实状态。

自动发现只处理当前用户消息，不从助手回答、旧聊天或附件中擅自提取。首版使用保守中文表达门槛，未触发时仍可直接明确要求保存；完整边界见 [任务 08 验收记录](docs/verification-08.md)。提取会增加一次计量的聊天模型请求，确认后嵌入另计；每一步检查预算。失败提供独立重试入口，未完成不会报告保存成功。

候选、来源、目标版本与重试关联保存在 PostgreSQL，应用启动自动迁移，无新增设置。`pnpm --dir frontend test:candidates` 默认使用 18108/18109，可通过测试端口环境变量覆盖。真实候选提取质量和嵌入服务兼容性仍待验。

## 忘记长期记忆（任务 09）

在“长期记忆”页面点击“忘记这条记忆”，或发送“删除记忆：完整事实”“忘记记忆 UUID”。完整事实必须唯一；不明确时会先澄清。删除立即停止召回，真实 Mem0 向量与全部内部历史核验清理后才报告完成；失败显示“清理未完成”，可重试，重启不会恢复被停用的事实。

忘记会清除相关候选、历次更正正文、派生搜索和最终资料缓存，并使旧卡片和旧预算许可失效。原聊天及原附件仍保留，原聊天中相同信息仍可主动回看；删除原文属于独立的来源删除功能。最小防恢复标记只保存身份，不保存被删事实。新用户消息重新明确保存属于新授权。

删除是本地 PostgreSQL / Mem0 操作，不调用云端、不受月度预算阻挡，也不要求当前嵌入连接可用。界面需要重试时只继续清理同一标识，不删除其他独立条目。详见 [任务 09 验证记录](docs/verification-09.md)。浏览器专项 `pnpm --dir frontend test:deletion` 默认使用 18110/18111，可用 `TEST_APP_PORT` / `TEST_MODEL_PORT` 覆盖。

## 会话文本资料（任务 10）

新建或进入会话后，在聊天框“添加资料”上传 UTF-8（含 BOM）的 TXT / Markdown。选中的文件随下一条消息发送，每条消息最多五个，每个最多 20 MB（20,000,000 字节）。后端对实际字节、数量、归属和可读取状态执行限制；分批上传也不能一次发送超过五个。未随消息发送的上传不会进入回答材料。

上传后显示处理中、可用或失败；失败文件取消选择后可继续普通聊天。原会话刷新、重启或重新进入后仍能使用已发送文件，新会话需要重新上传。同一原文件每次上传均独立保存，不存在跨会话文件库。上传及文字解析在本机完成；被选作回答依据的相关片段会发送给你配置的云端模型，回答请求使用统一预算和用量记录。

回答中的合法出处显示原文件、行号或行内字符范围，并附可核对摘录；点击文件位置可下载原文件。模型引用了未提供的标记时显示未核验；没有合法出处的资料回答也会明确提示。具体问题先按本条所选或具名的已发送文件限定范围，再使用最多十二个相关片段；明确要求全文总结或完整比较时，会逐段处理全部可提取文字后汇总，并展示真实进度与范围。PDF、DOCX、PNG / JPEG 已支持，Excel、音视频和扫描 OCR 不在本期范围。

原文件保存于 `APP_DATA_DIR/attachments/`，原文件名只用于显示，不用于构造磁盘路径。处理状态、行号及派生检索文字保存在 PostgreSQL，独立于长期记忆。原文件与数据库都需要保留；手工删文件夹不会同步清理数据库。来源删除与关联记忆选择由任务 15 提供。进程重启中断解析时显示失败并提示重新上传，不会把部分解析标作成功。

任务 10 的受控接口、上传浏览器、真实进程重启证据和后续模块合同见 [任务 10 验收记录](docs/verification-10.md)。真实云端资料理解与引用质量待验；本轮没有发送个人文件到真实外部服务。

## PDF 与 Word 文字资料（任务 11）

同一上传入口支持文本型 PDF 和 DOCX，继续限制每次五个文件、每个 20 MB。PDF 最多 200 页，出处对应实际物理页；Word 支持正文段落与表格，以段落、表格行列定位。上传卡片展示提取页数或段落数、缺口和限制，部分可读不会显示为完整阅读。

扫描 PDF 不做 OCR；空白、加密、损坏或超限文件会明确失败。复杂图表、内嵌图片和特殊排版需要将相关图像单独上传。Word 修订、文本框、页眉页脚等内容不在当前文字提取范围，存在时会说明缺口；请处理修订或将需要的内容放入正文再上传。这里的文字可用不代表已理解全部图像，也不代表全文总结已完成。

解析在本机受资源限制的独立进程执行：最长 20 秒、内存监测 512 MiB、最多提取 2,000,000 字符；DOCX 展开最多 2000 个条目、单项 10 MB、合计 50 MB。达到限制需拆分或简化文档。范围说明持久保存在 PostgreSQL 的附件元信息，原文件位置和现有启动方式不变。接口、格式样本、浏览器及真实服务待验记录见 [任务 11 验收记录](docs/verification-11.md)。

## 会话图片与视觉问答（任务 12）

在“添加资料”选择 PNG、JPG 或 JPEG；图片沿用每条消息五个、每个 20 MB 的限制。后台核验真实格式、完整性与解码，显示可用或失败以及实际尺寸。为控制解码资源，图片最多 4,000 万像素；多帧 PNG 需单独导出要分析的帧。文档图表或截图可另存为图片上传，本功能不自动理解 PDF / DOCX 内嵌图片，也不提供扫描 OCR。

在设置中运行“检查图片”，当前模型验证通过后，勾选图片发送问题。原会话可再次选图、指定文件名或明确追问“看看这张图片”。图片只属于原会话，新会话需要重新上传。普通聊天和直接“请记住：具体事实”不因会话已有图片而强制视觉能力；不需要发送图片时取消本条选择。改变模型、服务或密钥后需要重新验证图片能力。

实际读图时，后端把所选图片原字节发送给配置的模型，继续使用统一预算、用量、停止与重试。图片答案的出处指向“图片本身”，不会标造页码或假文字摘录。服务可能拒绝大图片或多图请求，失败不会被显示成已经理解；已取得的用量仍记录。真实识图和图表理解质量仍需实际服务验收。

运行 `pnpm --dir frontend test:images` 可在隔离端口 18096/18097 验证上传、视觉检查与原消息重试；支持同样的测试端口环境变量。实现、持久化和受控测试证据见 [任务 12 验收记录](docs/verification-12.md)。真实视觉服务验收待验，本轮没有把个人图片发往真实云端服务。

### 全文总结与多文件比较

发送文档时写“请全文总结资料”或“完整比较这几份文档”，系统会逐段处理全部可提取文字，包含末尾，再形成带出处的最终结果。当前消息所选文件优先；未重新选文件时，可按名称指定当前会话已发送的资料。新会话仍需重新上传。

聊天内显示完成步骤数和各文件范围，预算暂停、停止和失败都保留状态，刷新或应用重启后可以恢复。每个分段、汇总和最终回答都是一次独立模型请求，分别计量并受预算约束；批准一次只放行下一次请求。重试复用已持久完成的分段，不重复发送这些步骤。进程中断时未确认的结果仍可能需要重新请求，其上次用量会明确显示未知。记忆更正后重试仅重做依赖变更的最终回答，保留文档分段。

文字解析缺口和图片未读取范围会如实列出；全文任务完成不代表扫描页、嵌图、复杂排版或失败文件已被理解。当前文字总结不对图片执行视觉阅读；需要看图请在普通图片问答中明确提问。任务及分段缓存保存在 PostgreSQL，无新增启动配置。验收与删除清理合同见 [任务 13 验证记录](docs/verification-13.md)。


## 明确联网与外发确认（任务 17）

设置页“联网搜索”可填写独立 Tavily 密钥，默认 API 地址为 `https://api.tavily.com`；也可改为自己的兼容端点。搜索配置独立保存、掩码读取和移除，不复用聊天密钥。保存不会发出搜索请求，未配置仍可使用普通聊天、附件与记忆；明确要求搜索时会提示配置。

以“联网搜索：杭州天气”或“请上网查询：…”开头发起本次搜索。仅当前用户的明确指令会触发，不从旧聊天、附件、网页命令或解释示例中自动联网。搜索采用 Tavily basic/general，每次最多五条结果；回答显示本次实际结果中的可打开链接，无法核验的标记会提示未核验。未执行、超时和失败都显示真实状态。公开主题中的“资料、图片、文件扩展名、记忆研究”等词不会自动授权读取私人附件或长期记忆。

可说“联网搜索：根据长期记忆里的住址查附近咖啡店”或“联网搜索：根据附件里的地址查附近咖啡店”。系统先读取相关正式记忆或当前会话已发送资料，用配置的模型生成具体查询，并展示完整查询、用途和来源。此准备过程仍可能调用云端聊天或嵌入模型；在你批准前不会把查询交给 Tavily。所有来源于记忆或附件的查询都经过确认，不依赖模型判断是否敏感。

你可以编辑查询并保存、拒绝或允许发送。批准绑定当前会话、查询修订、来源版本和本次执行，有效期 30 分钟；修改内容后必须批准新修订。来源更正、删除或配置变化后不能复用旧批准，重复确认也不重复搜索。预算批准与外发批准分别检查；已完成搜索后暂停最终回答，恢复不会重复搜索。停止后重试创建新执行，涉及资料的查询需重新确认。

设置中的 `tavily-basic 每 credit 单价` 使用人民币元 / credit。查询准备、搜索与最终回答都经过逐次预算检查和实际用量记录；服务没有报告 credits 时显示未知，不把 basic 请求擅自记为固定费用。搜索结束不代表回答也已完成，已发请求在停止后仍可能产生服务费用。

搜索设置不需要新增启动步骤。`pnpm --dir frontend test:search` 默认使用隔离端口 18102 / 18103 / 18104；可用 `TEST_APP_PORT`、`TEST_MODEL_PORT`、`TEST_SEARCH_PORT` 覆盖。确认、失败、重启、来源更正和预算的受控验证，以及后续删除的必要清理合同见 [任务 17 验收记录](docs/verification-17.md)。真实 Tavily 协议、来源质量、credits 和账单仍 **待验**；本轮没有使用真实搜索密钥或发送个人资料到真实搜索服务。


## 明确查询旧聊天（任务 16）

在聊天中发送“查找旧聊天：蓝鲸”或“请查询聊天记录：旅行 预算”，才会查找其他会话仍有效的消息。使用冒号或空格分隔关键词；普通聊天、否定或讨论这个功能不会自动检索。首版在本机做大小写不敏感的原文关键词匹配，多个词以空格分隔，最多返回最近八条匹配消息，每条最多 1200 字符并标明截断。它不做语义向量检索；找不到时可用更短的原文关键词再试。

回答下方展示实际检索到的消息摘录、用户或助手角色、日期与原会话。点击“查看原消息”可回到对应会话并定位原文。模型编造的 H 引用不会生成可信出处；模型漏引时仍显示实际消息供核对。来源失效后摘录不再公开，提示重新查询。历史中的事实可能已经变化，应按原讨论的时间和语境理解。

历史检索不会读取旧附件原文件或解析片段，不会把旧消息自动变成候选或正式记忆，也不结合当前长期记忆推断过去的说法。要在新会话使用旧附件仍需重新上传。仅删除长期记忆时，保留的原聊天仍可按明确请求回看；删除原会话后的来源由来源删除流程失效。

本机查询不需要嵌入服务或 Tavily，也不产生云请求；有结果时只将有限消息摘录和本次问题发送给已配置的聊天模型，最终回答沿统一预算计量。没有匹配或来源已失效时使用本地回执，不额外请求模型。停止、重试和预算恢复沿原聊天流程处理。没有新增设置或启动步骤，迁移随应用启动自动完成。

`pnpm --dir frontend test:history` 默认使用 18114 / 18115；完整 `test:e2e` 包含该流程。公开接口、真实 PostgreSQL/Mem0、来源失效与浏览器跳转的证据和 09/15 清理合同见 [任务 16 验收记录](docs/verification-16.md)。真实模型的历史摘要质量和实际账单仍待验。


## 从附件提取长期记忆（任务 14）

在当前会话发送文件后，明确输入“请从附件提取长期记忆”，也可点名已发送的文件。每次最多五个文件，提取本次相关文字片段或实际图片内容，最多提出五个候选，不表示已穷尽全文。普通上传、阅读、总结或材料内的记忆指令不会授权保存。PDF/DOCX 沿用文字提取及可信位置；图片只有实际读取时才要求当前配置的视觉能力检查通过。

每条候选先展示事实、人物提示、原文依据和文件出处。选择“我本人”或填写其他人物的名称/关系后，点击“更新人物预览”仅改变预览；核对后另点“确认保存”才写入该条 Mem0 记忆。朋友、客户资料不会默认归为你本人。可以独立拒绝其他候选，确认前它们不参与跨会话召回。正式记忆管理页保留文件来源和已批准人物。

提取与确认嵌入分别遵守预算，失败、停止、重试和重启保持真实进度；确认时原文件失效会拒绝提交旧候选。直接聊天“请记住：具体事实”仍直接保存。候选、人物与文件来源关系保存在 PostgreSQL，原附件位置不变。运行 `pnpm --dir frontend test:attachment-memory` 验证隔离浏览器流程；真实附件模型/视觉/嵌入验收待验，边界和清理合同见 [任务 14 验收记录](docs/verification-14.md)。

## 删除会话或附件（任务 15）

点击“删除当前会话”或附件旁的“删除附件”，先查看全部关联长期记忆。列表默认勾选一起删除；取消勾选可明确保留已完整保存、实际可读取的事实。保留项在长期记忆页标记“来源已删除”，仍可召回、编辑和忘记。未批准或已拒绝的变更候选不会让其他会话的原正式记忆成为删除目标。

删除会话会移除其消息和附件；单独删除附件会清原文件、解析片段、相关候选与全文处理缓存，并撤销旧搜索批准及来源引用。单附件删除保留已经完成的聊天正文，其他会话独立上传的同名或同内容文件不受影响。正在处理的来源先停用，晚到解析或模型结果不能恢复正文；旧请求不能通过重试改用别的文件，需要重新选择并发送。

若部分本机清理失败，会明确显示未完成，并保留“重试来源清理”入口；刷新或重启后仍沿原批准选择继续。删除本身不调用模型、不需要预算额度，已经发生的费用保留。迁移由应用启动执行，删除状态保存在 PostgreSQL，原附件仍位于 `APP_DATA_DIR/attachments/<UUID>`，无需新增服务或密钥。

专项浏览器命令 `pnpm --dir frontend test:source-deletion` 默认使用 18116/18117，支持 `TEST_APP_PORT` / `TEST_MODEL_PORT`；完整 `test:e2e` 已包含。受控真实 PostgreSQL/Mem0 验证和供重建使用的保留/锁合同见 [任务 15 验收记录](docs/verification-15.md)。真实云端兼容性及账单验收仍待验。


## 更换嵌入空间与索引重建（任务 18）

在设置中修改嵌入地址、模型或维度并点击保存，会先预览有效记忆数量和影响范围；确认后才启动可能计费的验证及重建。当前只有已批准长期记忆采用向量检索。附件文字、全文总结、图片理解和历史消息不使用向量索引，本次不重建这些内容，也不提供数据迁移工具。同空间轮换密钥仍可直接保存，随后重新验证。

重建期间显示活动与目标模型、真实进度、暂停和失败状态。如果已有未完成的记忆保存或更正，重建会保留旧索引并提示先取消重建、恢复原操作或明确忘记该条目，避免丢失原修改的恢复身份。长期记忆召回及新的保存、更正、确认暂时暂停；普通聊天和本机资料/历史功能仍可使用。每次探针、事实嵌入和失败重试独立检查预算，按钮只批准下一次调用。刷新或重启后从设置中的原任务继续，完成的目标向量先核对再复用；进程中断而未获得的响应仍按未知用量记录，不承诺中断请求完全没有费用。

只重建当前有效且完整成功的已批准事实，保留正式 ID、正文、原时间及来源关系；来源已删除但明确保留的事实仍有效。忘记记忆会立即停用，并清活动、未完成目标及待清理旧空间的副本后才报告成功。未确认候选、已删除事实与历史旧值不会被重建恢复。

任务、空间、步骤及操作关联保存在 PostgreSQL。目标密钥暂存于 `APP_DATA_DIR/embedding-rebuilds/<任务 UUID>.json`，权限沿用现有私有配置文件；完成或取消后清除。活动配置仍是 `APP_DATA_DIR/embedding.json`。发布中断时保持维护状态，继续原任务会核对同一目标并完成文件及数据库切换；发布已开始后不能取消回旧空间。新索引可用但旧表清理失败时会如实提示，继续仅重试本机清理。没有新增启动步骤，仍使用单个后端进程。

`pnpm --dir frontend test:rebuild` 默认使用隔离端口 18118 / 18119，支持 `TEST_APP_PORT`、`TEST_MODEL_PORT`，并包含在 `test:e2e`。协议、并发删除和进程恢复的受控证据见 [任务 18 验收记录](docs/verification-18.md)。真实嵌入服务的目标模型、维度、相关性和实际账单仍待验；本票没有使用真实密钥或调用付费云服务。

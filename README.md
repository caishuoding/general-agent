## 启动

需要 Docker Desktop（已启动）、Python 3.12+、uv、Node.js 22.12+ 和 pnpm 11.25.0。项目锁定 Python、前端依赖及 PostgreSQL 基础镜像摘要，并从固定版本、校验和的源码构建 pgvector 0.8.7。首次构建需要访问 Docker、Alpine 软件源与 GitHub。

在项目根目录执行：

```sh
bash scripts/start.sh
```

脚本安装锁定的依赖、构建前端，启动业务 PostgreSQL、独立 Mem0 PostgreSQL 和官方 Mem0 API，随后在前台启动应用。若电脑安装了 Codex 自带运行时，脚本也会尝试使用它；可通过 `GENERAL_AGENT_PYTHON` 指定其他 Python。浏览器打开 [本机应用](http://127.0.0.1:8000)，Mem0 API 仅监听 `127.0.0.1:8888`。

在设置中输入服务商提供的 API 基础地址（通常以 `/v1` 结尾）、文字模型名称和 API 密钥，然后新建会话并发送消息。接口使用 OpenAI 兼容的 Chat Completions；保存配置仅表示已保存，不代表服务能力已验证。云端地址使用 HTTPS，本机服务允许回环 HTTP。更换服务地址需重新填写密钥；同一地址留空密钥会保留原密钥。

回答会逐段显示，页面和 PostgreSQL 都保留生成中、完成、已停止或失败状态。点击“停止生成”会冻结当前回答，不再追加后续文字；已经发出的模型请求会继续接收可返回的用量，因此停止不保证撤销服务商费用。浏览器断开或切换会话不会自动停止后端生成，重新进入后会恢复进度。

最新失败或停止的回答可点击“重试回答”；重试保留旧尝试及部分内容，创建新的调用记录，不重复插入用户消息。模型断流、输出长度限制和不支持流式接口都会明确显示为未完成。服务必须支持 Chat Completions 的 SSE 流式响应、结束标记与 stream_options.include_usage；本版本不会自动重发请求或回退成另一次调用。

设置页展示最近 100 次调用的状态以及服务返回的 token 或 credits。服务未返回用量时保留空值；重试产生新的实际调用记录。应用不维护价格、不估算费用，真实计费以服务商账单为准。

按 Ctrl+C 停止应用。停止数据库可执行 `docker compose stop`；再次启动后数据仍保留。数据库默认仅监听 `127.0.0.1:15432`，应用仅监听 `127.0.0.1:8000`。

## 数据与配置

| 内容 | 位置 |
| --- | --- |
| 会话、消息、调用记录、幂等操作、记忆来源及操作状态、结构版本 | 业务 PostgreSQL 的 `general-agent_postgres_data` 持久化卷 |
| Mem0 记忆正文、向量和内部历史 | 独立 Mem0 PostgreSQL 与 `mem0-history` 卷 |
| 搜索地址与独立智谱密钥 | `.local/search.json`，或 `APP_DATA_DIR/search.json`，仅当前用户可读写 |
| 搜索具体查询、来源版本、单次批准、实际结果和回答引用 | PostgreSQL 的 `search_requests` 与消息记录 |
| 历史聊天查询与出处标识、消息内容指纹（不另存摘录正文） | PostgreSQL 的 `history_queries` / `history_hits`；原文仍为 `messages.content` |
| 模型地址、名称、密钥 | 项目内 `.local/model.json`，新建文件权限为仅当前用户可读写 |
| Mem0 嵌入配置 | `.local/embedding.json`；`mem0-config` 启动容器读取后调用官方 `/configure` |
| 附件归属、处理状态、文字提取范围与缺口、文字片段与消息引用 | PostgreSQL 同一业务库中的独立附件表 |
| 附件原文件 | `.local/attachments/<附件 UUID>`，或 `APP_DATA_DIR/attachments/` |
| 前端构建 | `frontend/dist/`，可重新生成 |
| 规格与任务 | `.scratch/general-agent/` |

`.local/`、环境文件、依赖和构建产物均已排除 Git。业务后端只通过 `MEM0_API_URL` 调用官方 Mem0 REST API，不导入 Mem0 SDK、不直接访问 Mem0 数据库，也不在业务库复制记忆正文或向量。附件原文件与业务 PostgreSQL 中的派生文本分别保存。密钥仅由后端和一次性配置容器读取，配置接口不回传完整密钥；模型错误正文不会直接展示。

可用环境变量：`DATABASE_URL` 指定业务 PostgreSQL；`MEM0_API_URL` 指定 Mem0 API；`MEM0_API_KEY` 设置可选认证；`MEM0_USER_ID` 指定 Mem0 用户范围（默认 `local-person`）；`APP_DATA_DIR` 指定本机配置目录；`POSTGRES_PORT` 修改业务数据库宿主端口。Compose 内的密码仅用于本机开发实例。

数据库结构在应用启动时按版本迁移，已应用的迁移不会重复执行。应用使用单个后端进程运行；启动时会将上次进程中断的生成记录标为失败并保留已提交的内容与用量，请勿用多个 worker 共用同一业务库。请保留数据库卷；`docker compose down -v` 会删除其数据。

## 模型能力与独立嵌入配置（任务 03）

设置页分别提供文字、图片、工具调用与嵌入检查。每个检查都会对已保存配置发出真实请求，可能产生费用；记录可获取的用量，服务缺失用量时显示未知。保存嵌入配置后会立即验证一次。各项结果独立显示，修改连接地址、模型或密钥后旧结果失效；仅保存相同值会保留结果。检查使用固定测试内容，不发送会话或附件正文。

嵌入连接单独保存 API 地址、模型名称、密钥和预期维度。可以显式选择复用已保存聊天服务的地址与密钥，嵌入模型和维度仍需独立填写；复制后两套连接各自管理。嵌入检查请求 `/embeddings`，要求服务返回的模型标识与填写值一致、维度一致、向量为有限数值。若服务使用别名，请填写响应实际返回的模型标识，不能仅凭文字调用成功认定嵌入可用。

嵌入配置保存在 `.local/embedding.json`，与 `.local/model.json` 一样由本机后端以仅当前用户可读写的权限原子保存。配置版本随连接实际变更更新，能力结果保存在业务 PostgreSQL。重启 Mem0 Compose 后，一次性 `mem0-config` 容器会把聊天模型与嵌入配置提交给官方 `/configure`。完整密钥不出现在读取响应、能力错误或应用日志中。

业务应用不拥有 Mem0 的向量空间。更换嵌入服务、模型或维度后，应重启 Mem0 服务，由 Mem0 自己管理其索引；本项目不提供本地重建、代次表或向量迁移接口。检查通过仅表示本次基础协议验证通过，不代表 Mem0 已热加载新配置，也不保证相关性质量。

`pnpm --dir frontend test:e2e` 运行当前保留的会话、资料、搜索、来源删除和设置浏览器流程。能力设置专项也可单独运行 `pnpm --dir frontend test:capabilities`。实现边界、接口与历史测试证据见 [任务 03 验收记录](docs/verification-03.md)。

## 自动记忆、查看和对话工具

本次策略变更、受控测试与真实服务待验范围见[原生记忆验证记录](docs/verification-native-memory.md)。

先在设置中填写独立嵌入服务、模型与维度，并运行“检查嵌入”。聊天服务支持文字对话不表示它提供嵌入；缺少嵌入时普通聊天可用，自动记忆会明确提示缺少配置，补齐后可独立重试。

普通用户事实由 Mem0 原生 `infer=True` 流程提取和维护，不再逐条确认。纯提问、资料操作和不保存指令不会触发自动提取，不回填旧聊天。前端不展示长期记忆管理页；真实记忆正文、向量和历史应从独立 Mem0 存储核对，业务 PostgreSQL 只保留来源、动作和恢复状态。明确的“请记住：具体事实”仍可原样直接保存。

自动整理、嵌入和内部历史都由 Mem0 服务处理。应用按稳定动作身份先查询再写入，重试会核对 Mem0 返回的正式 ID，避免重复记忆。停止不会撤销 Mem0 已完成的保存，但会阻止应用尚未发出的后续动作。

Mem0 由 `mem0/` 下的官方源码 Docker 服务运行，业务后端只使用 REST API。Mem0 PostgreSQL 与业务 PostgreSQL 物理分离，应用不实现 `add`、`delete`、history 或 pgvector 适配层。默认遥测已关闭，配置由一次性容器通过官方 `/configure` 注入。

已有数据库卷从旧镜像切换时先停止应用并备份数据库，再执行 `docker compose up -d --build --wait`；保持现有卷和 PostgreSQL 主版本，不使用 `down -v`。此构建保持相同 PostgreSQL 17 Alpine 基础，安装 pgvector 扩展；正式库升级仍应核对原会话和记忆。`pnpm --dir frontend test:memory` 默认使用 18088/18089，所有浏览器专项均可用 `TEST_APP_PORT`、`TEST_MODEL_PORT` 隔离端口；测试 PostgreSQL 也必须提供 pgvector。

## 相关长期记忆召回（任务 06）

保存成功的记忆可以在新会话回答中使用。普通问题只检索个人身份下相关且仍有效的正式记忆，不会自动读取其他会话消息或附件；未被 Mem0 保存的聊天内容、未完整提交的记忆不会进入跨会话记忆召回。召回材料不会再次自动保存，明确保存操作仍按任务 05 的独立回执处理。

存在正式记忆时，每次普通问题先执行一次嵌入检索，再按需发送回答请求，两次调用分别记录用量。恢复执行会重新核验结果标识及版本，且不会重复已经完成的嵌入。检查点只保存标识和版本，不复制事实正文；已变更或移除的条目不会沿旧结果使用。没有正式记忆时普通聊天不增加嵌入调用。

嵌入未配置、未验证或召回失败时，应用会继续尝试基于当前会话回答。当前使用相似度阈值 0.72、最多五条有效记忆，该工程默认值的真实语义质量仍需用你选择的嵌入模型验收。

召回状态及标识检查点保存在 PostgreSQL，无新增本机配置文件或启动步骤。受控接口、重启和停止证据见 [任务 06 验收记录](docs/verification-06.md)；真实云端嵌入兼容性、相关性与账单仍待验。

## 编辑和对话记忆工具

智能体可使用 `search_memories`、`update_memory`、`delete_memory` 三种真实函数工具，例如“你记得我的住址吗”“把我的居住地改成苏州”“忘掉我的咖啡偏好”。先查找有效条目，再按当前用户意图及版本操作；目标不明确时澄清。当前每次对话请求更新或删除一条具体记忆。旧格式的精确更正、删除命令仍保留本地快捷路径。工具沿用当前聊天模型，不另设 LLM。

## 编辑与明确更正长期记忆（任务 07）

在聊天中发送`更正记忆：我住在杭州 => 我住在苏州`，或 `请把记忆中的“我住在杭州”改为“我住在苏州”`。完整旧事实必须唯一；也可从 PostgreSQL 查询记忆标识后使用“更正记忆 标识：新事实”。无法确定具体条目或内容时会先澄清，不会猜测另一个目标，附件和转述不会授权这条快捷命令；普通用户事实另由 Mem0 自动判断变更。

接受明确更正后，旧事实立即停止作为长期记忆召回。新的向量和历史同步完整成功后，聊天状态才显示更正完成；暂停、停止、配置缺失或同步失败都不会提前报告成功。未完成时可沿原回答恢复或重试。

更正保持同一记忆标识，原消息来源继续保留，每次更正另外记录聊天来源。精确命令同步通常只需要一次嵌入请求；自然语言工具及自动整理另有模型调用。重复提交及部分提交后的恢复不会重复修改或多增一个版本。源聊天中的原文字仍保留，相关召回只采用当前完整成功的事实。

更正记录及所有尝试关联均保存在 PostgreSQL，应用启动自动迁移，无新增配置文件。`pnpm --dir frontend test:correction` 默认使用 18098/18099，支持测试端口环境变量覆盖。更正、来源、失败恢复和适配验证，以及后续删除需清理的数据合同见 [任务 07 验收记录](docs/verification-07.md)。真实云端嵌入兼容性和账单仍待验。

## 自动记忆与旧候选兼容

聊天中的新事实由 Mem0 原生自动整理，并显示处理状态。应用不创建待确认卡片，也不保留候选记忆接口或兼容数据。附件不会进入自动记忆输入，也不会被当作个人事实。

原生推理、每次嵌入与对话工具均单独记录用量。失败状态保存在 PostgreSQL；已完成步骤与部分写入先核对再恢复。

## 忘记长期记忆（任务 09）

发送“删除记忆：完整事实”“忘记记忆 UUID”或使用对话记忆工具删除。完整事实必须唯一；不明确时会先澄清。删除立即停止业务召回，再调用 Mem0 官方删除接口；失败会保留可重试状态，重启不会恢复被停用的事实。

忘记会清除历次更正正文、派生搜索和最终资料缓存，并使旧操作失效。原聊天及原附件仍保留，原聊天中相同信息仍可主动回看；删除原文属于独立的来源删除功能。最小防恢复标记只保存身份，不保存被删事实。新用户消息重新明确保存属于新授权。

直接删除是本地 PostgreSQL / Mem0 操作，不调用云端，也不要求当前嵌入连接可用；自然语言工具在找到目标前的模型规划和语义查找仍会产生模型调用。界面需要重试时只继续清理同一标识，不删除其他独立条目。详见 [任务 09 验证记录](docs/verification-09.md)。

## 会话文本资料（任务 10）

新建或进入会话后，在聊天框“添加资料”上传 UTF-8（含 BOM）的 TXT / Markdown。选中的文件随下一条消息发送，每条消息最多五个，每个最多 20 MB（20,000,000 字节）。后端对实际字节、数量、归属和可读取状态执行限制；分批上传也不能一次发送超过五个。未随消息发送的上传不会进入回答材料。

上传后显示处理中、可用或失败；失败文件取消选择后可继续普通聊天。原会话刷新、重启或重新进入后仍能使用已发送文件，新会话需要重新上传。同一原文件每次上传均独立保存，不存在跨会话文件库。上传及文字解析在本机完成；被选作回答依据的相关片段会发送给你配置的云端模型，回答请求使用统一调用和用量记录。

回答中的合法出处显示原文件、行号或行内字符范围，并附可核对摘录；点击文件位置可下载原文件。模型引用了未提供的标记时显示未核验；没有合法出处的资料回答也会明确提示。具体问题先按本条所选或具名的已发送文件限定范围，再使用最多十二个相关片段；明确要求全文总结或完整比较时，会逐段处理全部可提取文字后汇总，并展示真实进度与范围。PDF、DOCX、PNG / JPEG 已支持，Excel、音视频和扫描 OCR 不在本期范围。

原文件保存于 `APP_DATA_DIR/attachments/`，原文件名只用于显示，不用于构造磁盘路径。处理状态、行号及派生检索文字保存在 PostgreSQL，独立于长期记忆。原文件与数据库都需要保留；手工删文件夹不会同步清理数据库。来源删除与关联记忆选择由任务 15 提供。进程重启中断解析时显示失败并提示重新上传，不会把部分解析标作成功。

任务 10 的受控接口、上传浏览器、真实进程重启证据和后续模块合同见 [任务 10 验收记录](docs/verification-10.md)。真实云端资料理解与引用质量待验；本轮没有发送个人文件到真实外部服务。

## PDF 与 Word 文字资料（任务 11）

同一上传入口支持文本型 PDF 和 DOCX，继续限制每次五个文件、每个 20 MB。PDF 最多 200 页，出处对应实际物理页；Word 支持正文段落与表格，以段落、表格行列定位。上传卡片展示提取页数或段落数、缺口和限制，部分可读不会显示为完整阅读。

扫描 PDF 不做 OCR；空白、加密、损坏或超限文件会明确失败。复杂图表、内嵌图片和特殊排版需要将相关图像单独上传。Word 修订、文本框、页眉页脚等内容不在当前文字提取范围，存在时会说明缺口；请处理修订或将需要的内容放入正文再上传。这里的文字可用不代表已理解全部图像，也不代表全文总结已完成。

解析在本机受资源限制的独立进程执行：最长 20 秒、内存监测 512 MiB、最多提取 2,000,000 字符；DOCX 展开最多 2000 个条目、单项 10 MB、合计 50 MB。达到限制需拆分或简化文档。范围说明持久保存在 PostgreSQL 的附件元信息，原文件位置和现有启动方式不变。接口、格式样本、浏览器及真实服务待验记录见 [任务 11 验收记录](docs/verification-11.md)。

## 会话图片与视觉问答（任务 12）

在“添加资料”选择 PNG、JPG 或 JPEG；图片沿用每条消息五个、每个 20 MB 的限制。后台核验真实格式、完整性与解码，显示可用或失败以及实际尺寸。为控制解码资源，图片最多 4,000 万像素；多帧 PNG 需单独导出要分析的帧。文档图表或截图可另存为图片上传，本功能不自动理解 PDF / DOCX 内嵌图片，也不提供扫描 OCR。

在设置中运行“检查图片”，当前模型验证通过后，勾选图片发送问题。原会话可再次选图、指定文件名或明确追问“看看这张图片”。图片只属于原会话，新会话需要重新上传。普通聊天和直接“请记住：具体事实”不因会话已有图片而强制视觉能力；不需要发送图片时取消本条选择。改变模型、服务或密钥后需要重新验证图片能力。

实际读图时，后端把所选图片原字节发送给配置的模型，继续使用统一调用、用量、停止与重试。图片答案的出处指向“图片本身”，不会标造页码或假文字摘录。服务可能拒绝大图片或多图请求，失败不会被显示成已经理解；已取得的用量仍记录。真实识图和图表理解质量仍需实际服务验收。

运行 `pnpm --dir frontend test:images` 可在隔离端口 18096/18097 验证上传、视觉检查与原消息重试；支持同样的测试端口环境变量。实现、持久化和受控测试证据见 [任务 12 验收记录](docs/verification-12.md)。真实视觉服务验收待验，本轮没有把个人图片发往真实云端服务。

### 全文总结与多文件比较

发送文档时写“请全文总结资料”或“完整比较这几份文档”，系统会逐段处理全部可提取文字，包含末尾，再形成带出处的最终结果。当前消息所选文件优先；未重新选文件时，可按名称指定当前会话已发送的资料。新会话仍需重新上传。

聊天内显示完成步骤数和各文件范围，停止和失败都保留状态，刷新或应用重启后可以恢复。每个分段、汇总和最终回答都是一次独立模型请求并分别记录用量。重试复用已持久完成的分段，不重复发送这些步骤。进程中断时未确认的结果仍可能需要重新请求，其上次用量可能为空。记忆更正后重试仅重做依赖变更的最终回答，保留文档分段。

文字解析缺口和图片未读取范围会如实列出；全文任务完成不代表扫描页、嵌图、复杂排版或失败文件已被理解。当前文字总结不对图片执行视觉阅读；需要看图请在普通图片问答中明确提问。任务及分段缓存保存在 PostgreSQL，无新增启动配置。验收与删除清理合同见 [任务 13 验证记录](docs/verification-13.md)。


## 明确联网与外发确认（任务 17）

设置页“联网搜索”可填写独立智谱密钥，默认 API 地址为 `https://open.bigmodel.cn/api/paas/v4`；也可改为自己的兼容端点。搜索配置独立保存、掩码读取和移除，不复用聊天密钥。保存不会发出搜索请求，未配置仍可使用普通聊天、附件与记忆；明确要求搜索时会提示配置。旧 Tavily 配置不会被自动复用为智谱配置。

以“联网搜索：杭州天气”或“请上网查询：…”开头发起本次搜索。仅当前用户的明确指令会触发，不从旧聊天、附件、网页命令或解释示例中自动联网。搜索采用智谱 `search_std` 基础引擎，每次最多五条结果，查询最多 70 字符；回答显示本次实际结果中的可打开链接，无法核验的标记会提示未核验。未执行、超时和失败都显示真实状态。公开主题中的“资料、图片、文件扩展名、记忆研究”等词不会自动授权读取私人附件或长期记忆。

可说“联网搜索：根据长期记忆里的住址查附近咖啡店”或“联网搜索：根据附件里的地址查附近咖啡店”。系统先读取相关正式记忆或当前会话已发送资料，用配置的模型生成具体查询，并展示完整查询、用途和来源。此准备过程仍可能调用云端聊天或嵌入模型；在你批准前不会把查询交给智谱。所有来源于记忆或附件的查询都经过确认，不依赖模型判断是否敏感。

你可以编辑查询并保存、拒绝或允许发送。批准绑定当前会话、查询修订、来源版本和本次执行，有效期 30 分钟；修改内容后必须批准新修订。来源更正、删除或配置变化后不能复用旧批准，重复确认也不重复搜索。停止后重试创建新执行，涉及资料的查询需重新确认。

查询准备、搜索与最终回答分别记录调用。搜索请求成功发出并收到 HTTP 响应后记录一次 credit；连接中断或超时时 credit 可能为空。搜索结束不代表回答也已完成，已发请求在停止后仍可能由服务商计费。

搜索设置不需要新增启动步骤。`pnpm --dir frontend test:search` 默认使用隔离端口 18102 / 18103 / 18104；可用 `TEST_APP_PORT`、`TEST_MODEL_PORT`、`TEST_SEARCH_PORT` 覆盖。原有确认、失败、重启和来源更正边界见 [任务 17 验收记录](docs/verification-17.md)；智谱替换验证见 [智谱搜索验证](docs/verification-zhipu-search.md)。


## 明确查询旧聊天（任务 16）

在聊天中发送“查找旧聊天：蓝鲸”或“请查询聊天记录：旅行 预算”，才会查找其他会话仍有效的消息。使用冒号或空格分隔关键词；普通聊天、否定或讨论这个功能不会自动检索。首版在本机做大小写不敏感的原文关键词匹配，多个词以空格分隔，最多返回最近八条匹配消息，每条最多 1200 字符并标明截断。它不做语义向量检索；找不到时可用更短的原文关键词再试。

回答下方展示实际检索到的消息摘录、用户或助手角色、日期与原会话。点击“查看原消息”可回到对应会话并定位原文。模型编造的 H 引用不会生成可信出处；模型漏引时仍显示实际消息供核对。来源失效后摘录不再公开，提示重新查询。历史中的事实可能已经变化，应按原讨论的时间和语境理解。

历史检索不会读取旧附件原文件或解析片段，也不会把旧消息送入 Mem0 自动记忆或结合当前长期记忆推断过去的说法。要在新会话使用旧附件仍需重新上传。仅删除长期记忆时，保留的原聊天仍可按明确请求回看；删除原会话后的来源由来源删除流程失效。

本机查询不需要嵌入服务或联网搜索服务，也不产生云请求；有结果时只将有限消息摘录和本次问题发送给已配置的聊天模型，最终回答沿统一网关记录用量。没有匹配或来源已失效时使用本地回执，不额外请求模型。停止和重试沿原聊天流程处理。没有新增设置或启动步骤，迁移随应用启动自动完成。

`pnpm --dir frontend test:history` 默认使用 18114 / 18115；完整 `test:e2e` 包含该流程。公开接口、真实 PostgreSQL/Mem0、来源失效与浏览器跳转的证据和 09/15 清理合同见 [任务 16 验收记录](docs/verification-16.md)。真实模型的历史摘要质量和实际账单仍待验。


## 附件与长期记忆边界

附件只用于当前会话的阅读、问答、比较、总结和图片理解。附件正文不会进入 Mem0；输入“请从附件提取长期记忆”不会启动独立提取流程。需要保存的事实应由用户在聊天消息中直接说出，再由聊天记忆流程处理。项目不保留附件记忆表或旧数据兼容逻辑。

## 删除会话或附件（任务 15）

点击“删除当前会话”时，先查看全部关联长期记忆。列表默认勾选一起删除；取消勾选可明确保留已完整保存、实际可读取的事实。保留项在长期记忆页标记“来源已删除”，仍可召回、编辑和忘记。删除附件没有记忆选择步骤，因为附件不会生成长期记忆。

删除会话会移除其消息和附件；单独删除附件会清原文件、解析片段与全文处理缓存，并撤销相关搜索批准及来源引用。单附件删除保留已经完成的聊天正文，其他会话独立上传的同名或同内容文件不受影响。正在处理的来源先停用，晚到解析或模型结果不能恢复正文；旧请求不能通过重试改用别的文件，需要重新选择并发送。

若部分本机清理失败，会明确显示未完成，并保留“重试来源清理”入口；刷新或重启后仍沿原批准选择继续。删除本身不调用模型，已经发生的调用记录保留。迁移由应用启动执行，删除状态保存在 PostgreSQL，原附件仍位于 `APP_DATA_DIR/attachments/<UUID>`，无需新增服务或密钥。

专项浏览器命令 `pnpm --dir frontend test:source-deletion` 默认使用 18116/18117，支持 `TEST_APP_PORT` / `TEST_MODEL_PORT`；完整 `test:e2e` 已包含。来源冻结与保留规则见 [任务 15 验收记录](docs/verification-15.md)。


## 更换 Mem0 模型配置

在设置中保存聊天模型和嵌入模型后，重启 `mem0` Compose。一次性 `mem0-config` 容器会读取 `.local/model.json` 与 `.local/embedding.json` 并调用官方 `/configure`。业务应用不扫描、复制或重建 Mem0 向量；需要迁移已有记忆空间时，应使用 Mem0 官方提供的运维能力，并在操作前备份独立 Mem0 数据卷。

## 系统提示词

所有发送给模型的稳定系统提示词、工具描述、资料信任边界和引用规则集中在 `backend/general_agent/prompts/`。附件、历史聊天、长期记忆、网页搜索和文档汇总模块只传入结构化动态资料，不再各自维护提示正文。

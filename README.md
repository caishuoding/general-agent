# 个人对话智能体

当前已实现任务 01、02、03、04：本机 Web 文字对话、独立聊天与嵌入配置、分项能力验证、会话持久化、流式回答、停止与失败重试，以及逐次调用计量、费用估算与月度预算暂停。长期记忆、附件和搜索仍按后续任务实现；记忆页面会明确显示尚未启用。

## 启动

需要 Docker Desktop（已启动）、Python 3.12+、uv、Node.js 22.12+ 和 pnpm 11.25.0。项目锁定 Python 与前端依赖，以及 PostgreSQL 镜像摘要。

在项目根目录执行：

```sh
bash scripts/start.sh
```

脚本安装锁定的依赖、构建前端、启动 PostgreSQL，随后在前台启动应用。若电脑安装了 Codex 自带运行时，脚本也会尝试使用它；可通过 `GENERAL_AGENT_PYTHON` 指定其他 Python。浏览器打开 [本机应用](http://127.0.0.1:8000)。

在设置中输入服务商提供的 API 基础地址（通常以 `/v1` 结尾）、文字模型名称和 API 密钥，然后新建会话并发送消息。接口使用 OpenAI 兼容的 Chat Completions；保存配置仅表示已保存，不代表服务能力已验证。云端地址使用 HTTPS，本机服务允许回环 HTTP。更换服务地址需重新填写密钥；同一地址留空密钥会保留原密钥。

回答会逐段显示，页面和 PostgreSQL 都保留生成中、完成、已停止或失败状态。点击“停止生成”会冻结当前回答，不再追加后续文字；已经发出的模型请求会继续接收可返回的用量，因此停止不保证撤销服务商费用。浏览器断开或切换会话不会自动停止后端生成，重新进入后会恢复进度。

最新失败或停止的回答可点击“重试回答”；重试保留旧尝试及部分内容，创建新的调用记录，不重复插入用户消息。模型断流、输出长度限制和不支持流式接口都会明确显示为未完成。服务必须支持 Chat Completions 的 SSE 流式响应、结束标记与 stream_options.include_usage；本版本不会自动重发请求或回退成另一次调用。

设置页展示最近100次调用的状态、服务返回 token 与费用估算，并按全部记录汇总上海时区当前自然月。用量或费用缺失显示为未知；可设置月度预算及按服务、模型绑定的单价。重试按新的实际调用计费。真实调用按你的服务商规则计费。

按 Ctrl+C 停止应用。停止数据库可执行 `docker compose stop`；再次启动后数据仍保留。数据库默认仅监听 `127.0.0.1:15432`，应用仅监听 `127.0.0.1:8000`。

## 数据与配置

| 内容 | 位置 |
| --- | --- |
| 会话、消息、调用记录、预算、单价、操作批准与幂等结果、结构版本 | PostgreSQL 的 `general-agent_postgres_data` 持久化卷 |
| 模型地址、名称、密钥 | 项目内 `.local/model.json`，新建文件权限为仅当前用户可读写 |
| 前端构建 | `frontend/dist/`，可重新生成 |
| 规格与任务 | `.scratch/general-agent/` |

`.local/`、环境文件、依赖和构建产物均已排除 Git。当前不写入附件，也未创建 Mem0 数据。密钥仅由后端读取，配置接口不回传完整密钥；模型错误正文不会直接展示。

可用环境变量：`DATABASE_URL` 指定 PostgreSQL；`APP_DATA_DIR` 指定本机配置目录；`POSTGRES_PORT` 修改 Compose 的宿主端口。修改数据库端口时，同步设置 `DATABASE_URL`。Compose 内的密码仅用于这个本机开发实例。

数据库结构在应用启动时按版本迁移，已应用的迁移不会重复执行。应用使用单个后端进程运行；启动时会将上次进程中断的生成记录标为失败并保留已提交的内容与用量，请勿用多个 worker 共用同一业务库。请保留数据库卷；`docker compose down -v` 会删除其数据。

## 开发与检查

```sh
uv sync --locked
docker compose up -d --wait
uv run mypy
uv run pytest tests/test_chat.py -q
pnpm --dir frontend typecheck
pnpm --dir frontend build
pnpm --dir frontend exec playwright install chromium
pnpm --dir frontend test:e2e
```

完整 Python 测试使用 `uv run pytest -q`。默认测试连接本机 PostgreSQL 的管理库，每个测试创建随机命名的独立数据库，结束后只删除它创建的数据库；可用 `TEST_DATABASE_URL` 指定专用测试实例。浏览器测试使用临时配置、独立数据库和本机受控模型，不读取你的模型密钥，不调用付费服务。可用 TEST_APP_PORT、TEST_MODEL_PORT 修改默认的 18080/18081 测试端口，用 TEST_PYTHON 指定测试服务的 Python。

开发热更新可分别运行 `uv run uvicorn general_agent.app:create_app --factory --app-dir backend --host 127.0.0.1 --port 8000 --reload` 和 `pnpm --dir frontend dev`，浏览器访问 Vite 提供的本机地址。

测试遵循应用对外接口边界，使用真实 PostgreSQL；测试用模型替身只替换外部 HTTP 响应。实际服务兼容性需填写自己的模型配置后验证，替身通过不等同于真实接口已验收。

## 模型能力与独立嵌入配置（任务 03）

设置页分别提供文字、图片、工具调用与嵌入检查。每个按钮都会对已保存配置发出真实请求，可能产生费用；记录可获取的用量，服务缺失用量时显示未知。保存配置本身不验证能力。各项结果独立显示，修改连接地址、模型或密钥后旧结果失效；仅保存相同值会保留结果。检查使用固定测试内容，不发送会话或附件正文。

嵌入连接单独保存 API 地址、模型名称、密钥和预期维度。可以显式选择复用已保存聊天服务的地址与密钥，嵌入模型和维度仍需独立填写；复制后两套连接各自管理。嵌入检查请求 `/embeddings`，要求服务返回的模型标识与填写值一致、维度一致、向量为有限数值。若服务使用别名，请填写响应实际返回的模型标识，不能仅凭文字调用成功认定嵌入可用。

嵌入配置保存在 `.local/embedding.json`，与 `.local/model.json` 一样由本机后端以仅当前用户可读写的权限原子保存。配置版本随连接实际变更更新。能力结果和索引身份登记保存在 PostgreSQL。完整密钥不出现在读取响应、能力错误或应用日志中。

后续检索消费者须登记所用嵌入空间。已有索引时，更换服务地址、模型或维度会明确提示需要重建，并拒绝修改；任务 18 实现重建前不允许静默混用。轮换相同空间的密钥仍可保存，但必须重新验证。检查通过仅表示本次基础协议验证通过，不保证服务支持全部图片任务，也不代表附件或长期记忆已实现。

`pnpm --dir frontend test:e2e` 依次运行原会话浏览器流程和独立能力设置流程；后者使用隔离端口 18084/18085，也可运行 `pnpm --dir frontend test:capabilities`。任务 03 的四项真实服务验收目前均待验；本任务没有读取或复制真实凭据，也没有发起付费请求。实现边界、接口与测试证据见 [任务 03 验收记录](docs/verification-03.md)。


## 用量与月度预算（任务 04）

预算和价格均以人民币元表示，模型输入/输出价格单位为元 / 百万 token；其他币种需自行换算。预算留空时不限制使用，填 0 时每次请求前暂停。达到额度、缺少单价、本月已有费用未知或仍有请求等待用量时，暂停新的云端调用。估算不等于服务商实际账单，也不是服务商扣费上限；单次已允许的请求仍可能超过额度。

暂停提示说明原因，可打开设置补价/调整预算后重新检查，也可取消或明确“仅允许下一次云端调用”。此批准绑定原操作和配置，不会永久放行或转移到别的会话。后续多轮执行每次调用仍需检查。补齐价格会为之前完整用量补算费用，已知费用保留调用时单价；缺失 usage 和缺少服务身份的旧记录无法安全补算。停止仍保留后续返回的用量，重试按新实际请求计量。

预算、单价、暂停挑战和幂等操作结果保存在 PostgreSQL。同步与流式聊天、能力检查、嵌入全部通过同一调用网关；未来 Mem0、资料与搜索必须复用它。显式跨线程上下文、批准、取消、缓存失效与多步骤续跑约束见 [任务04验收与公共接口合同](docs/verification-04.md)。当前仍按单个后端进程运行。

`pnpm --dir frontend test:budget` 使用独立端口18086/18087、临时配置与随机测试数据库；完整 `test:e2e` 也包含该流程。真实云端价格、usage 与账单对应尚待验，本任务没有读取真实凭据或发起付费请求。

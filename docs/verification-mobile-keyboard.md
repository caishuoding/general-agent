# 手机端键盘与会话布局验收

日期：2026-10-19

## 问题与原因

用户反馈 iPhone 点击消息输入框后，键盘出现，整个会话和输入区离开可见范围。

旧实现只监听 `visualViewport.resize` 并调整高度，没有跟随 `offsetTop` 和 `scroll`；消息定位使用 `scrollIntoView`，可能滚动外层文档。文档滚动与键盘视口调整叠加，不能保证聊天工作区留在可见区域内。

[VisualViewport 文档](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)说明软键盘会改变可视视口，页面可结合高度及偏移定位界面。本次按这一边界建立回归测试。

## 修复

- 仅在手机聊天工作区锁定外层文档滚动，页面退出后恢复普通滚动。
- 工作区及会话抽屉同时跟随可视视口高度和顶部偏移，合并同一帧的 resize、scroll 更新。
- 消息跟随仅滚动 `.chat-scroll`；键盘和输入区高度变化时，保持原有跟随状态。历史阅读不被强制跳到底部。
- 手机输入区采用紧凑布局，草稿自动增高并限制最大高度；键盘展开时收起辅助说明。
- 触屏发送或停止时保留输入焦点；手机端删除会话入口移入抽屉，给聊天内容留出空间。

## 回归结果

运行 `pnpm test:mobile`（独立 Vite 服务，不依赖数据库）。

测试使用模拟账号与会话，在 Chromium 中注入可控 VisualViewport，驱动真实应用的事件监听和布局。修复前两项测试均失败：模拟键盘打开后，顶部或输入区超出可视范围。修复后三项通过：

1. 可视视口从 844px 缩到 370px，顶部偏移先为 180px，再仅通过 scroll 改为 240px，最后关闭键盘恢复；顶部、输入区及消息阅读区始终可见，原本贴底时继续贴底。
2. 历史阅读位置保留；回到最新仅滚动消息区，文档 scrollY 为 0。
3. 长草稿下仍有消息阅读空间；触屏发送后草稿清空，输入焦点保持。

TypeScript 类型检查、Vite 生产构建及 `git diff --check` 通过。

## 验证边界

上述测试覆盖视口事件与布局回归，不等同于 iPhone Safari 原生键盘验收。真机仍需复测点击输入、中文候选词、发送、关闭键盘及上下翻阅消息；本次未声称已完成真机验收。

# 任务 11：文本 PDF 与 DOCX 阅读

日期：2026-10-15。独立分支 `codex/ticket-11-documents`，编码前合入基线 `26d33c4`。测试只使用 15433 的随机数据库、临时文件及受控外部 HTTP；没有读取主配置或调用真实云端模型。

## 行为与位置

同一会话上传入口新增 `.pdf` 和 `.docx`，保持单次上传及消息绑定最多五个、每份实际字节不超过 20,000,000。异步登记、处理状态、归属、重试、预算及可信出处沿用任务 05/10 接缝，不创建第二套执行器。同步 `/messages` 与流式 `/runs` 均使用提取材料，所有回答调用继续记录用量并遵守预算。

PDF 使用锁定的 `pypdf==6.20.1`，在提取前读取真实页树并执行最多 200 页。引用使用物理页序 `第 N 页`；长页分片另带页内字符范围。199 和 200 页文件的最后一页均经实际问答定位；201 页失败且不调用回答模型。加密 PDF 明确要求未加密副本。扫描、空白、损坏及伪造 PDF 不会显示为成功读取；混合文件只记录可提取文字的页，并列出无文字页或提取失败页，不做 OCR。

DOCX 使用锁定的 `python-docx==1.2.0`，按正文顺序提取普通段落和表格，空段落仍计入位置。例如 `正文段落 2`、`表格 1，第 1 行，第 2 列，段落 1`；不伪造 Word 页码。嵌套表格保留层级位置，合并单元格不重复采集。修订、文本框、页眉页脚、脚注尾注及批注有明确提取缺口提示。空 Word、损坏 ZIP、普通 ZIP 改名、DOC/DOCM 不被当成可读 DOCX。

上传卡片显示“文字可用”或“文字可用（部分）”、可读页/段落数量、缺口及局限。所有文档都说明复杂图表、内嵌图片和特殊排版没有被理解，需要单独上传相关图像。`coverage=complete` 只表示当前文字提取范围没有已识别缺口，不等于理解整份文档全部图像或完成全文总结。当前资料问答仍检索最多十二个相关片段；任务 13 负责全文处理。

## 数据与模块合同

`012_document_parse_info.sql` 为 `attachments` 增加 `parse_info JSONB NOT NULL DEFAULT '{}'`，原文件继续位于 `APP_DATA_DIR/attachments/<UUID>`。元信息随公开附件列表及本轮模型资料返回，重启后保留。它包含 `format`、`total_units`、`readable_units`、`coverage`、`missing_units`、`limitations`；每份来源仍使用持久 `A{citation_id}`，原有引用白名单不变。

`general_agent.documents.parse_document(path, extension) -> ParsedDocument` 返回 Pydantic 结果：`chunks: list[tuple[location, text]]`（最多 1500 字符/块）、`info: DocumentInfo`、`error: str | None`。`AttachmentService.process` 从登记的 filename 识别格式，对 PDF/DOCX 调此入口；成功后事务保存片段及范围，失败持久记录原因且不能绑定给消息。该入口不发模型请求、不保存记忆、不访问数据库；图片解析由任务 12 的独立分支处理。

解析使用子进程，环境只传模块路径、系统 PATH 和 locale，不传应用服务配置。父进程限制 20 秒墙钟时间并监测 512 MiB RSS，子进程限制 CPU 软/硬限额 10/12 秒、输出文件 16,000,000 字节；Linux 另设置数据段 512 MiB / 地址空间 1 GiB 限额，macOS 使用 RSS 监测。异常退出和限额终止都返回明确失败，不将截断输出当成功；子进程退出或取消后回收。这里是资源约束，不是系统级网络沙箱。

解析前限制 DOCX 最多 2000 ZIP 条目、单项展开 10,000,000 字节、合计展开 50,000,000 字节，拒绝重复条目及 UTF-8/UTF-16 XML 的 DOCTYPE/ENTITY 声明。PDF 压缩流展开上限 10,000,000 字节；两类文档的提取文字总量上限 2,000,000 字符。超限提示拆分或简化。没有增加启动配置；锁定依赖随现有 `uv sync --locked` 安装，迁移随应用启动执行。

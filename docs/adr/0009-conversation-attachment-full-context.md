# 会话附件使用完整上下文

文字附件全文注入及不保留切片的决定已由 [ADR 0011](0011-conversation-document-tools.md) 替代。图片 file_id 协议继续有效；所有附件补充应用层 30 天 TTL。

## 背景

现行附件链路同时维护可检索片段、文件引用、全文总结和总结进度。用户于 2026-10-19 决定先采用最小可行方案：附件上传成功后直接成为当前会话后续回答的资料，不再保留总结、分段检索、引用核验或附件专用任务状态。

## 决策

- 附件仍归属于原会话，其他会话不能读取。
- TXT、Markdown、文本型 PDF 和 DOCX 在上传时提取完整可读文字，保存到 `attachments.content`；图片保存原文件和校验后的图片元信息。
- 每次回答读取当前会话全部 `ready` 附件：文字以完整 JSON 资料消息发送，图片于 2026-10-20 按下述 Files API 决策改为持久化 `file_id` 引用。
- 不再创建 `attachment_chunks`、`message_attachments`、`document_jobs` 或 `document_steps`，也不再返回文件引用或总结进度。
- 上传数量、单文件大小和 PDF 页数限制继续由后端执行。解析失败的文件明确显示失败，不进入模型上下文。
- 删除附件仍会删除原文件、完整派生文字和搜索来源关联；删除会话仍会清理其附件和消息。
- 为在聊天记录中说明附件随哪条用户消息发送，`attachments.user_message_id` 记录首次发送位置；该关联只用于历史展示，回答仍读取当前会话全部 `ready` 附件，不按消息筛选。

## 结果

实现和交互显著简化，用户不需要选择文件后才能提问，模型也能看到完整的可提取文字。代价是每次回答都会发送会话中全部可用附件，长文档可能超过模型上下文或产生较高用量；当前版本不自动分页、摘要或裁剪，超出能力时由模型服务返回真实失败，之后再加预算或工具化读取。

本决策取代 ADR 0006 和 ADR 0007 中关于附件总结、分段处理及文件引用的部分；附件不生成长期记忆的边界不变。


## 2026-10-20：图片改用 DeepSeek Files API

用户要求图片上传后通过 `file_id` 发送给 LLM，避免每次回答重复发送原图。经核对官方上传协议，TTL 最长为 30 天，用户明确选择 30 天。图片校验后由后端复用当前 LLM 地址及密钥，以 `POST /files`、`purpose=user_data`、`expires_after[anchor]=created_at`、`expires_after[seconds]=2592000` 上传；只有取得有效文件身份和过期时间才标记可用。

本机原文件继续保留用于下载；业务库保存远端文件身份和到期时间。后续完整会话资料使用扁平 `{"type":"file","file_id":"…"}` 内容块，重启不重复上传。已有旧图片在首次使用时补上传。远端文件过期后明确提示用户重新上传，不自动续期；更换服务地址后也要求重新上传，避免向新服务引用旧身份。同一服务内密钥轮换可继续按供应商账户权限引用文件，实际权限由服务端校验。

删除附件或会话先停用来源，再串行清理远端文件和本机原文件；远端删除失败保留删除身份及重试入口。图片上传与删除共用附件锁，防止上传的迟到结果逃过远端清理。文字附件、会话归属及不提取附件长期记忆的边界保持不变。

协议依据见 [Files API](https://api-docs.deepseek.com/guides/files_api/) 和 [Vision](https://api-docs.deepseek.com/guides/vision/)，核对记录见 [DeepSeek Files 研究笔记](../research-deepseek-files.md)。

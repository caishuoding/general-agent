# 阅读与检索共用会话文档切片

2026-10-22

适用范围为会话附件的阅读和检索共用切片。独立知识库使用自己的 `knowledge_chunks`，与附件复用算法但不共用切片表，见 [ADR 0015](0015-independent-knowledge-bases.md)。

## 背景

ADR 0011 将解析原文与检索切片分别持久化，阅读依赖原文表，检索依赖切片表并关联原文位置。用户确认阅读也应复用检索切片：按页定位、完整返回、原文顺序；跨页带出的额外文字及重叠可以保留，不需要精确裁页。

## 决定

本决定替代 ADR 0011 的独立原文存储和原文范围读取约定，其余权限、工具调用次数、上下文预算和附件生命周期合同继续有效。

- 上传仍需解析格式和定位页码，但解析段落仅作为切片生成的临时输入；唯一持久正文保存在 `document_chunks`。
- 切片自行保存起止页、起止段落和结构；检索和阅读都直接读取切片，不再关联 `document_units`。
- `read_document` 的初始参数仍为文档 ID、页码或段落范围。选取所有范围相交的切片，按文档内序号升序返回，不做相关性排序，不受 `DOCUMENT_SEARCH_RESULTS` 限制。
- 返回完整切片正文，保留跨页文字、重叠和重复表头，不做原文还原，不额外提示范围外文字。阅读结果只需切片编号和正文，搜索结果继续提供位置和结构。
- 阅读单次仍最多 10,000 Token，并受当前上下文预算限制；整片分页，`next_cursor` 仅定位下一片。连一整片都放不下时返回预算不足，不生成原地循环的游标。
- 删除原文表、重复全文列，以及切片指向原文的引用和字符偏移字段；删除对应的持久化、关联查询、重复解析输出与字符续读代码。

## 迁移与后果

迁移 046 先从旧原文表补齐已有切片的元数据，再删除冗余结构。保留既有切片身份、正文、Token 信息、结构性包装、关键词、向量和附件有效期；此迁移不要求重新解析附件或重新计算向量。未完成索引的旧附件仍沿用从上传原件恢复的既有机制。

按页读取可能包含相邻页文字；连续阅读可能出现重叠文字。这是复用完整检索切片所接受的行为。单片大于当前阅读预算时需要释放上下文后重试。

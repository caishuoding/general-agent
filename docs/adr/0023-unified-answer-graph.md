# 唯一 Agent 图与运行状态

Status: accepted

2026-11-02：按用户确认的完整重构要求，主智能体、子智能体、同步入口和流式入口统一使用 `build_agent_graph()`。本决策替代 ADR 0007/0012/0017 的外层会话图与内层工具图结构，以及 ADR 0021 按主 Run 分离检查点的部分。代码不保留旧图、第二套 State、旧执行器或兼容包装。

图固定包含五个节点：`prepare_context → prepare_model → call_model`；有工具调用时进入 `execute_tools → prepare_model`，否则进入 `finalize`。结束前仍有子任务或后台命令时，`finalize` 返回 `prepare_model`，完成后结束。主从差别只由 `AgentContext.role` 和注册工具权限表达。

`AgentState` 只保存恢复、路由与人工检查需要的可变数据：工作消息、Run 身份、模型轮次、已加载 Skill、可访问附件与知识库、待完成子任务、工具失败次数、文档调用次数、完成标志与错误。最终正文和工具调用直接来自消息，不再另存回答或布尔工具使用标志。来源、生成文件和副作用事实保存在业务表，避免重复状态。

冻结的 `AgentContext` 保存角色、账号、会话、用户消息、助手消息、Run 身份、配置、外部操作和传输回调。`AgentRunner` 负责构造上下文、创建和恢复唯一图；`chat` 目录只管理消息入口、后台线程和流式投影；`skills` 目录负责路径访问与隔离执行。系统提示、客户端、连接、工具定义和调度器不进入 State。

所有 Skill 工具从一开始就注册；加载仅更新顶层 `loaded_skills` 的名称、版本、根目录和入口。读取 Skill 文件要求名称已经加载，工作区文件读写、导入、命令、发布和预览按账号、会话、Run 和允许目录校验，无需先加载 Skill。普通工具与 Skill 工具共用失败额度及适用的幂等缓存。

主回答使用会话 ID 作为稳定 LangGraph thread，子任务使用独立 Run thread。新回答保留对话和摘要，移除旧工具协议轨迹；继续执行保留原工作消息并从待执行节点恢复。State 的 `run_id` 用于区分当前检查点所属执行，避免在首次输入提交前中断时误接上一轮。

检查点版本升级通过迁移 069 一次性清除旧图的派生检查点，并终结旧未完成执行。保留原消息和业务事实；不迁移旧 State，不在正常启动时反复清除。最终提交、停止、来源撤销和副作用依赖业务归属校验；恢复重放工具时仍须保证幂等。字段说明见 [Agent State](../agent-state.md)。

# 知识库独立存储，复用文档处理与召回算法

2026-10-22：用户需要在独立入口长期管理资料、查看解析切片进度，并在会话中选择知识库供智能体按需检索。会话附件有会话归属和 30 天有效期，知识库则跨会话使用；因此两者使用独立的数据表和文件生命周期，同时复用已验证的解析、图片描述、切片及混合召回算法，避免复制两套策略。

## 决定

- 附件继续使用 `attachments`、`document_chunks` 和 `document_images`。
- 知识库使用 `knowledge_bases`、`knowledge_documents`、`knowledge_chunks` 和 `knowledge_document_images`；会话选择关系单独保存。知识库文档不创建附件记录，不向 `document_chunks` 或 `document_images` 写入数据，也不使用“来源类型”字段将两类切片混存一表。
- 公共处理层复用 Word／PDF／TXT／Markdown 解析、`ChunkPolicy`、图片描述及图片绑定；公共检索层复用 BM25、向量余弦召回、等权 RRF 和智谱重排。数据访问分别实现，调用公共算法前就限定账号和知识库／会话范围。
- 知识库上传后台完成解析、图片描述、切片和向量索引，并持久化各阶段的真实进度。与 ADR 0013 的附件向量按需生成不同，知识库在入库时构建向量，避免首次提问才承担整份文档的嵌入等待。
- 对话提供 `search_knowledge(query)`。模型只决定是否需要检索，不接收知识库或文件 ID；服务端读取 `conversation_knowledge_bases`，在候选召回前固定该会话绑定的一个或多个知识库，不默认检索账号下的全部知识库。
- 召回先按 BM25、向量、RRF 和可选重排选出相关切片，再把最终入选切片按知识库、文档及原文序号重排后交给模型，兼顾相关性筛选和原文阅读顺序。
- 每个召回切片获得本次回答唯一的 `[K编号]`。模型依据切片回答时引用实际编号；收尾节点只保留工具实际返回且正文真正引用的来源，并持久化知识库、文档、切片、位置、摘录及可选图片身份到消息。
- `[K编号]` 只表示引用依据。模型若判断直接展示召回图片或表格更便于用户理解，可另起一段输出 `[[MEDIA:K编号]]`；服务端只接受本次真实返回且类型为图片或表格的编号。前端把媒体块放到对应段落后，文末仍列出全部实际引用来源。
- 文末来源链接按格式定位：PDF 使用 `#page` 打开对应页；Word 显示大致页、段落或表格位置并打开原文档；文本来源定位到段落。所有实际引用均按首次出现顺序去重。
- 用户界面中的知识引用显示为紧凑右上标 `[1]`，不显示内部 `K编号` 或长文件名。文末参考来源只列文件名和位置，不重复切片摘录；图片和表格只在模型要求的位置行内展示。
- 行内图片保持正文宽度并取消独立卡片外框，图片下不重复显示说明或来源标签。文末普通文字来源可以显示单行摘录并使用省略号；图片、表格来源仍只显示文件和位置。
- 引用的图片切片通过受保护的知识库图片接口内联展示；客户端不能凭任意 ID 读取其他账号或已删除资料。
- 来源保存 `text`、`table` 或 `image` 类型。图片类型只展示原图，不把视觉模型生成的描述当作对用户展示的引用正文；表格类型使用 Markdown 表格组件可视化，普通正文才展示文字摘录。
- 图片描述使用已接入的 `deepseek-flash` 视觉链路，直接返回纯文字，原文成为切片正文；不要求 JSON 或拆分字段。解析时把“图 03 …”一类图注绑定到同段或最近相邻图片，随后视觉模型同时接收图注和原图。已绑定图注从普通文字单位中移除，不能另生成正文切片；位置、章节、图注与知识库自己的图片身份保存在元数据，命中后把描述和原图一起交给回答模型。
- 知识库原件及派生内容长期保存，用户删除文档或知识库时清理；删除会话只移除选择关系。远端图片临时文件到期时从本机原图重传，不能把远端 TTL 当成知识库文档的有效期。

## 与既有决策的关系

2026-10-23：用户明确知识库范围属于会话绑定，不应交给模型选择。本节替代此前“向模型提供已选清单并由模型选择指定库”的工具合同；存储、账号隔离及独立切片表决策保持不变。

2026-10-23：用户要求召回切片按原文顺序进入上下文，并保留文字及图片引用来源。新增原文顺序重排、`[K编号]` 核验、消息级知识库来源持久化和受保护原图展示；模型不能凭回答正文伪造来源。

2026-10-23：浏览器正文中的知识库引用直接显示“文件名 · 原文位置”，来源详情默认展开；`[K编号]` 仅作为稳定锚点和内部核验标识保留。

2026-10-23：按引用类型调整来源卡片。图片引用隐藏描述并只显示原图；表格引用渲染为真正的表格；普通文字引用保留摘录。

2026-10-23：用户要求图注属于图片处理单元。图注从普通正文切片中排除，并与图片一起发送给视觉模型生成描述，避免描述和说明文字被拆散到不同切片。

2026-10-23：用户确认引用与媒体展示是两个独立协议。普通 `[K编号]` 声明知识依据；`[[MEDIA:K编号]]` 由模型自主选择图片或表格插入位置。媒体自动计入引用来源，文末只保留定位链接，不重复展示媒体。

2026-10-23：用户要求正文引用简化为右上标编号，来源列表仅保留文件和位置。同步加强 Markdown 标题、段落、列表和表格的前后空行及视觉间距，避免长回答章节拥挤。

2026-10-23：用户要求行内图片融入正文、移除图片下方说明；文字来源允许一行省略摘要。图片和表格来源不重复内容。

[ADR 0014](0014-shared-document-chunks.md) 的“共用切片”仅指附件阅读与附件检索共用 `document_chunks`，不表示附件与知识库共用切片表。附件现有工具和生命周期继续有效；本次不顺带重写聊天附件的完整处理流程。知识库内容同样不进入 Mem0 自动记忆。

独立表会增加数据访问与清理代码，但避免附件到期、删除会话或附件索引重建误操作知识库内容。具体处理阶段、降级和验收合同见[知识库规格](../../.scratch/knowledge-base/spec.md)。

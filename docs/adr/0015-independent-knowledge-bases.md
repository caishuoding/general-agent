# 知识库独立存储，复用文档处理与召回算法

2026-10-22：用户需要在独立入口长期管理资料、查看解析切片进度，并在会话中选择知识库供智能体按需检索。会话附件有会话归属和 30 天有效期，知识库则跨会话使用；因此两者使用独立的数据表和文件生命周期，同时复用已验证的解析、图片描述、切片及混合召回算法，避免复制两套策略。

## 决定

- 附件继续使用 `attachments`、`document_chunks` 和 `document_images`。
- 知识库使用 `knowledge_bases`、`knowledge_documents`、`knowledge_chunks` 和 `knowledge_document_images`；会话选择关系单独保存。知识库文档不创建附件记录，不向 `document_chunks` 或 `document_images` 写入数据，也不使用“来源类型”字段将两类切片混存一表。
- 公共处理层复用 Word／PDF／TXT／Markdown 解析、`ChunkPolicy`、图片描述及图片绑定；公共检索层复用 BM25、向量余弦召回、等权 RRF 和智谱重排。数据访问分别实现，调用公共算法前就限定账号和知识库／会话范围。
- 知识库上传后台完成解析、图片描述、切片和向量索引，并持久化各阶段的真实进度。与 ADR 0013 的附件向量按需生成不同，知识库在入库时构建向量，避免首次提问才承担整份文档的嵌入等待。
- 对话提供 `search_knowledge(knowledge_base_id, query)`。模型从当前会话已选择的知识库清单获得 ID 并自主决定是否调用；服务端检查该知识库属于当前账号且已被当前会话选择，不接收文件 ID，也不默认检索账号下的全部知识库。
- 图片描述使用已接入的 `deepseek-flash` 视觉链路，直接返回纯文字，原文成为切片正文；不要求 JSON 或拆分字段。位置、章节与知识库自己的图片身份保存在元数据，命中后把描述和原图一起交给回答模型。
- 知识库原件及派生内容长期保存，用户删除文档或知识库时清理；删除会话只移除选择关系。远端图片临时文件到期时从本机原图重传，不能把远端 TTL 当成知识库文档的有效期。

## 与既有决策的关系

[ADR 0014](0014-shared-document-chunks.md) 的“共用切片”仅指附件阅读与附件检索共用 `document_chunks`，不表示附件与知识库共用切片表。附件现有工具和生命周期继续有效；本次不顺带重写聊天附件的完整处理流程。知识库内容同样不进入 Mem0 自动记忆。

独立表会增加数据访问与清理代码，但避免附件到期、删除会话或附件索引重建误操作知识库内容。具体处理阶段、降级和验收合同见[知识库规格](../../.scratch/knowledge-base/spec.md)。

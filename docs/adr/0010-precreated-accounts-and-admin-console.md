# 预创建多账号、登录会话与管理员后台

Status: accepted (2026-10-19)

## 背景

项目此前只面向本机单用户运行，没有账号、登录或数据归属。用户现在要求增加登录模块，不开放自助注册；账号由管理员在后台预先创建。应用未来部署在云服务器并通过公网 IP 访问，当前没有域名，个人项目后续可能扩展为企业版。

## 决策

- 账号由管理员预创建，系统不提供注册入口。角色只有管理员和普通用户；管理员只使用独立管理端，普通用户只使用用户聊天端。
- 会话、消息、附件、长期记忆、搜索记录和调用用量按账号隔离。管理员可以在独立管理端只读查看所有账号的上述内容并下载附件，但不能代发消息、修改或删除用户内容；管理员查看他人内容写入审计记录。
- 模型、嵌入和搜索配置是全局配置，仅管理员可以修改；普通用户不接触服务密钥。
- 登录使用用户名和密码。密码以 Argon2id 哈希保存；新账号由管理员设置临时密码，首次登录强制改密；用户之后可以自行改密。密码至少 10 位并拒绝常见弱口令，不做定期过期。
- 登录状态使用服务端保存的不透明会话，浏览器只持有 `HttpOnly + Secure + SameSite=Lax` Cookie，有效期 7 天。退出、改密、重置密码或停用账号时吊销该账号的旧会话。
- 生产环境预置初始管理员 `admin / 123456`，首次登录必须改密；改密完成前只允许服务器本机或 SSH 隧道登录，不接受公网登录。开发和测试环境使用同一测试账号。
- 账号只允许停用，不物理删除；停用后不能登录，但数据保留。管理员可以创建普通用户和其他管理员，系统阻止停用或降级最后一个有效管理员。
- 公网部署使用 Docker 运行应用、PostgreSQL 和 Mem0；Nginx 监听 `443` 并反向代理到 `127.0.0.1:8000`。没有域名时使用包含 IP SAN 的自签名证书，不直接暴露应用、数据库或 Mem0 端口。
- 升级时先备份现有 PostgreSQL 与附件，再清空全部业务数据，保留模型、嵌入和搜索配置。迁移后只有新账号体系中的数据。
- 本期明确不做登录失败次数限制或账号锁定。该风险由用户接受；实现仍使用强密码哈希和统一的登录错误提示。

## 结果

现有全局会话模型必须迁移为账号归属模型，所有业务接口都要经过身份认证和授权，Mem0 也要按账号使用独立用户标识。管理员获得跨账号只读能力后，审计记录成为必要边界，避免“可查看”演变为不可追溯的隐式写权限。

预置弱初始密码与公网部署叠加存在被抢先登录的风险，因此通过“首次改密前拒绝公网登录”降低暴露窗口，但不提供登录限流意味着上线后仍可能遭受持续暴力尝试。自签名证书只解决传输加密，不提供浏览器信任；正式企业版仍应配置自有域名、正式证书和更完整的入口防护。

## 考虑过的替代方案

- 允许自助注册：与“不开放注册”要求冲突。
- 只做单账号门禁：无法支持后台新增用户和后续企业版。
- 使用 JWT 保存在浏览器：无法方便地集中吊销旧会话，改密和停用后的失效语义较弱。
- 每个用户配置自己的模型密钥：增加密钥管理和计费复杂度，本期不需要。
- 管理员可写他人内容：权限面过大，本期只保留只读查看和账号管理。

## 更新（2026-10-19）

用户进一步要求管理系统与聊天系统分开。管理端改用独立入口 `/admin`，拥有独立登录页和管理界面；用户端 `/` 不再显示管理员入口。登录接口通过 `expected_role` 区分用户端和管理端，管理员调用用户聊天接口会被拒绝，普通用户调用管理端接口也会被拒绝。管理员账号只承担账号管理、跨账号只读查看和系统配置，不再进入用户聊天界面。

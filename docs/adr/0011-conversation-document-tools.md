# 会话文档通过工具按需读取

2026-10-20：文字附件不论大小均不自动加入模型上下文，替代 ADR 0009 的全文注入决定。每轮重新提供文档 ID、文件名和页数（非分页文件为段落数）的清单，不提供状态或解析缺口。正文、切片及索引只属于原会话，不进入长期记忆；图片沿用 DeepSeek file_id 链路。

PDF 使用原有物理页；Word 保存原文件并由后台自动排版为固定 PDF 副本，后续页码以副本为准。解析原文保留页、段落及段内位置，检索切片保存到原文的映射。TXT、Markdown 使用段落位置。全部文字文件均切片；切片大小和返回数量是独立策略，不按检索结果 Token 数裁剪。

只暴露 search_documents 与 read_document 两个工具，由模型自主决定是否、何时以及以何种顺序调用，不增加任务分类、前置检索或总结流程。前者返回固定数量的完整切片；后者从解析原文按范围读取，单次最多 min(10,000 Token, 当前可用上下文预算)，超限返回部分原文及精确续读位置。计数优先使用对应模型官方 Tokenizer／计数接口，没有对应实现才按字符保守估算。每次回答中两个工具分别最多执行五次，正常、失败、重试及续读均计入，后端执行限制。

所有附件从上传登记成功开始保留 30 天，不滑动续期；到期先禁止访问，再重试清理原文件、分页副本、原文、切片及索引，图片同时清理远端身份。已生成的聊天正文保留。主动删除沿用现有来源撤回和清理合同，迟到处理结果不得恢复来源。工具正文可随上下文压缩移出，持久内容及每轮清单仍支持重新读取。

## 实现边界

当前代码未实现滑动窗口／摘要压缩，也没有现成预算接口；本次不另建压缩机制。原文读取在执行点根据实际消息、工具定义、已返回工具结果及模型窗口／输出预留计算剩余预算，并预留包装开销。窗口与输出预留作为模型配置保存，可供后续压缩机制直接接入。

初版保留当前 1,500 字符分片作为可配置默认值，默认返回五片；采用支持中英文的关键词倒排索引检索，不新增外部嵌入服务依赖。Word 分页使用 LibreOffice，部署必须安装对应运行时和中文字体；缺少运行时或转换失败时明确处理失败，不能伪造页码。原有文档在启动时从原文件重建知识库，仍遵守原上传时间 TTL。


2026-10-21 修订：将初版固定字符截断改为自然段→句子→分句→空白→字符的递归切分，保留 1,500 字符上限并将 overlap 计入上限，默认重叠目标 200 字符。重叠优先保留完整句子，允许单句超出目标；若妨碍容纳新句，则缩减重叠，确保每片推进。短段按序合并，显式 Markdown 标题及“第…章／节／篇／部”阻断切片和重叠，物理分页不阻断；原文仍无损保存，切片记录起止单元及偏移。自然段先采用空行规则，PDF 未引入版面模型；迁移 042 后启动重建旧版索引，不延长 TTL。此规则替代上文初版字符分片策略，继续使用关键词检索，不引入嵌入依赖。


## 2026-10-21：混合召回决定

上述仅关键词检索、不依赖外部嵌入服务的初版边界由 [ADR 0013](0013-attachment-hybrid-retrieval.md) 替代：采用 BM25 + 项目既有 embedding 配置，RRF 融合并由智谱 rerank 重排。其余工具和生命周期合同保持有效。


## 2026-10-22：Word 原生结构与重叠硬上限

切片默认上限改为 800 字符（包含重叠），overlap 默认 160 字符，所有配置均收敛到切片上限的 20% 以内；完整句子过长时不再扩大重叠。

Word 正文改为直接读取原件的原生段落、标题和带列名的表格行。此前转换后的 PDF 虽显示正确，文字层仍可能损坏数字，且已丢失原生结构；因此分页副本只提供位置：在临时 Word 副本中加入不可见书签，再读取 PDF 书签目的页，不从 PDF 抽取 Word 正文。跨页原生块按起止页定位，按页读取时返回与所选页面相交的完整块，并明确 end_page。Word 的表格、章节边界分别切片，表格行不重叠，完整行超过字符上限时才递归拆分。迁移 044 增加结构元数据，启动仅重建旧 Word 与配置已变化的 Word；PDF 解析路径及已有 PDF 数据保持原状，附件有效期不变。


## 2026-10-22：Token 软预算与 Markdown 表格

根据后续确认，以上八百字符规则由目标 800 Token、完整块容差最多 200 Token 替代，绝对上限 1000 Token。自然段、句子或表格行在容差内可完整保留；超长无边界正文仍按目标切分。正文 overlap 默认 160 Token，并收敛到目标的 20% 以内。

Word 表格转标准 Markdown，按行切分且各片重复表头，Markdown 语法和表头计入预算；数据行不重复。超长单行按单元格续片并保留空列定位。重复表头与续片包装单独存为 context_prefix／context_suffix，原文起止偏移只指向实际正文，不能将重复表头伪装成数据行原文。迁移 045 增加包装和 Token 计数元数据。

优先加载所选嵌入模型对应的官方 tokenizer.json，可显式覆盖计数模型；没有对应配置时沿用 UTF-8 字节数保守估算并标记 character_estimate。预算、分词器文件和模型指纹纳入 Word 重建条件，避免混用旧字符切片。PDF 解析路径不变，现有 PDF 不因 Word 升级而重建，附件有效期不变。


## 2026-10-22：文字型 PDF 表格解析

用户明确开始处理文字型 PDF，替代前文“PDF 不增加版面分析、不因 Word 升级而重建”的阶段边界。保留 pypdf 的文字提取与已有资源限制，增加 pdfplumber 的线条和文字坐标表格识别；有框表格优先，无框候选需稳定列间隙和短单元格，避免将普通单栏或双栏文章误判为表格。能力依据见 [pdfplumber 官方文档](https://github.com/jsvine/pdfplumber#extracting-tables)。

识别出的表格转标准 Markdown，表格首行作为列头，合并位置留空，单元格换行保留为 br；普通正文排除表格区域，按位置与表格交错输出，避免重复文本。复用已有表格分片和重复表头预算，不另建正文存储。复杂跨页表格逐页解析，不猜测拼接或恢复多级表头；单页表格识别异常保留可提取文字并标记缺口。

解析版本与切片配置纳入 PDF 启动升级条件；从原件重建切片并撤销旧向量，保持原到期时间，配置匹配时不重复重建。阅读与检索继续遵守 ADR 0014 的共用切片约定。


## 2026-10-22：文档内嵌图片描述与原图召回

Word 与 PDF 的常见栅格图片由格式解析器提取并保存稳定图片身份、页码或段落位置、章节、文件哈希和派生文件。视觉模型对每张图片返回结构化结果：`ocr_text`、`caption`、`description` 与 `uncertainties`。描述生成普通文本切片，切片通过 `image_id` 绑定原图；检索和阅读命中后，工具循环在下一轮模型请求中同时发送切片与对应文件身份，同一回答中每张图片只发送一次。

当前复用管理端 LLM 连接及 `deepseek-flash` 模型，不新增独立视觉服务。描述失败只影响该图片；只有既无文字、又没有任何成功图片描述时才使文档失败。图片、描述、切片及远端身份随附件 30 天生命周期清理。第一版限制为每份文档 50 张可由 Pillow 解码的栅格图片，不处理 SmartArt、EMF、WMF、矢量图表和 Markdown 外部图片引用。

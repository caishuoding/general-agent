# 在回答尝试内按需编排主智能体与子智能体

Status: accepted and implemented（2026-10-23）

对话任务由主智能体自主判断是否分工，通过 `spawn_agent`、`wait_agents`、`send_agent_message`、`cancel_agent` 管理一层子智能体。采用独立消息上下文的异步工具循环，避免同步等待创建结果而无法并行，也避免固定角色流水线强制拆分简单问题。主从默认使用同一模型配置；独立身份与上下文决定角色，无需部署多个模型。

保留 `prepare_context → agent → finalize`；主从复用通用 `AgentToolGraph`，子智能体不运行外层对话图，不触发自动长期记忆，不直接写用户回答。子智能体系统提示由后端固定规则和主智能体提供的任务级 `instructions` 组成，后者只细化任务方法，不能覆盖权限、来源和安全约束；提示只在模型请求时注入，不写入历史。工具按公共、主智能体专属和编排三组注册，子智能体自动复用安全公共工具，不继承记忆写入或编排工具。智能体身份和执行轮次分别持久化；补充任务新建执行轮次并延续同一子智能体上下文。模型决定分工与验收，后端保证权限、幂等、并发、预算和终态。

首版采用单应用进程的有界后台线程调度与业务 PostgreSQL 记录，不增加 Redis、独立 worker 或 LangGraph checkpointer。主流程等待不得占用子任务工作池。每次子任务执行使用独立操作身份并关联根回答，避免复用以用户消息或 operation 聚合的缓存与搜索状态。根回答取消、删除或结束时终止所有剩余子任务；已发请求仅继续记录真实用量，不能恢复业务结果。

按回答尝试汇总可信来源，且只有主智能体实际获得的工具结果或已交付子任务证据可以进入最终引用核验。模型生成的来源编号不能自行成为可信来源。已有账号、附件有效期和会话知识库绑定检查继续在实际读取和交付时执行。

本决策补充 [ADR 0012](0012-state-based-conversation-flow.md)，保留 State 传递与不可变运行参数的约定。新增执行记录为业务持久化，不是图检查点；重启终止未完成执行，重试创建新回答尝试。知识库访问与媒体协议继续遵守 [ADR 0015](0015-independent-knowledge-bases.md)。完整合同见[主从智能体规格](../../.scratch/multi-agent/spec.md)。

## 2026-10-26：结果信箱同时支持主动等待与被动交付

此前仅经带目标和游标的 wait_agents 交付子任务结果；该合同由规格中的零参数 wait_agents 与结果信箱替代。每次子执行终态原子登记事件，主模型请求前自动收信；主动等待在同一信箱上挂起主线程，数据库提交后用 Condition 和版本号唤醒，保留定期有效性检查。模型不承担轮询和游标管理。

交付批次与事件登记保存在业务 PostgreSQL，服务重启仍中断旧执行，不作为 LangGraph checkpoint。主从上下文和工具权限保持不变。候选回答结束前先接收未读结果、等待活动任务，根锁串行化完成事件与最终关闭；草稿用现有 SSE 快照替换而非追加。主动与被动交付同样重新验证权限并登记真实来源，资料撤销清理新记录。

取舍：保留 wait 让模型主动让出执行，同时由收尾检查阻止漏收。采用线程通知加数据库兜底，不新增消息中间件；真实模型调用仍计入原预算，等待本身不触发工具失败禁用。完整合同与本次验收在[规格](../../.scratch/multi-agent/spec.md#wait_agents)。

## 2026-10-26：子智能体会话只读展示

子智能体保留稳定身份、独立工作上下文和连续聊天外观，但不成为独立用户会话。用户在根回答下打开只读线程，查看主智能体派工、系统状态、各执行轮次结果和真实来源；输入、补充和取消仍由主智能体编排。这样既提供可审计的 Agent 工作视图，又避免新增用户可自由对话的会话边界和权限入口。

持久化继续使用业务 PostgreSQL 中的 agent、run 和来源记录，公开接口只投影可展示正文与状态，不返回模型工作消息或私有推理。新增记录随根回答清理，并遵守资料撤销。主对话仍只由主智能体形成最终回答，子智能体结果以带发送者身份的过程消息展示。完整合同见[规格](../../.scratch/multi-agent/spec.md#子智能体只读会话)。

## 2026-10-28：流式断线续写与共享联网额度

模型 Chat Completions 流在完整结束前断开时，应用保留已收到的公开正文并在同一执行内最多尝试三次。尚未产生正文时重发原请求；已有正文时把原上下文和 assistant 前缀重新发送，并附加临时续写指令。每次真实请求独立计量，恢复位置以内部标记显示在前端。该方案是应用层续写，不依赖也不声称模型 API 提供 Token 级推理恢复。

搜索与网页抓取由一个六次共享额度约束，真实外发请求（包括后端重试）逐次计数。额度耗尽后两个工具同时停止；不同智能体和新用户消息分别计算。停止条件是否已满足仍需真实任务研究，当前常因缺少信息充分性判断而接近额度上限。

## 2026-10-28：按搜索与网页抓取分别限制额度

用户明确要求搜索最多五次、抓取最多十次，替代上文的六次共享联网额度。主智能体和每个子智能体各自使用 `search_count` 与 `fetch_count` 计数，后端重试仍逐次计入对应类别；某一类别耗尽只禁用对应工具，另一类别继续使用自己的剩余额度。密钥或余额错误仍同时禁用两个联网工具。同一子智能体的补充执行沿用原额度，新回答尝试重新计数。

复用已有迁移建立的分类计数字段，无需修改历史迁移或重算历史调用；`web_count` 保留为历史共享额度记录，不再用于当前执行限制。

# 个人对话智能体需求

本项目为个人日常使用提供一个在本机运行的 Web 对话助手，支持附件理解、可管理的长期记忆，以及由模型工具按需调用的联网搜索。对话、附件和记忆保存在本机，允许按需使用用户选定的云端模型 API。

本文记录截至 2026 年 10 月 23 日的产品范围与技术栈，包含独立知识库及会话按需召回。实现边界见[实现方案](implementation-plan.md)及相关 ADR；术语定义见 [GLOSSARY.md](../GLOSSARY.md)。

## 使用方式与范围

- 当前版本支持管理员预先创建的多账号，不开放自助注册；账号主要供本人及授权使用者访问。
- 应用将从本机运行扩展到云服务器公网部署，登录和账号边界见 [ADR 0010](adr/0010-precreated-accounts-and-admin-console.md)。
- 第一版包含日常对话、写作辅助、附件理解、资料检索和长期记忆。
- 自助注册、手机原生应用和多设备同步留到后续。
- 发邮件、修改外部系统、后台自主执行任务留到后续。

## 登录与账号

- 由管理员在独立管理端创建账号，系统不提供注册入口；角色分为管理员和普通用户。
- 普通用户从 `/` 使用对话，只能访问自己的数据；管理员从 `/admin` 管理账号并只读查看所有账号的会话、附件、记忆、搜索记录和用量，不进入用户聊天界面。
- 所有账号首次登录必须修改临时密码；生产环境预置初始管理员 `admin / 123456`，首次改密前只允许本机或 SSH 隧道登录。
- 登录使用 7 天有效的服务端会话；退出、改密、重置密码或停用账号时吊销旧会话。
- 模型、嵌入和搜索配置为全局配置，仅管理员可修改。
- 公网部署使用 `服务器IP.sslip.io` 和 Caddy 自动 HTTPS，FastAPI 仍只监听本机回环地址。
- 当前不提供自助注册、邮箱找回、双因素认证、登录失败锁定、用户配额或组织/租户隔离。
- 具体范围、数据迁移和验收要求见[登录与后台账号管理规格](../.scratch/login/spec.md)。

## 界面与交互

- 左侧提供会话列表，主区域用于聊天和附件上传，另设设置页面；不提供长期记忆列表界面。
- 前端不展示长期记忆条目、来源、召回结果或自动处理状态；真实数据直接从 PostgreSQL 查看。
- 回答逐步显示，支持停止生成和失败后重试。
- 提供独立知识库管理页面和会话知识库选择入口；知识库处理进度可见，不改变长期记忆不在前端展示的边界。
- 回答下以折叠列表显示真实子任务标题和状态；展开时按需读取公开交付与可访问来源，不展示推理或子智能体流式正文。

## 核心验收场景

1. 用户通过对话完成日常问答和写作任务。
2. 用户在会话中上传资料后，可以要求总结、比较并继续追问；助手通过文档工具按需检索、读取完整切片，并依据实际内容和位置回答。
3. 用户开启新会话后，助手能够在相关对话中运用已保存的个人偏好和背景信息。
4. 用户明确更正某条记忆后，助手使用新值，不再把旧值作为当前事实；含义不明确的变化先由用户确认。
5. 用户删除某条记忆后，助手停止通过长期记忆使用它，也不会从同一旧来源自动重新生成它。
6. 用户在设置中配置模型 API 地址、密钥和模型名称后，能够使用已支持的文字、图片与工具调用能力。
7. 用户在知识库页面上传文档并查看真实阶段进度，在不同会话中选择该知识库后，由助手按需调用知识库召回工具回答。
8. 主智能体判断任务适合并行时创建子智能体；创建后继续自己的工作，需要时等待、追加或取消，并只汇总实际交付的结果与来源。

## 主从智能体

- 主智能体在一次回答尝试内自主决定是否分工，普通问题不增加固定规划请求或强制拆分。
- 主智能体可在一次回答内创建最多六个子智能体，每个子智能体最多执行三次；单回答、账号和应用均使用有界并发与截止时间。
- 子智能体使用独立消息上下文和操作身份，只开放时间、附件、会话绑定知识库及网页工具，不能创建下一层、操作长期记忆或直接写用户回答。
- 子智能体固定规则由后端维护；主智能体可通过 `instructions` 指定任务方法、重点和交付方式，但不能覆盖安全规则或扩大工具权限。
- 工具按公共、主智能体专属和编排分组；子智能体复用公共工具，不通过“主工具减编排工具”的方式自动继承记忆或编排权限。
- `spawn_agent` 立即返回身份；`wait_agents` 零参数等待当前回答任一子任务的新终态，结果也会在模型轮次间自动交付；`send_agent_message` 仅向已完成的子智能体追加且保留上下文；`cancel_agent` 幂等取消当前活动执行。
- 用户停止、回答完成或失败、资料范围变化、超时及应用重启都会关闭后续分派；已发出请求可继续记录真实用量，但不能恢复或写入业务结果。
- 子任务来源必须来自真实工具结果，并经等待工具交付后才可由主回答引用；完整任务与验收边界见[主从规格](../.scratch/multi-agent/spec.md)。

## 长期记忆

- 长期记忆使用用户指定的 Mem0 实现，由 Mem0 根据当前用户消息自动判断新增、更新和删除。
- 长期记忆用于跨会话保留和运用用户偏好、背景等事实，与附件内容分别定义。
- 用户明确要求记住某项信息时，由 Mem0 在当前消息的自动记忆处理中保存。
- Mem0 可以从当前用户消息中自动提取适合跨会话使用的稳定事实和偏好，不设候选记忆或逐条确认流程。
- 已保存的记忆用于相关对话时，不要求用户逐次确认。
- 用户直接从 PostgreSQL 查看 Mem0 实际保存的记忆及来源，不由前端复制展示。
- 用户明确要求更正或删除记忆时，由聊天中的记忆工具执行，旧值不再作为当前事实使用。

## 记忆与来源的删除

- 删除记忆条目时保留原聊天记录，停止通过长期记忆使用该条目，并阻止从同一旧来源自动重新生成它。
- 删除记忆不等于删除原文。原聊天仍可在原会话回看时被读到；移除原文需要另行删除来源。
- 删除会话时默认一并清理关联记忆，不在前端展示其正文或提供保留选择。附件没有关联记忆，只清理附件及其处理数据。
- 用户选择保留的关联记忆继续存在，并标明“原始来源已删除”。

## 附件

- 第一版支持单栏文字型 PDF、DOCX、TXT、Markdown、PNG 和 JPEG；整页扫描 PDF 使用 PP-StructureV3 版面 OCR，正文和表格复用现有切片，独立插图交给视觉模型描述；实施状态见扫描 PDF 规格。
- 每次上传最多 5 个附件，单文件最多 20 MB，单份 PDF 最多 200 页；超出时明确提示。这些是首版产品限制，不代表模型或服务商的接口上限。
- Excel、音视频、双栏 PDF 和 Word SmartArt／EMF／WMF 留到后续；单栏 PDF 中的矢量流程图按页面区域保留原图。
- 所有附件从上传登记成功开始保留 30 天，访问不续期；有效期内回到原会话可继续使用。到期后立即停用并自动重试清理，已经生成的聊天正文保留。
- 附件仅属于上传它的会话，新会话需要使用同一文件时必须重新上传。
- 第一版不提供跨会话选择已有附件的入口。不同会话中的上传互不影响，删除会话时一并删除该会话的附件。
- 附件内容不提取为长期记忆；附件只用于当前会话中的资料问答和处理。
- 需要长期保存的事实必须由用户在聊天消息中直接表达，再由聊天记忆流程处理。
- PDF 按单栏页面坐标恢复标题、自然段、完整图和结构化表格；DOCX 读取原生正文与内嵌栅格图片。PDF 完整图包含矢量线条、箭头和图内文字，图注按距离绑定后由当前视觉模型输出纯文字描述。表格保留跨行跨列、多级表头、表题和续表；无法可靠判断表头时使用原区域截图。Word SmartArt、EMF 和 WMF 暂不自动理解。
- 文字文档无论大小均不自动进入正文上下文，每轮只提供文档 ID、文件名和页数／段落数清单；图片继续通过 DeepSeek file_id 自动提供。
- 模型自主调用切片检索和原文读取两个工具，不设计任务分类或调用顺序。检索按切片大小和返回片数控制，不额外计算 Token；命中图片切片后，后端在下一轮请求中发送对应原图，同一回答每张图片只发送一次。
- 原文读取单次最多 10,000 Token 且不超过当前可用上下文，超限返回部分内容和精确续读位置。优先使用对应模型官方 Tokenizer，没有对应实现时才按字符估算。每个工具每轮最多调用五次，包含失败、重试及续读。
- PDF 使用固定物理页；Word 后台自动排版为固定分页副本，两者统一支持页码、页内段落和段内位置。Word 页码以该副本为准。
- 附件方案见 [ADR 0011](adr/0011-conversation-document-tools.md)。

## 独立知识库

- 提供独立知识库页面，可创建、重命名和删除知识库，在库内上传 PDF、DOCX、TXT 和 Markdown，查看文档、下载原件、删除和重试失败处理。
- 知识库归属于账号，长期保存至用户删除，可在同账号多个会话中选择使用；删除会话或附件到期不影响知识库文档。
- 展示上传与服务端处理两类进度。服务端阶段包括排队、解析、图片描述、切片和索引；已知总量按完成数展示，未知总量显示进行中。单张图片失败和向量失败明确显示，不能一直只显示“正在处理中”。
- 复用已有格式解析、图片描述、切片及 BM25 + 向量 + RRF + 智谱重排策略。图片继续使用 `deepseek-flash` 生成描述，命中图片切片后把描述和原图一起交给回答模型。
- 图片图注和原图属于同一处理单元；图注不能另进入普通正文切片，视觉模型应同时接收图注和原图。
- 知识库入库时生成向量；向量失败保留 BM25 可检索状态并支持重试，页面明确标记降级。
- 会话可以选择一个或多个自己的知识库。模型自主调用 `search_knowledge(query)`，只决定是否需要检索；后端从会话绑定读取固定范围，不向模型提供知识库 ID 或名称，不能默认搜索账号下的全部知识库。
- 最终召回的切片按原文顺序进入模型上下文。回答实际引用知识库时使用真实 `[K编号]`，并在回答下保留知识库、文档和原文位置；普通正文显示摘录，表格可视化展示，图片切片只显示受保护原图。
- 普通 `[K编号]` 表示知识依据；模型可另起一段使用 `[[MEDIA:K编号]]` 自主嵌入实际召回的图片或表格。媒体与引用分别处理，并统一进入文末来源。
- 用户界面把正文知识引用显示为小号右上标 `[1]`；参考来源只列出文件和位置，不展示切片正文。长回答必须保持清晰章节、段落、列表和表格间距。
- 行内图片应与正文自然融合，不添加图片下方说明；文字切片来源可以显示一行省略摘要，图片和表格来源不显示内容摘要。
- 附件继续使用 `document_chunks`／`document_images`；知识库使用独立的 `knowledge_chunks`／`knowledge_document_images`，只复用算法，不共用切片表或附件清理任务。
- 知识库文档不进入 Mem0；本次不将现有附件自动转成知识库，也不顺带重写聊天附件处理流程。
- 完整处理、权限、生命周期和验收合同见[知识库规格](../.scratch/knowledge-base/spec.md)和 [ADR 0015](adr/0015-independent-knowledge-bases.md)。

## 联网搜索

- 助手根据当前请求按需自主调用联网搜索工具，无需固定句式或明确联网口令，并给出可打开的来源链接。
- 联网搜索直接执行；即使查询包含附件或记忆中的个人信息，也不增加额外确认步骤。
- 搜索服务与模型服务分别配置，搜索使用独立的 API 密钥；当前接入 DeepSeek Search / Fetch，并保留更换服务的接口。
- 未配置搜索时，聊天、附件与记忆仍可使用，联网搜索提示需要先配置。

## 数据位置与模型调用

- 聊天、附件、长期记忆、账号、登录会话和管理员审计保存在本机业务存储中；公网部署时由同一业务 PostgreSQL 保存。
- 允许将对话与附件内容按需发送给用户选定的第三方模型 API，不要求完全本地推理。
- 用户可以在设置中填写 API 地址、密钥和模型名称；具体服务商和模型由用户配置。
- 模型接口首先支持 OpenAI 兼容的 Chat Completions。
- 第一版先验证一套服务，使用一个同时支持文字、图片和工具调用的模型，再逐步扩展兼容范围。
- 模型接入以真实调用结果为准，不因纯文字连接成功就默认图片或工具调用可用。

## 调用用量

- 记录本应用产生的云端请求状态以及服务商实际返回的 token 或 credits。
- 应用不维护服务单价、不估算费用、不设置消费额度，也不以本地记录代替服务商账单。
- 服务商没有返回用量时保留空值；停止和重试仍分别记录真实发生的调用。

## 技术栈与本机数据管理

- 界面采用 React 与 TypeScript，本机后端服务采用 Python FastAPI。
- 数据库采用用户明确指定的 PostgreSQL，保存聊天、记忆及相关业务记录；附件原文件保存在本机目录。
- PostgreSQL 通过 Docker Compose 在本机运行，使用持久化存储卷；前端和后端直接在本机运行。
- 长期记忆使用 Mem0；会话附件仍按自身归属独立处理，不因接入 Mem0 就自动成为长期记忆。
- 提供启动说明、数据位置说明和升级前备份/恢复脚本；自动备份调度留到后续。
- Mem0 的本机集成、PostgreSQL 历史存储适配及嵌入模型配置见[实现方案](implementation-plan.md)；自定义适配需在锁定 SDK 版本后验证。

# 个人对话智能体需求

本项目为个人日常使用提供一个在本机运行的 Web 对话助手，支持附件理解、可管理的长期记忆，以及用户明确要求触发的联网搜索。对话、附件和记忆保存在本机，允许按需使用用户选定的云端模型 API。

本文记录截至 2026 年 10 月 15 日已确认的产品范围与技术栈。Mem0 接入能力已核实并整理为[实现方案](implementation-plan.md)，具体适配及整体方案待最终核对，尚未进入实现阶段；术语定义见 [GLOSSARY.md](../GLOSSARY.md)。

## 使用方式与范围

- 第一版供本人使用，主要通过这台电脑的浏览器访问本机运行的应用。
- 第一版包含日常对话、写作辅助、附件理解、资料检索、长期记忆和按需触发的历史聊天检索。
- 多用户开放注册、手机访问和多设备同步留到后续。
- 发邮件、修改外部系统、后台自主执行任务留到后续。

## 界面与交互

- 左侧提供会话列表，主区域用于聊天和附件上传，另设记忆管理与设置页面。
- 候选记忆在聊天中以确认卡片呈现，用户可以决定是否保存。
- 回答逐步显示，支持停止生成和失败后重试。

## 核心验收场景

1. 用户通过对话完成日常问答和写作任务。
2. 用户上传资料后，可以要求总结、比较并继续追问；助手能指出资料回答依据的文件和具体内容位置。
3. 用户开启新会话后，助手能够在相关对话中运用已保存的个人偏好和背景信息。
4. 用户在新会话中明确要求查找以前讨论过的内容时，助手可以检索其他会话的历史消息。
5. 用户明确更正某条记忆后，助手使用新值，不再把旧值作为当前事实；含义不明确的变化先由用户确认。
6. 用户删除某条记忆后，助手停止通过长期记忆使用它，也不会从同一旧来源自动重新生成它。
7. 用户在设置中配置模型 API 地址、密钥和模型名称后，能够验证连接并使用已支持的文字、图片与工具调用能力。
8. 本应用估算费用达到用户设置的月度预算时，暂停新的云端请求，由用户决定是否继续。

## 长期记忆

- 长期记忆使用用户指定的 Mem0 实现；引入 Mem0 不改变下列确认、更新、查看与删除规则。
- 长期记忆用于跨会话保留和运用用户偏好、背景等事实，与历史聊天记录和附件内容分别定义。
- 用户明确要求记住某项信息时，直接保存为记忆条目。
- 助手自行发现可能值得记住的信息时，先生成候选记忆，由用户确认后保存。
- 已保存的记忆用于相关对话时，不要求用户逐次确认。
- 用户能够查看、修改和删除记忆条目，并查看每条记忆的来源。
- 用户明确要求更正记忆时直接更新，旧值不再作为当前事实使用。例如，“把我的常住地改成杭州”直接更新；“最近在杭州”只作为待确认的候选变更。

## 记忆与来源的删除

- 删除记忆条目时保留原聊天记录，停止通过长期记忆使用该条目，并阻止从同一旧来源自动重新生成它。
- 删除记忆不等于删除原文。原聊天仍可能在回看或用户主动检索历史时被读到；移除原文需要另行删除来源。
- 删除会话或附件前，列出由它产生的关联记忆，默认勾选一并删除，允许用户取消勾选并保留部分记忆。
- 用户选择保留的关联记忆继续存在，并标明“原始来源已删除”。

## 附件

- 第一版支持文本型 PDF、DOCX、TXT、Markdown、PNG 和 JPEG。
- 每条消息最多 5 个附件，单文件最多 20 MB，单份 PDF 最多 200 页；超出时明确提示。这些是首版产品限制，不代表模型或服务商的接口上限。
- 扫描版 PDF、Excel 和音视频留到后续。
- 附件随原会话保留，回到原会话后能够继续追问。
- 附件仅属于上传它的会话，新会话需要使用同一文件时必须重新上传。
- 第一版不提供跨会话选择已有附件的入口。不同会话中的上传互不影响，删除会话时一并删除该会话的附件。
- 只有用户明确要求时，才从附件提取个人记忆；先展示人物归属与具体候选内容，经用户确认后保存，避免将他人的资料归为用户本人的经历。
- 用户直接在聊天中明确要求记住某个事实，仍按明确指令直接保存，不要求重复确认。
- PDF 与 DOCX 以可提取的文字为主要依据；复杂图表或内嵌图片需要用户单独上传为图片，不承诺文字提取能够完整保留复杂排版的含义。
- 长文档显示处理状态，全文总结可以分段处理后汇总。

## 历史聊天检索

- 用户明确要求查找以前讨论过的内容时，助手可以检索其他会话的历史消息。
- 普通对话不会自动检索其他会话；已保存的相关长期记忆仍可自动使用。
- 历史聊天检索查找的是过去的消息，与使用长期记忆分开处理；它不授权读取其他会话的附件原文。

## 联网搜索

- 用户明确要求查询网络信息时，助手可以联网检索，并给出可打开的来源链接。
- 搜索需要使用附件或记忆中的个人信息时，先确认具体要发送的内容。
- 搜索服务与模型服务分别配置，搜索使用独立的 API 密钥；第一版接入 Tavily，并保留更换服务的接口。
- 未配置搜索时，聊天、附件与记忆仍可使用，联网搜索提示需要先配置。

## 数据位置与模型调用

- 聊天、附件和长期记忆保存在本机。
- 允许将对话与附件内容按需发送给用户选定的第三方模型 API，不要求完全本地推理。
- 用户可以在设置中填写 API 地址、密钥和模型名称；具体服务商和模型由用户配置。
- 模型接口首先支持 OpenAI 兼容的 Chat Completions。
- 第一版先验证一套服务，使用一个同时支持文字、图片和工具调用的模型，再逐步扩展兼容范围。
- 模型接入分别验证文字聊天、图片理解和工具调用，不因纯文字连接成功就默认其他能力可用。

## 用量与预算

- 统计本应用产生的云端请求用量，费用按服务商单价估算并明确标注为估算值，最终以服务商账单为准。
- 用户可以在设置中填写月度预算；估算费用达到额度时，暂停新的云端请求，提示用户决定是否继续。
- 此控制仅覆盖本应用的新请求，不代表服务商账户的精确扣费上限。
- 已启用预算控制但未配置单价，或服务商没有返回用量而无法估算费用时，显示“费用未知”，暂停后续云端请求，由用户选择补齐配置或允许本次继续；未知费用不计为零。
- 未设置月度预算时允许正常使用，只展示能够获取的用量与费用信息。

## 技术栈与本机数据管理

- 界面采用 React 与 TypeScript，本机后端服务采用 Python FastAPI。
- 数据库采用用户明确指定的 PostgreSQL，保存聊天、记忆及相关业务记录；附件原文件保存在本机目录。
- PostgreSQL 通过 Docker Compose 在本机运行，使用持久化存储卷；前端和后端直接在本机运行。
- 长期记忆使用 Mem0；会话附件和历史聊天仍按各自的访问范围独立处理，不因接入 Mem0 就自动成为长期记忆。
- 第一版提供启动说明和数据位置说明；自动备份与数据迁移工具留到后续。
- Mem0 的本机集成、PostgreSQL 历史存储适配、嵌入模型配置及预算控制见[实现方案](implementation-plan.md)；自定义适配需在锁定 SDK 版本后验证。

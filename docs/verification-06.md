# 任务 06：在新会话使用相关长期记忆

完成个人身份范围内的相关记忆召回及同步、流式入口接入，保留任务 05 的明确保存语义与任务 10 的附件归属和引用。未提前提供任务 07–09 的编辑、候选确认或删除接口。

## 用户行为与相关性边界

普通回答只将当前问题送入真实 Mem0 `Memory.search`，限定 `user_id=local-person`。向量相似度阈值为 0.72，先取得最多 50 个候选，再用应用业务状态过滤，最多提供五条有效事实。该阈值为工程默认值，不代表任何嵌入模型都已达到相同的相关性质量。

每条候选必须同时满足：Mem0 属于当前个人、应用 `memory_actions.status=complete`、正式标识一致，以及实际 Mem0 正文和应用批准事实一致。SDK 部分提交而业务失败的孤立向量不会成为批准事实。新会话可以使用相关正式记忆；未保存的旧消息、其他会话的附件和不相关记忆不会因召回进入回答。

召回材料作为独立资料块加入当前会话上下文，并明确其中指令不构成保存、历史读取或工具授权。没有自动写入或提取动作。明确保存的分支继续使用任务 05 的确定回执；同条输入保存后要求回答，也不额外发出一次自动召回。

消息公开响应增加 `memory_recall={status,count,detail}`，状态包括 pending、complete、failed、skipped、unavailable。页面展示已参考数量、等待或失败详情；没有记忆时隐藏 skipped 提示。嵌入未配置或验证失效时明确显示“长期记忆未读取”，召回失败时显示真实失败状态，并将同一限制告知回答模型；普通聊天仍可继续，回答调用仍接受预算检查。

## 预算、恢复与有效性

`ChatExecution` 在第一步预留真实的下一次调用：有正式记忆时为查询嵌入，没有正式记忆时为聊天。检索和回答通过同一 `CallGateway` 独立准入及计量，不把嵌入预留挪作聊天，也不同时预留两个尚未执行的请求。

`MemoryRecall.prepare` 与 `materialize` 分开处理有费用的检索和无外部调用的正式状态复核。新增 `memory_recalls` 表按回答操作保存状态、配置版本、命中条目的动作标识、Mem0 标识及版本；不保存查询或事实正文副本。检索完成而回答暂停时，刷新或应用重启后恢复同一尝试，从现有检查点重读正式状态，不再次发送查询嵌入。

发送回答前，命中条目必须仍为完整成功、版本相同，且 Mem0 正文仍匹配批准事实；失效条目从检查点移除。新增 `memory_actions.version` 默认 1，后续任务 07 修改事实应递增；任务 09 / 15 删除必须使正式状态和实体失效。续跑检查原来绑定的嵌入配置版本，不把记忆数量变化误判为配置变化。

召回失败保留本次失败状态，预算续跑不偷偷重新检索；用户重试创建新的回答尝试和实际调用记录。停止会立即冻结回答并取消尚未发出的后续调用，已发出的嵌入仍记录可以取得的用量；停止期间完成检索不会继续发送聊天请求。嵌入配置变化仍受既有批准范围及恢复版本检查约束。

## 持久化与配置

数据库迁移 `007_memory_recall.sql` 增加版本及召回检查点。Mem0 向量、历史、正式动作、来源和检查点均在现有 PostgreSQL 中，启动与数据目录保持当前部署方式。仍使用锁定的 Mem0 OSS 1.0.11 与任务 05 的 PostgreSQL 适配、显式操作上下文和预算嵌入器；没有 SQLite、托管 Mem0 或新云端模型客户端。

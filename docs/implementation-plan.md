# 个人对话智能体实现方案

第一版供个人本机使用：React 与 TypeScript 提供 Web 界面，FastAPI 执行对话与资料处理，PostgreSQL 17 通过 Docker Compose 持久化业务状态；长期记忆正文和向量由独立 Mem0 PostgreSQL/pgvector 保存。聊天、嵌入和智谱 Web Search 使用分别配置的服务连接。

产品范围见 [正式规格](../.scratch/general-agent/spec.md)，历史任务及验收记录见 [任务目录](../.scratch/general-agent/issues/)，执行与合并证据见 [集成记录](../.scratch/general-agent/integration.md)。术语采用 [GLOSSARY.md](../GLOSSARY.md)。本文件描述交付实现；各项真实服务验收是否通过，以验证记录中的实际证据为准。

## 模块与持久化

| 部分 | 实现职责 |
| --- | --- |
| 会话执行 | 持久化消息和回答尝试，协调流式生成、停止与失败重试 |
| 长期记忆 | Mem0 自动新增、更新和删除，支持管理、来源关系与跨会话召回 |
| Mem0 适配 | 通过官方 REST API 调用独立 Docker Mem0；记忆正文、向量和内部历史不进入业务数据库 |
| 会话资料 | 按会话保存独立附件，解析完整文字、读取图片，并在后续回答中直接提供当前会话全部可用资料 |
| 联网搜索 | 作为模型工具自主调用智谱 Web Search；查询直接执行，保留操作记录、真实用量和可核验来源 |
| 调用记录 | 保存稳定操作身份、调用状态及服务商返回的 token 或 credits |
| 来源删除 | 默认清理关联记忆，撤回来源许可并可恢复地清理原文件和派生记录；前端不展示记忆正文 |

Psycopg 直接访问 PostgreSQL，启动时按版本执行 SQL 迁移；没有引入 SQLAlchemy 或 Alembic。数据库版本迁移用于应用升级，没有新增面向用户的数据导入导出工具。应用以单个后端进程运行。

## Mem0 自动记忆规则

每条获准处理的用户消息由 Mem0 原生推理判断是否新增、更新或删除长期记忆。应用保存正式记忆及其来源和执行状态，不建立候选记忆表，也不提供逐条确认流程。助手回答和附件全文不会进入自动记忆输入。

更正使用稳定的记忆标识和版本。接受更正后旧值立即停止召回，只有向量及历史同步成功后才显示完成。部分提交和中断保留真实状态；重试核对已有结果，不把失败当作保存成功。

Mem0 的默认历史实现不满足本项目的 PostgreSQL 持久化范围。自定义适配集中在记忆模块，覆盖历史、最近消息、初始化、关闭和重置，并通过真实 SDK 契约检查；不修改机器上的已安装包，不以独立 SQLite 文件保存正式历史。导入 SDK 前关闭默认遥测，外部嵌入通过应用计量入口执行。

删除记忆先停止召回，再清正式向量、内部历史及相关操作缓存。防止旧来源自动恢复的标记不保存被删事实正文；原聊天仍可主动回看。删除会话时先预览真实关联记忆，默认一起删除；明确保留的事实继续可用并标注来源已删除。附件不产生记忆关系，删除附件只清理文件及其处理数据。

## 检索与资料边界

- 个人长期记忆采用 pgvector 相似度检索，只纳入完整成功、已批准、当前有效的条目，支持跨会话使用。
- 附件每次上传形成独立对象，始终按当前会话授权。TXT、Markdown、PDF 和 DOCX 把完整可提取文字放入回答上下文；图片使用实际图片内容发起视觉请求。当前不提供分段检索、文件引用或全文总结。
- 附件目前没有向量索引。更换嵌入服务、模型或维度只重建实际使用向量的正式记忆范围，不新建资料迁移工具。
- 重建不得混用不同空间的向量。已删除记忆不参加；来源已删但用户明确保留的有效事实仍参加。进度、失败和恢复必须与实际执行一致。

支持文本型 PDF、DOCX、TXT、Markdown、PNG 和 JPEG。后端执行每次上传最多五个文件、单文件最多 20 MB、PDF 最多 200 页的限制。PDF 保留物理页标记，DOCX 保留段落或表格位置，供模型理解原文结构，不再生成文件引用。扫描 OCR、复杂排版和文字文档内嵌图像理解不在本期范围，提取缺口会显示出来。

## 云端调用与用量

聊天、Mem0 自动提取与变更判断、记忆嵌入、召回、完整附件上下文、工具搜索和最终回答都经过统一调用网关。一次请求可能对应多次调用，每次调用单独保存状态以及服务商返回的 token 或 credits。保存配置只表示连接信息已保存，实际能力以真实调用结果为准。

联网搜索由模型根据当前请求自主调用并直接执行，无需固定句式或明确联网口令，不再等待用户编辑或批准查询；附件或记忆中的个人信息也可能随查询外发。停止会阻止尚未发送的后续调用；已经发送的请求仍可能由服务商计费，可取得的实际用量继续记录。应用不估算价格或费用，账单以服务商为准。

当前聊天传输仍使用 OpenAI 兼容 Chat Completions，搜索由应用执行 `search_web` 并把结果回传模型；没有接入供应商内置搜索。DeepSeek 独立 Search / Fetch API 与 Responses 内置搜索的支持范围及迁移边界见 [README](../README.md#deepseek-搜索能力与当前接入边界)，不能把模型名称变更等同于已经接入联网。

## 本机运行与数据位置

完整启动和配置步骤见 [README](../README.md)。`bash scripts/start.sh` 安装锁定依赖、构建前端、启动数据库并在 `127.0.0.1:8000` 运行应用；数据库默认仅绑定 `127.0.0.1:15432`。

PostgreSQL 的 `general-agent_postgres_data` 卷保存会话、消息、调用记录、记忆来源、搜索记录等业务状态；记忆正文、向量和内部历史只保存在独立 Mem0 数据库。附件原文件保存在 `APP_DATA_DIR/attachments/`，默认项目 `.local/attachments/`；模型、嵌入及搜索配置由后端以私有文件保存。配置读取接口不回传完整密钥，错误响应不直接暴露服务商正文。数据库卷和本机附件需要一起保留，测试配置不覆盖用户配置。

业务数据库使用固定摘要的官方 PostgreSQL 17 Alpine 镜像，不安装 pgvector；Mem0 使用自己的 PostgreSQL/pgvector 服务。升级保持同一持久化卷和 PostgreSQL 主版本，维护前备份；不使用删除卷的命令升级。

## 验证边界

主要测试通过公开应用接口验证用户可观察行为，使用真实 PostgreSQL 与真实 Mem0，外部模型、嵌入和搜索仅在 HTTP 边界使用受控响应。少量浏览器流程覆盖上传、来源删除、设置和搜索工具；Mem0 REST 适配补充契约测试。

任务 01 曾用已配置的 DeepSeek 完成一次真实非流式文字调用并记录用量。受控测试不证明真实流式、视觉、工具、嵌入或智谱搜索兼容；未执行的真实调用及质量和账单验证均保留待验状态。各任务验证文档保留实际时间线，不把阶段测试改写成不存在的整套或真实服务验收。

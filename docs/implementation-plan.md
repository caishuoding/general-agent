# 个人对话智能体实现方案

第一版供个人本机使用：React 与 TypeScript 提供 Web 界面，FastAPI 执行对话与资料处理，PostgreSQL 17 和 pgvector 0.8.7 通过 Docker Compose 持久化。聊天、嵌入和 Tavily 使用分别配置的服务连接。

产品范围见 [正式规格](../.scratch/general-agent/spec.md)，18 项任务及验收记录见 [任务目录](../.scratch/general-agent/issues/)，执行与合并证据见 [集成记录](../.scratch/general-agent/integration.md)。术语采用 [GLOSSARY.md](../GLOSSARY.md)。本文件描述交付实现；各项真实服务验收是否通过，以验证记录中的实际证据为准。

## 模块与持久化

| 部分 | 实现职责 |
| --- | --- |
| 会话执行 | 持久化消息和回答尝试，协调流式生成、停止、失败重试与预算恢复 |
| 长期记忆 | 明确保存、候选确认、人物归属、更正、删除、来源关系与跨会话召回 |
| Mem0 适配 | 锁定 OSS 1.0.11，使用真实 SDK、pgvector 和自定义 PostgreSQL 历史存储 |
| 会话资料 | 按会话保存独立附件，解析文字、读取图片、检索片段、全文分段总结并生成可核对出处 |
| 历史聊天 | 仅本轮明确要求时检索其他会话的消息，动态核验原消息并提供跳转 |
| 联网搜索 | 仅本轮明确要求时调用 Tavily；从记忆或附件生成的查询先展示具体内容并取得批准 |
| 调用与预算 | 统一准入、逐次批准、调用状态、实际用量与费用估算 |
| 来源删除 | 展示关联记忆与保留选择，撤回来源许可并可恢复地清理原文件和派生记录 |
| 索引重建 | 显式改变嵌入空间，记录进度并按预算重嵌入已批准的有效记忆 |

Psycopg 直接访问 PostgreSQL，启动时按版本执行 SQL 迁移；没有引入 SQLAlchemy 或 Alembic。数据库版本迁移用于应用升级，没有新增面向用户的数据导入导出工具。应用以单个后端进程运行。

## Mem0 与确认规则

明确要求保存的具体事实直接写入；自动发现的事实先作为候选保存在业务表。附件提取还需明确授权和人物归属确认。批准后的事实通过同一正式保存入口调用 Mem0 `add(..., infer=False)`；确认前不进入正式向量集合。助手回答、历史消息和附件全文不会自动升级为长期记忆。

更正使用稳定的记忆标识和版本。接受更正后旧值立即停止召回，只有向量及历史同步成功后才显示完成。部分提交、预算暂停和中断保留真实状态；重试核对已有结果，不把失败当作保存成功。

Mem0 的默认历史实现不满足本项目的 PostgreSQL 持久化范围。自定义适配集中在记忆模块，覆盖历史、最近消息、初始化、关闭和重置，并通过真实 SDK 契约检查；不修改机器上的已安装包，不以独立 SQLite 文件保存正式历史。导入 SDK 前关闭默认遥测，外部嵌入通过应用计量入口执行。

删除记忆先停止召回，再清正式向量、内部历史及相关候选和操作缓存。防止旧来源自动恢复的标记不保存被删事实正文；原聊天仍可主动回看。另行删除会话或附件时，先预览所有真实关联记忆，默认一起删除；明确保留的事实继续可用并标注来源已删除。

## 检索与资料边界

- 个人长期记忆采用 pgvector 相似度检索，只纳入完整成功、已批准、当前有效的条目，支持跨会话使用。
- 附件每次上传形成独立对象，始终按当前会话授权。文字问题使用本机词法检索，全文总结按段处理全部可提取文字再汇总；图片使用实际图片内容发起视觉请求。
- 历史聊天使用本机原文关键词检索，返回原会话和消息出处；不读取其他会话附件原文，不把检索结果自动保存为记忆。
- 附件和历史聊天目前没有向量索引。更换嵌入服务、模型或维度只重建实际使用向量的正式记忆范围，不新建资料迁移工具。
- 重建不得混用不同空间的向量。已删除记忆和未确认候选不参加；来源已删但用户明确保留的有效事实仍参加。进度、预算暂停、失败和恢复必须与实际执行一致。

支持文本型 PDF、DOCX、TXT、Markdown、PNG 和 JPEG。后端执行每条消息最多五个文件、单文件最多 20 MB、PDF 最多 200 页的限制。PDF 按物理页、DOCX 按段落或表格位置、纯文本按行等位置建立引用。扫描 OCR、复杂排版和文字文档内嵌图像理解不在本期范围，提取缺口会显示出来。

## 云端调用与费用

聊天、候选提取、记忆嵌入、召回、资料分段及最终回答、搜索和索引重建都经过统一调用网关。一次请求可能对应多次计量调用，每次发送前分别检查预算。保存配置不等于通过文字、视觉、工具或嵌入能力验证。

已启用预算但估算达到额度、缺少价格或已有用量未知时，暂停新的云端调用。一次批准只放行与原操作和配置绑定的下一次请求；外发查询批准与预算批准分别执行。停止阻止后续调用，已经发送的请求仍可能产生费用；可取得的实际用量继续记录。应用估算不替代服务商账单。

## 本机运行与数据位置

完整启动和配置步骤见 [README](../README.md)。`bash scripts/start.sh` 安装锁定依赖、构建前端、启动数据库并在 `127.0.0.1:8000` 运行应用；数据库默认仅绑定 `127.0.0.1:15432`。

PostgreSQL 的 `general-agent_postgres_data` 卷保存业务、向量、历史和任务状态。附件原文件保存在 `APP_DATA_DIR/attachments/`，默认项目 `.local/attachments/`；模型、嵌入及搜索配置由后端以私有文件保存。配置读取接口不回传完整密钥，错误响应不直接暴露服务商正文。数据库卷和本机附件需要一起保留，测试配置不覆盖用户配置。

pgvector 从固定版本和校验和源码构建到固定摘要的 PostgreSQL 17 Alpine 基础。升级保持同一持久化卷和 PostgreSQL 主版本，维护前备份；不使用删除卷的命令升级。

## 验证边界

主要测试通过公开应用接口验证用户可观察行为，使用真实 PostgreSQL 与真实 Mem0，外部模型、嵌入和搜索仅在 HTTP 边界使用受控响应。少量浏览器流程覆盖上传、确认卡片、来源预览、记忆管理、设置及重建；Mem0 自定义适配补充契约测试。

任务 01 曾用已配置的 DeepSeek 完成一次真实非流式文字调用并记录用量。受控测试不证明真实流式、视觉、工具、嵌入或 Tavily 兼容；未执行的真实调用及质量、价格和账单验证均保留待验状态。各任务验证文档保留实际时间线，不把阶段测试改写成不存在的整套或真实服务验收。

# 个人对话智能体实现方案

第一版供个人本机使用：React 与 TypeScript 提供 Web 界面，FastAPI 执行对话与资料处理，PostgreSQL 17 通过 Docker Compose 持久化业务状态；长期记忆正文和向量由独立 Mem0 PostgreSQL/pgvector 保存。聊天、嵌入和智谱 Web Search 使用分别配置的服务连接。

产品范围见 [正式规格](../.scratch/general-agent/spec.md)，历史任务及验收记录见 [任务目录](../.scratch/general-agent/issues/)，执行与合并证据见 [集成记录](../.scratch/general-agent/integration.md)。术语采用 [GLOSSARY.md](../GLOSSARY.md)。本文件描述交付实现；各项真实服务验收是否通过，以验证记录中的实际证据为准。

## 独立知识库

2026-10-22 确认方案，2026-10-23 接入独立存储、后台入库、对话工具和前端页面。完整合同与任务拆分见[知识库规格](../.scratch/knowledge-base/spec.md)，存储边界见 [ADR 0015](adr/0015-independent-knowledge-bases.md)。

- 新增账号所有的 `knowledge_bases`、`knowledge_documents`、`knowledge_chunks`、`knowledge_document_images` 及会话选择关系；文件使用独立知识库目录，长期保留至用户删除。
- 从附件能力中复用格式解析、`ChunkPolicy`、`deepseek-flash` 图片描述与绑定、BM25／向量／RRF／智谱重排。公共算法通过各自数据访问接口工作；附件仍使用原表，知识库不创建附件记录。
- 后台入库顺序为解析 → 图片描述 → 切片 → 向量与索引；阶段状态和计数持久化，前端展示真实进度并提供失败重试。知识库向量在入库时生成，失败时明确降级为 BM25。
- 会话保存知识库选择，每轮将已选知识库 ID／名称提供给模型。模型自主调用 `search_knowledge(knowledge_base_id, query)`，后端在召回前核验账号和选择范围；命中图片后同时提供描述和原图。
- 按存储与生命周期、入库与进度、召回与对话工具、页面与会话选择四项任务实施。数据库迁移不改动现有附件内容，本期不重写附件处理流程。
- 迁移 049 创建独立业务表，原件、分页副本与派生图片位于 `APP_DATA_DIR/knowledge/`。任务随应用恢复；图片最多三路并发，每张完成后保存进度。失败的远端／本机清理保留对象和重试入口。

## 模块与持久化

| 部分 | 实现职责 |
| --- | --- |
| 会话执行 | 持久化消息和回答尝试，协调流式生成、停止与失败重试 |
| 长期记忆 | Mem0 自动新增、更新和删除，支持管理、来源关系与跨会话召回 |
| Mem0 适配 | 通过官方 REST API 调用独立 Docker Mem0；记忆正文、向量和内部历史不进入业务数据库 |
| 会话资料 | 按会话保存 30 天附件，文档只提供清单与两个按需工具；图片沿用 DeepSeek file_id |
| 联网搜索 | 作为模型工具自主调用智谱 Web Search；查询直接执行，保留操作记录、真实用量和可核验来源 |
| 调用记录 | 保存稳定操作身份、调用状态及服务商返回的 token 或 credits |
| 来源删除 | 默认清理关联记忆，撤回来源许可并可恢复地清理原文件和派生记录；前端不展示记忆正文 |

Psycopg 直接访问 PostgreSQL，启动时按版本执行 SQL 迁移；没有引入 SQLAlchemy 或 Alembic。数据库版本迁移用于应用升级，没有新增面向用户的数据导入导出工具。应用以单个后端进程运行。

## 对话图 State 数据流

外层流程为 prepare_context → agent → finalize。节点通过返回字段更新共享 State，不修改 runtime.context；消息字段是完整快照，按覆盖语义更新，不重复追加历史。模型工具循环的完整消息最终返回外层 State。

| 节点 | 读取 State | 返回 State 更新 |
| --- | --- | --- |
| prepare_context | 历史与当前消息、调用预留 | 组装后的模型消息、附件来源标识、可用调用预留 |
| agent | 模型消息、来源标识、预留及失败状态 | 工具循环后的消息、回答、是否使用工具；失败时含部分正文及错误 |
| finalize | 回答、失败状态、消息及预留 | 核验后的消息、回答和网页来源，同时保存业务终态 |

runtime.context 是不可变运行参数，只包含会话、账号、消息及操作身份、私密模型配置和同步／流式方式。数据库和执行服务由图实例持有，不进入 State。图外层消费框架 values 流保留最新 State，以便在节点边界异常时保存已有结果。

当前应用未实现基于外层检查点的中断恢复，因此停用 PostgreSQL checkpointer 和专用连接池；重启仍终止未完成请求，重试创建新的回答尝试。业务表继续保存消息、增量、用量和幂等事实；删除会话仍清旧 langgraph schema 中对应的历史检查点，不写入新的正文快照。决策见 [ADR 0012](adr/0012-state-based-conversation-flow.md)。

## Mem0 自动记忆规则

每条获准处理的用户消息由 Mem0 原生推理判断是否新增、更新或删除长期记忆。应用保存正式记忆及其来源和执行状态，不建立候选记忆表，也不提供逐条确认流程。助手回答和附件全文不会进入自动记忆输入。

更正使用稳定的记忆标识和版本。接受更正后旧值立即停止召回，只有向量及历史同步成功后才显示完成。部分提交和中断保留真实状态；重试核对已有结果，不把失败当作保存成功。

Mem0 的默认历史实现不满足本项目的 PostgreSQL 持久化范围。自定义适配集中在记忆模块，覆盖历史、最近消息、初始化、关闭和重置，并通过真实 SDK 契约检查；不修改机器上的已安装包，不以独立 SQLite 文件保存正式历史。导入 SDK 前关闭默认遥测，外部嵌入通过应用计量入口执行。

删除记忆先停止召回，再清正式向量、内部历史及相关操作缓存。防止旧来源自动恢复的标记不保存被删事实正文；原聊天仍可主动回看。删除会话时先预览真实关联记忆，默认一起删除；明确保留的事实继续可用并标注来源已删除。附件不产生记忆关系，删除附件只清理文件及其处理数据。

## 检索与资料边界

- 个人长期记忆采用 pgvector 相似度检索，只纳入完整成功、已批准、当前有效的条目，支持跨会话使用。
- 附件每次上传形成独立对象，始终按当前账号和会话授权。TXT、Markdown、PDF 和 DOCX 均只持久化带位置元数据的共用切片及索引，每轮只提供文档清单。search_documents 返回配置数量的完整切片，不限制 Token；read_document 按页／段落元数据定位全部相交切片，按原文顺序整片返回，最多 10,000 Token 且不超过执行点可用预算，超限返回下一切片游标，整片无法放入时明确返回预算不足。每个工具每轮最多五次，含失败和续读；是否调用及调用参数由模型自主决定。图片继续引用持久化 DeepSeek file_id。
- 附件正文及位置元数据只存于 document_chunks，阅读与检索共用；迁移 046 删除 document_units、重复全文及旧原文引用字段。附件检索采用 BM25 + 向量语义召回和智谱重排（ADR 0013），切片向量按嵌入配置版本缓存；阅读按文档顺序，不经过重排（ADR 0014）。
- 重建不得混用不同空间的向量。已删除记忆不参加；来源已删但用户明确保留的有效事实仍参加。进度、失败和恢复必须与实际执行一致。

支持文本型 PDF、DOCX、TXT、Markdown、PNG 和 JPEG。后端执行每次上传最多五个文件、单文件最多 20 MB、PDF 最多 200 页的限制。PDF 保留原有物理页；DOCX 使用 LibreOffice 自动生成固定分页 PDF 副本，切片保存起止页、段落及结构。Word 页码以固定副本为准，最多 200 页；原 DOCX 继续保存。扫描 OCR、复杂排版和文字文档内嵌图像理解不在本期范围，提取缺口会显示出来。

所有附件上传登记成功后保留 30 天。访问入口独立检查 expires_at，到期立即禁止清单、下载和工具读取；启动及每分钟清理原件、副本、共用切片与索引，图片同时清理远端文件。失败可恢复清理，晚到解析不能恢复来源。旧文字附件启动时从原件重建知识库，不延长有效期。

阅读预算优先使用 MODEL_TOKENIZERS 明确配置的模型官方 tokenizer.json，缺少对应实现时按字符保守估算。读取执行点以当前实际消息、工具定义、同批工具结果和最近模型真实用量核算可用空间，扣除模型配置中的回答预留。当前没有滑动窗口／摘要模块，本次不增加该模块，也不增加文档全文注入预算分支。实现决策见 [ADR 0011](adr/0011-conversation-document-tools.md)，具体规格和任务见 [会话文档工具](../.scratch/conversation-document-tools/spec.md)。

## 云端调用与用量

聊天、Mem0 自动提取与变更判断、记忆嵌入、召回、附件工具结果、工具搜索和最终回答都经过统一调用网关。一次请求可能对应多次调用，每次调用单独保存状态以及服务商返回的 token 或 credits。保存配置只表示连接信息已保存，实际能力以真实调用结果为准。

联网搜索由模型根据当前请求自主调用并直接执行，无需固定句式或明确联网口令，不再等待用户编辑或批准查询；附件或记忆中的个人信息也可能随查询外发。停止会阻止尚未发送的后续调用；已经发送的请求仍可能由服务商计费，可取得的实际用量继续记录。应用不估算价格或费用，账单以服务商为准。

当前聊天传输仍使用 OpenAI 兼容 Chat Completions，搜索由应用执行 `search_web` 并把结果回传模型；没有接入供应商内置搜索。DeepSeek 独立 Search / Fetch API 与 Responses 内置搜索的支持范围及迁移边界见 [README](../README.md#deepseek-搜索能力与当前接入边界)，不能把模型名称变更等同于已经接入联网。

## 本机运行与数据位置

完整启动和配置步骤见 [README](../README.md)。`bash scripts/start.sh` 安装锁定依赖、构建前端、启动数据库并在 `127.0.0.1:8000` 运行应用；数据库默认仅绑定 `127.0.0.1:15432`。

PostgreSQL 的 `general-agent_postgres_data` 卷保存会话、消息、调用记录、记忆来源、搜索记录等业务状态；记忆正文、向量和内部历史只保存在独立 Mem0 数据库。附件原文件保存在 `APP_DATA_DIR/attachments/`，默认项目 `.local/attachments/`；模型、嵌入及搜索配置由后端以私有文件保存。配置读取接口不回传完整密钥，错误响应不直接暴露服务商正文。数据库卷和本机附件需要一起保留，测试配置不覆盖用户配置。

业务数据库使用固定摘要的官方 PostgreSQL 17 Alpine 镜像，不安装 pgvector；Mem0 使用自己的 PostgreSQL/pgvector 服务。升级保持同一持久化卷和 PostgreSQL 主版本，维护前备份；不使用删除卷的命令升级。

## 验证边界

主要测试通过公开应用接口验证用户可观察行为，使用真实 PostgreSQL 与真实 Mem0，外部模型、嵌入和搜索仅在 HTTP 边界使用受控响应。少量浏览器流程覆盖上传、来源删除、设置和搜索工具；Mem0 REST 适配补充契约测试。

任务 01 曾用已配置的 DeepSeek 完成一次真实非流式文字调用并记录用量。受控测试不证明真实流式、视觉、工具、嵌入或智谱搜索兼容；未执行的真实调用及质量和账单验证均保留待验状态。各任务验证文档保留实际时间线，不把阶段测试改写成不存在的整套或真实服务验收。

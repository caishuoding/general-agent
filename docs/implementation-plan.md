# 个人对话智能体实现方案

第一版是供本人使用的本机 Web 应用，支持流式对话、会话附件、Mem0 长期记忆、按明确要求触发的历史聊天检索和联网搜索。界面使用 React 与 TypeScript，后端使用 FastAPI，PostgreSQL 通过 Docker Compose 在本机运行。

状态（2026-10-15）：任务 01 已实现本机文字对话、模型配置、PostgreSQL 持久化及用量记录，并完成 DeepSeek 真实文字调用。本文其余部分描述整体方案，不能视为已实现能力；Mem0、附件等仍按后续任务推进。产品行为以 [正式规格](../.scratch/general-agent/spec.md) 为准，实现范围和顺序以 [任务目录](../.scratch/general-agent/issues/) 为准，术语见 [GLOSSARY.md](../GLOSSARY.md)，实际检查见 [任务 01 验收记录](verification-01.md)。

## 总体结构

| 部分 | 职责与选择 |
| --- | --- |
| 浏览器界面 | 会话列表、聊天及附件上传、记忆管理、模型与搜索及预算设置 |
| FastAPI 后端 | 会话执行、权限判断、资料处理、记忆确认、预算控制和流式结果 |
| Mem0 OSS | 在本机运行 Python SDK，管理已批准的长期记忆，提供存取、检索和更新能力 |
| PostgreSQL | 业务记录、候选记忆、来源关联、调用用量和适配后的记忆历史 |
| pgvector | 拟作为 Mem0 的向量存储，也用于独立的资料和历史消息检索索引 |
| 本机附件目录 | 保存每个会话独立上传的原文件，路径由后端管理 |
| 外部调用 | 可配置的聊天模型、嵌入模型和 Tavily 搜索；统一经过用量与预算控制 |

Mem0 使用 OSS `Memory`，不使用连接托管平台的 `MemoryClient`，以符合数据在本机持久化的既定范围。Mem0 官方支持 pgvector 后端；模型与嵌入计算仍可按已确认规则调用云端服务。[OSS 与平台区别](https://docs.mem0.ai/platform/platform-vs-oss)、[pgvector 配置](https://docs.mem0.ai/components/vectordbs/dbs/pgvector)

## Mem0 接入与需要验证的适配

### 确认规则由应用执行

候选记忆先保存在应用的 PostgreSQL 表中，确认前不会进入 Mem0 的正式记忆集合。用户明确要求保存，或批准候选条目后，只把已批准的具体事实写入 Mem0；附件提取还要包含人物归属确认。

计划使用 `add(..., infer=False)` 保存已批准的文本，更新已有事实时调用对应记忆的更新操作。`infer=False` 是直接写入而不是预览，仍会产生嵌入调用；不能用它来实现“先看候选再决定”。[Mem0 add 说明](https://docs.mem0.ai/core-concepts/memory-operations/add)、[update 说明](https://docs.mem0.ai/core-concepts/memory-operations/update)

Mem0 默认的自动提取流程不承担本项目的候选确认规则。历史检索结果、模型回答和附件全文也不会因出现在上下文中就自动升级为长期记忆。

### 历史记录接入 PostgreSQL

核实到的 Mem0 Python OSS 当前源码仍以 SQLite 保存内部历史及部分消息上下文，没有正式可配置的 PostgreSQL 历史存储入口。因此，使用 pgvector 并不意味着其全部内部持久化已经进入 PostgreSQL。[配置源码](https://github.com/mem0ai/mem0/blob/main/mem0/configs/base.py)、[初始化源码](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py)、[历史存储源码](https://github.com/mem0ai/mem0/blob/main/mem0/memory/storage.py)

为保持 PostgreSQL 存储方案，拟在记忆模块内实现局部历史存储适配，覆盖历史追加、批量写入、查询、最近消息、初始化、关闭和重置等行为。此项是本项目的自定义集成，不是 Mem0 官方原生配置；必须锁定 SDK 版本并通过契约测试后，才进入后续实现。正式历史不依赖独立的 SQLite 文件，也不直接修改机器上的已安装依赖。

### 删除与来源关系

应用维护记忆 ID、来源消息或附件、确认状态和操作状态。删除或更新期间，先在应用层停止使用旧条目，避免存储同步尚未完成时继续召回旧事实；失败要显示并支持重试，不提前报告完成。

Mem0 当前删除实现会把旧正文写入删除历史，因此不能仅调用 `delete` 就认定内部正文已清除。适配需覆盖正式记忆、相关索引与内部历史正文的清理；保留防止旧来源再次自动提取所需的最小标记，不保留被删事实正文作为该标记。[Mem0 删除实现](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py)

删除记忆仍保留原聊天，符合既定规则；用户另行删除来源时，默认同时删除关联记忆，允许明确保留部分条目。删除来源时，也清理该来源的派生检索索引；保留的记忆标明原始来源已删除。

### 模型、嵌入与用量

设置中分别配置聊天模型和嵌入模型的地址、模型名称及凭证。服务商支持时可以复用地址和凭证，但需分别验证；嵌入服务不能被假定为聊天模型的同一接口。Mem0 的 OpenAI provider 提供这些配置能力。[LLM 配置](https://docs.mem0.ai/components/llms/config)、[嵌入配置](https://docs.mem0.ai/components/embedders/config)

Mem0 默认嵌入实现只返回向量，不能依靠记忆操作的最终返回值完整统计费用。拟用模型与嵌入调用适配统一执行调用前预算检查、调用后用量记录，覆盖批量调用和重试；适配的 SDK 接入方式也列入契约验证。[LLM 实现](https://github.com/mem0ai/mem0/blob/main/mem0/llms/openai.py)、[嵌入实现](https://github.com/mem0ai/mem0/blob/main/mem0/embeddings/openai.py)

按本机数据范围关闭 Mem0 默认遥测，在导入 SDK 前设置 `MEM0_TELEMETRY=False`。[遥测实现](https://github.com/mem0ai/mem0/blob/main/mem0/memory/telemetry.py)

## 模块职责

| Module | Interface 对调用者提供的行为 |
| --- | --- |
| 会话执行 | 提交一次用户请求、返回执行进度和回答、停止执行；内部协调上下文、工具调用与重试 |
| 长期记忆 | 提交候选、执行已批准变更、管理条目、召回有效记忆；隐藏 Mem0、来源规则和存储适配 |
| 会话资料 | 上传并处理附件、查询处理状态、获取有出处的相关内容、删除附件及派生内容 |
| 历史聊天 | 在明确授权的本轮请求中查找旧消息并返回出处，不借此读取其他会话附件原文 |
| 联网搜索 | 校验本轮搜索意图及个人信息发送确认，再调用 Tavily 并返回来源 |
| 模型调用与预算 | 校验连接能力、执行聊天或嵌入调用、计量用量、暂停并恢复预算受限的请求 |

Mem0 的适配、来源状态和删除清理集中在长期记忆模块内。外部模型和搜索请求通过可替换的 Adapter 执行，真实调用与测试使用同一 Interface，避免在聊天页面和路由中重复实现规则。

## 检索范围与资料处理

- 长期记忆按个人身份范围检索，仅返回已批准且有效的条目；不使用会话 ID 隔离个人长期记忆，以支持跨会话使用。
- 附件始终按所属会话过滤。每次重新上传形成该会话独立的附件和索引，不共享可见的文件对象。
- PDF 按页、DOCX 按段落或可识别结构、纯文本按段落保留出处。复杂图表或内嵌图片由用户单独上传为图片处理。
- 长资料先完成解析并显示状态。具体问题检索相关内容，全文总结按段处理后汇总，避免把局部检索结果称作全文总结。
- 历史聊天检索只在用户明确要求时启用，并返回原会话及消息出处；检索到的消息不自动成为候选记忆。
- 拟为资料和历史消息建立独立的 pgvector 检索索引，可复用嵌入服务配置，但不写入 Mem0 的长期记忆集合。
- 更新嵌入模型或维度时，记录索引所属模型并执行显式重建，不混用不同模型产生的向量。重建过程遵守预算规则。

## 界面与费用行为

左侧是会话列表，主区域提供流式回答、附件上传、处理状态、停止与重试入口。候选记忆通过卡片确认；记忆管理页面支持查看、修改、删除及查看来源；设置页面集中配置聊天、嵌入、搜索与预算。

用量记录覆盖聊天生成、候选提取、Mem0 内部调用、资料处理涉及的模型调用、嵌入及搜索。费用只能在取得用量且已知相应单价时估算，不完整的数据必须显示为未知。

启用月度预算后，估算达到额度或费用无法估算时暂停后续云端请求，用户可以补齐配置或允许本次继续；未设置预算则允许正常使用并展示可获取的信息。停止生成会阻止后续调用，但已经发出的请求可能仍被服务商计费，这部分有返回用量时继续记录。

## 数据与本机运行

任务 01 使用 Psycopg 直接访问 PostgreSQL，以 SQL 文件、结构版本记录和事务锁执行启动迁移；目前没有引入 SQLAlchemy 或 Alembic。版本迁移属于应用升级实现，不增加本期用户数据导入导出工具。

PostgreSQL 使用 Docker Compose 与持久化存储卷。任务 01 使用固定摘要的 PostgreSQL 17 镜像；pgvector 随 Mem0 集成任务引入。前端和后端直接在本机运行，数据库及应用仅绑定本机地址，前端构建产物由后端同源提供。[pgvector 镜像说明](https://github.com/pgvector/pgvector#docker)

业务表保存会话、消息、附件及处理状态、候选记忆、记忆来源和操作状态、用量与设置。Mem0 管理的正式记忆集合、适配后的记忆历史及独立资料索引分别组织，避免通过删除一种资料误删另一种。

模型和搜索密钥由后端保存在独立的本机配置中，设置读取接口仅返回是否已配置及掩码，不回传完整密钥；日志不记录凭证。交付文档说明数据库卷、附件目录和本机配置的位置。

已使用本机 Docker Desktop、Compose、Node.js 24 和 Python 3.12 启动应用与 PostgreSQL，并验证实际数据库容器重启后的记录保留。

## 实现顺序

以下为初始阶段划分；当前执行顺序以正式规格拆分出的 18 项任务及其阻塞依赖为准，先交付任务 01 的可用文字对话，再推进流式响应、能力验证、预算与 Mem0。

1. **Mem0 集成验证**：锁定 SDK 版本，验证 pgvector、直接写入与更新、历史存储适配、删除清理和统一计费入口；使用受控替身验证调用规则，避免把未验证的适配当成既有能力。
2. **本机基础与对话**：建立项目结构、数据库迁移与 Compose 配置、模型设置和连接检查，完成会话持久化、流式回答、停止及失败重试。
3. **记忆闭环**：实现候选确认、明确指令保存、编辑、删除、来源管理与跨会话召回，并验证旧来源不会自动恢复已删除记忆。
4. **附件及历史检索**：落实上传限制、解析与引用、独立检索范围、分段总结，以及明确要求触发的历史聊天查询。
5. **搜索、预算与完整界面**：接入 Tavily、个人信息发送确认、全部云端调用计量与预算暂停，完成设置和管理页面。
6. **端到端验收与交付**：验证核心行为及重启持久化，提供启动说明、配置示例、数据位置说明与已知限制。

如锁定版本的 Mem0 适配验证失败，应先修正局部适配或重新提出具体取舍，不静默替换 Mem0、存储方案或记忆规则。

## 验收清单

| 场景 | 完成标准 |
| --- | --- |
| 模型配置 | 分别验证文字、图片、工具调用和嵌入能力，缺少能力时准确提示 |
| 对话与持久化 | 会话可创建、继续和删除；流式显示可停止，应用重启后已保存内容仍存在 |
| 候选记忆 | 未确认的条目不会进入 Mem0 正式集合或跨会话召回 |
| 明确保存与修改 | 明确要求保存直接生效；明确修改后不再将旧值作为当前事实 |
| 删除记忆 | 正式记忆停止召回，内部旧正文按删除规则清理，同一旧来源不自动重新生成；原聊天按既定规则保留 |
| 删除来源 | 展示关联记忆并默认一并删除，保留项显示来源已删除；附件及派生索引按所属会话清理 |
| 附件限制 | 每条消息 5 个、单文件 20 MB、PDF 200 页的限制被后端校验，超限明确提示 |
| 资料回答 | 支持的类型能处理并给出文件及位置引用；无法提取或尚未处理完成时明确说明 |
| 会话隔离 | 新会话不能读取旧会话附件原文；重新上传后作为新的会话附件处理 |
| 历史检索 | 明确要求时查旧消息并给出处，普通聊天不自动翻其他会话 |
| 联网搜索 | 配置后能够检索并引用来源；发送个人信息前确认，未配置时不影响其他能力 |
| 预算 | 达到额度或已启用预算但费用未知时阻止后续云端请求；Mem0 与嵌入调用不能绕过控制 |
| SDK 适配 | 初始化、重启、重置、错误重试和删除流程不会意外恢复默认持久化或绕过预算 |

核心验证覆盖真实 PostgreSQL 与 Mem0 的集成，外部接口错误用受控替身测试；配置实际模型与搜索服务后，再验证真实请求、来源和用量。尚未发生的真实接口验收不标记为通过。

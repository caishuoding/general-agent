独立分支 `codex/ticket-16-history-search`，从集成 `80e222c` 创建并确认祖先。沿已批准的公开应用 HTTP seam 实现；只使用 15433 上随机隔离 PostgreSQL、必要的真实 Mem0 与受控外部 HTTP。未读取主 `.local`、调用真实服务或变更用户数据库/8000 应用。

## 行为、接口与执行边界

通过现有 `POST /api/conversations/{id}/messages` 和 `/runs` 提交“查找旧聊天：关键词”；支持查询、检索、回看等明确中文动词及旧消息/聊天记录等对象，关键词需以冒号或空格分隔。普通提问、否定、引用解释、多行示例或讨论功能本身不触发。没有使用模型判定用户是否授权。保守句式之外可改为上述格式。

`history.py:HistorySearch` 是独立本机检索边界，不接收附件或 Mem0 客户端。当前查询只读其他会话 status=complete 的 `messages.content`，参数化词法匹配，最多十二个输入词、最近八条消息；结果明确区分用户与助手说法，并从首个匹配词附近截取最多 1200 字符。长原文的截断有省略号。无新向量集合、嵌入配置、第三方服务或后台索引；18 不需要重建历史向量。

`ChatExecution` 在当前历史请求上跳过明确记忆变更、候选发现和自动召回；同步与流式回答只接收已查到的有限摘录及当前请求。资料、全文总结和联网分支不会把旧消息转换成读取旧附件或执行旧指令的授权。真实 Mem0 既有正式事实不变化，历史结果不写入候选或正式记忆。

公开会话和 SSE 的助手消息增加 `history_search`（complete/empty/unavailable、数量和说明）及 `history_sources`（H 键、conversation_id、message_id、会话标题、角色、日期、摘录）。前端展示可核对来源，点击“查看原消息”重新读取真实会话并核验消息存在、滚动定位。未找到结果本地回执；来源不存在、不是有效完成消息或指纹改变时不显示其旧摘录。模型未知 H 标记替换为未核验；漏引仍提供实际检索结果并提示核对。

本机查询不计云费用；最终回答走已有 BoundCalls，遵守逐次预算、停止、重试和真实 token 记录。预算暂停前已存无正文出处关系，应用重启可恢复；不会因恢复再次查询新增来源。明确重试创建新的 operation、重新检索，保留同一原用户消息。停止后已发请求继续收取实际用量而不追加回答。流式每段写入前重新核验全部来源，公开读取也屏蔽来源失效时尚未完成的派生回答；迟到响应不能恢复失效摘录。

## 数据位置及 09 / 15 必须执行的清理合同

迁移 `017_history_search.sql` 创建独立业务记录：

- `history_queries`：operation_id（主键/指向 cloud_operations）、请求 conversation_id、request_message_id、最初命中数量和时间。没有查询正文副本，关键词从原当前消息读取。
- `history_hits`：operation_id、source_message_id、source_conversation_id、source_hash、稳定 H 键和 ordinal；没有原文、标题或摘录副本。来源 FK 和 query FK 删除时 CASCADE；两个来源索引方便删除前查依赖。
- `history_search` / `history_sources` 仅在公开响应中实时从有效原消息重建，不新增消息 JSON 列，不把模型输出另存最终结果缓存。聊天 perform_run 幂等重放也读取实时状态；实际完成的助手正文仍是原聊天记录。

**09 忘记记忆**：历史来源是 messages，不是 memory_actions 或 Mem0；保留的原聊天依 ADR 可被用户明确重新查阅。删除记忆不应抹去原聊天或无差别清空历史命中。当前历史动作绕过候选/明确保存流程，因此不会把命中正文自动重新提取。09 的旧来源抑制仍需在记忆模块执行，未来不能把历史查询结果再传给候选提取。

**15 删除会话/真实来源**：在删除源消息或会话之前，按 history_hits.source_message_id / source_conversation_id 收集所有其他会话依赖的 operation。先撤销执行及预算批准并清 cloud_operations.result，停止关联的生成/暂停回答；再删除对应 hits。被删查询所在会话的 history_queries 及 hits 随请求/会话 CASCADE。保留仍需展示失效说明的其他 query 与原始 result_count（无正文），使公开读取准确报告来源减少，不能把“原来有结果”伪装为从未命中。

活动工作线程已持有的摘录只能在来源重新核验成功时写结果；删除流程仍必须先取消关联 operation，阻止下一次真实模型调用。对活动或未完成历史回答，清理其派生部分正文及失效的暂停挑战；实际已发生的 model_calls 费用保留。已有完成聊天正文按用户选择的会话保留规则另行处理，不能将其与后台摘录缓存混淆。当前没有历史结果正文副本需要额外物理 purge；若以后增加索引或缓存必须加入同一清理闭包。

单独删附件不删除同会话的 messages；历史检索本来不读附件，因此无需删除无关的历史命中。若聊天已经引用过附件，其原聊天及引用依 15 既有规则处理，不能由历史入口重新打开已删原文件。删除中若新增来源状态，应同时接入 `HistorySearch.prepare` 与 `public_history` 的有效性判断，不能只靠最后物理删除。

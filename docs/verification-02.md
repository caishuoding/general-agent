## 实现与接口

- 发送时先在 PostgreSQL 保存用户消息与生成中的助手消息，随后逐段提交回答。SSE 发送已持久化的消息快照；切换会话或刷新后可以恢复当前进度，不重复拼接已收到的内容。
- 停止立即把回答和调用标为 stopped，并冻结部分内容。已经发出的同一次请求继续被消费以收集可返回的用量；不再发起自动重试或后续请求。停止不是服务商撤销费用的保证。
- 断流、无效响应、服务错误或长度限制均保存 failed 与公开错误说明，不把部分回答标为 complete。长度限制事件后的 usage 尾帧仍会被收集；错误事件携带的 usage 也会保存，服务原始错误正文不会展示。
- 仅可重试本会话最后一条失败或停止的回答。重试创建新的助手消息和实际调用记录，reply_to 指向同一原用户消息；旧尝试和已知用量均保留。旧同步失败消息也可以通过原用户消息恢复重试。
- 同一会话有生成中的回答时，新的流式与兼容同步发送均返回 409。其他会话仍可独立执行。
- 单进程启动恢复会将遗留 generating 消息与调用标为 failed；部分内容和已取得用量保留。正常关闭也会终结未完成状态。此运行模型不支持多个后端 worker 共用同一业务库。
- 浏览器网络断开会显示进度连接中断与自动重连提示；此时不擅自把仍在后台执行的模型请求标为失败。明确的停止按钮负责停止回答。

公开接口：

| 接口 | 行为 |
| --- | --- |
| POST /api/conversations/{id}/runs | 创建用户消息与流式回答，202 返回当前会话详情 |
| GET /api/conversations/{id}/messages/{message_id}/events | SSE 消息快照；终态关闭连接 |
| POST /api/conversations/{id}/messages/{message_id}/stop | 停止并返回最新会话详情；重复停止不改变终态 |
| POST /api/conversations/{id}/messages/{message_id}/retry | 复用原用户消息创建新尝试，202 返回详情 |
| GET /api/conversations/{id} | 查询生成中、完成、停止、失败及部分内容 |
| GET /api/usage | 每次实际调用的状态与已知或未知 token 用量 |

迁移 003_streaming.sql 增加 messages.reply_to、messages.error、model_calls.assistant_message_id，拓展生成状态并约束每会话最多一条 generating 回答。费用估算和预算属于后续任务；本票保留供后续计费使用的实际调用与服务用量，不将未知值冒充零。

后续多步骤能力应在每次新外部请求前检查持久化生成状态。当前 StreamingChat.execute 在调用边界检查生成状态，停止后的同一次外部流只用于收集已发出请求的用量。当前实现没有自动后续模型调用。

本票 7 项后端测试覆盖：

1. 完成之前可读取第一段及 generating 状态，完成事件、用量与重启读取一致。
2. 停止保留第一段并立即改变状态，后续文字不追加，延迟返回的用量仍保存。
3. 断流保留部分内容，重试不重复用户消息，两个实际调用分别记录用量；不能重复重试旧尝试。
4. 兼容同步发送接口不能绕过同会话生成保护。
5. 长度限制结束事件之后的 usage 尾帧仍保存，回答仍是失败。
6. 错误事件中的用量被保留，敏感服务正文不回显。
7. 使用真实后端进程、真实 HTTP 与受控本机模型，强制终止生成中的进程，再启动新进程：部分内容保留，状态恢复为 failed，未取得用量保持未知。

本票浏览器测试覆盖第一段先出现再完成、停止后刷新仍保留状态与内容、断流后刷新再重试且只保留一条用户消息。原有配置、会话切换、刷新与迟到读取不会覆盖新回答的测试仍通过。

核心行为按先失败后实现验证。长度限制尾帧漏用量、流错误事件漏用量和旧同步接口绕过并发保护均有先失败再通过的回归。浏览器服务器仅在 127.0.0.1:18082 与 18083 运行，使用临时配置和随机数据库；测试退出清理所创建的数据。强制重启测试使用系统分配的空闲本机端口。没有读取主工作区 .local、真实模型密钥或重启共享数据库。

测试工具仍提示 Starlette TestClient 的 HTTPX 兼容方式弃用及 Playwright 颜色环境变量提示；没有测试失败，未修改锁定依赖以消除这些提示。

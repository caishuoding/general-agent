# 管理端细化与独立登录规格

Status: ready-for-agent

## 已确认的范围

- 系统只有固定的 `admin` 管理员账号。管理端不能创建、改名、停用第二个管理员，也不能把普通用户提升为管理员；当前没有第二个管理员需要迁移。
- 管理员与普通用户的凭据保存在同一个 PostgreSQL 数据库的不同表，分别验证登录并维护独立会话和 Cookie。同一浏览器可以同时保持两个入口的登录状态；`/` 始终是用户端，`/admin` 始终是管理端，互不跳转。
- 在错误入口提交账号时统一返回“用户名或密码错误”，不提示账号属于另一端。现有管理员密码哈希与普通用户账号及其数据在迁移中需要保留。
- 管理端账号列表只展示普通用户，支持按用户名、状态查找；管理员自己的改密和退出入口放在管理端顶部。创建账号表单不再提供角色选择。
- 选定普通用户后，管理端只在打开具体栏目时读取对应数据。现有会话、消息、附件、长期记忆、搜索记录、调用用量六类数据继续提供只读查看。
- 会话支持按标题、消息内容和日期查找，消息按时间顺序展示用户可见的正文、时间、生成状态、附件和回答引用；不展示内部提示词或工具执行细节。
- 附件支持下载；图片和 PDF 增加管理端预览。管理员查看其他账号内容和下载附件继续写入审计记录，并提供可查看的审计页。
- 管理员重置普通用户密码时由系统生成强临时密码，只在成功时显示一次；重置吊销该账号旧会话并强制下次登录改密。管理员无法查看原密码或之后找回临时密码。
- 管理端删除“仅查看”“只读”“不会替用户发送消息”等重复提示和教学式空状态文案；保留明确的栏目名、错误、操作结果，以及停用账号和重置密码等操作的必要后果说明。
- 用户端不显示管理员可查看会话、附件等内容的提示。
- 审计页保留完整历史，支持按目标账号、操作和日期筛选，展示操作者、资源、时间和来源地址；审计只可追加，管理端不能修改或删除。
- 管理端只查看仍有效的会话和附件；用户已删除的会话和已到期的附件内容不可查看，已有访问审计继续保留。
- 唯一管理员忘记密码时，由服务器本机恢复命令设置新密码、吊销旧会话并留下恢复记录；管理端网页不提供管理员密码找回入口。
- 管理员阅读会话的界面必须清晰易用，与用户端的聊天排版保持一致的视觉质量，不能沿用当前简单段落堆叠的展示方式。
- 管理端采用“普通用户列表 → 该用户的会话列表 → 会话阅读页”的导航。桌面端阅读页并排显示会话列表和消息；窄屏逐层进入，提供清楚的返回路径，不把三个层级挤在同一行。
- 会话消息沿用用户端的阅读体验：区分用户和助手，正确排版 Markdown、表格与代码；附件和引用可打开，消息可复制，搜索结果可定位到对应消息。时间和失败状态作为辅助信息展示。
- 管理端沿用现有产品的颜色与字体，减少多余边框、徽章和说明文字；账号管理与审计保持简洁，会话阅读区保证长内容可读。

## 验收重点

- 管理端与用户端分别登录；同一浏览器同时保持两种会话时，访问各自 URL 不跳到另一端，错误入口的登录失败不泄露账号归属。
- 管理端只能管理普通用户账号；聊天内容和附件可按已确认范围查看，但不能通过管理端代发消息或修改用户内容。
- 对话阅读页在桌面和窄屏均可顺畅查找、阅读长回答、打开附件与引用；审计能追溯每次跨账号内容读取。
- 密码只保存哈希；临时密码只显示一次，管理员恢复仅能在服务器本机执行。

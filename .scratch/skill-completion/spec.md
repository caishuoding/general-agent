# 聊天输入区的 Skill 卡片显式选择

## 最新用户要求

本方案替代此前的 `$` 候选与描述插入方案，当前实现与验收记录见 `docs/verification-skill-cards.md`。

可用 Skill 在聊天输入框上方以卡片展示，点击选中或取消，可多选。输入框只编辑用户真实需求。发送时把所选 Skill 的完整 description 与真实需求拼接为一条 user message。选择本身不发送、不创建任务、不执行脚本，后续继续使用现有 Skill 加载流程。

## 界面与目录

复用 GET /api/skills，按真实安装目录只展示 name 和选中标记；卡片不显示 description、版本或“查看说明”，实际发送仍使用完整原文，不翻译、不摘要。只有一个 Skill 时只展示一张名称卡片。

卡片位于输入框上方，桌面换行、手机自适应；数量多时限制卡片区高度并内部滚动。纯文本渲染，切换按钮使用 aria-pressed，支持键盘、触屏和屏幕阅读器。

目录按账号缓存并在进入输入区时刷新；退出登录清除，迟到响应不得污染其他账号。加载、失败重试、空目录状态明确，失败保留草稿且不阻止普通聊天。

## 选择生命周期

- 默认未选，点击切换，可多选，按选择顺序拼接。
- 选择只作用于待发送消息；成功后清空选择和草稿。
- 发送失败恢复该次原文与选择，不覆盖用户后来编辑的新草稿。
- 切换会话、开始新会话、退出登录时清空选择。
- 生成中沿用现有发送限制，卡片不会影响正在生成的回答。
- 必须填写真实需求，不能只靠选择卡片发送。
- 未选卡片时沿用普通聊天，模型仍可自主选择 Skill。

## 请求与模型消息

前端发送用户原文和所选名称：

```json
{
  "content": "根据附件做一份季度汇报，控制在 12 页以内。",
  "skills": ["ppt-master"]
}
```

后端解析已安装目录，按名称取得完整 description，不信任客户端自带描述。名称去重、保持顺序；未知或失效名称明确报错并保留草稿，不静默忽略选择。最终长度和上下文预算按完整消息检查，超限不截断描述或正文。

最终发给模型的一条 user message 示例：

```text
本次明确指定的 Skills：

Skill：ppt-master
Description：
<该 Skill 完整 description 原文>

用户需求：
根据附件做一份季度汇报，控制在 12 页以内。
```

多选时依次添加各名称和完整描述，最后仅拼接一次用户真实需求。角色为 user，块边界明确；描述不能自行扩大执行权限。SKILL.md 正文仍按现有 load_skill/read_skill_file 流程加载，不因卡片选中强制预加载或增加意图分类器。

## 保存、历史和重试

用户消息保存真实 content，以及所选 Skill 的名称、版本和完整 description 快照。历史界面显示真实输入与 Skill 小标签，可展开查看当时的描述，避免将长说明直接铺进聊天正文。

统一上下文准备处从已保存快照生成模型消息，当前回答、后续历史和重试共用此规则，防止重复拼接。上游更新后，既有消息不更换描述；实际 Skill 正文版本兼容仍由运行层检查。

同步、流式和重试入口共用选择信息；操作幂等范围包含所选名称及描述版本，避免同一正文的不同选择串用旧结果。skills 缺省为空列表，兼容现有调用方。

## 实现落点

1. Skill 卡片模块：读取目录、紧凑名称选择、无障碍与错误状态。
2. App 输入区：选择集合、发送快照、切换清空和失败恢复，沿用现有 textarea/输入法逻辑。
3. 消息类型与接口：请求接收名称，响应提供历史选择摘要与快照。
4. 用户消息持久化：新增选择快照字段，旧消息为空选择，不改写原正文。
5. 统一模型上下文准备：拼接描述与真实需求，继续使用现有 Skill 工具与预算。
6. 测试与文档：覆盖 UI、模型实际 user 消息、历史和重试。

## 验收

- 卡片展示真实目录，选中/取消和多选顺序正确，输入框不被选择动作改写。
- 选择本身不外发消息或创建任务；无真实需求时不能发送。
- 模型收到所选完整描述与真实需求组成的一条 user message，需求只出现一次。
- 未选择保持原行为，显式选择不绕过加载、权限或预算。
- 成功清空，失败恢复，迟到响应不覆盖新编辑。
- 刷新保留真实正文、标签和说明快照；历史与重试不重复拼接、不更换描述版本。
- 切换会话/账号、目录刷新、Skill 移除、长描述和超预算有明确处理。
- 桌面、手机、键盘、输入法、附件和既有发送功能正常。

# 05: 通过 Mem0 明确保存并查看记忆

**What to build:** 在聊天中明确说“记住”后直接保存，并在记忆管理页查看事实、来源和真实操作状态。

**Blocked by:** 04 — 用量展示与月度预算暂停。

**Status:** ready-for-agent

**规格覆盖：** 个人对话智能体首版规格，用户故事 19、23、29、40、41。

- [ ] 采用用户指定的 Mem0，在实现开始时锁定 SDK 版本并验证本机持久化方案；以 OSS 与 PostgreSQL/pgvector 为工程基线，不能静默改用托管记忆服务或其他正式数据库。
- [ ] 明确要求保存的具体事实无需重复确认，只有已批准内容进入正式记忆；普通聊天、模型回答和附件全文不被批量自动写入。
- [ ] 记忆管理页能读取已保存条目及原会话、消息来源，应用和数据库重启后仍可查看。
- [ ] 落实并契约验证所选版本的 PostgreSQL 历史持久化适配、初始化、关闭、重启与重置行为，不把自定义适配描述为 SDK 官方现成功能；关闭未纳入产品范围的默认遥测。
- [ ] Mem0 产生的模型或嵌入调用使用统一计量与预算边界；直接保存所需的嵌入调用同样受预算约束。
- [ ] 失败显示真实状态并可重试，重复请求不会造成不符合用户意图的重复条目；适配无法满足约束时给出具体失败证据和取舍，不假报完成。
- [ ] 应用接口集成测试使用真实 PostgreSQL、真实 Mem0 与可控云端替身；补充必要适配契约测试，不以完全模拟 Mem0 的测试替代验证。
- [ ] 本任务涉及的启动、配置、数据位置和能力边界说明与实现同步更新。
- [ ] 所有新增或修改的函数、方法、构造函数、箭头函数和回调函数都有中文用途说明注释，逻辑改变时同步更新注释。
- [ ] 分别记录受控替身测试和真实服务验收结果；缺少凭据或尚未执行的真实请求明确标为待验，不以替身测试通过冒充真实服务兼容。

# 10: 会话内上传文本并带出处回答

**What to build:** 在聊天框上传 TXT 或 Markdown，查看处理状态并提问；回答引用当前会话中的文件与位置。

**Blocked by:** 04 — 用量展示与月度预算暂停。

**Status:** ready-for-agent

**Completion:** complete

**规格覆盖：** 个人对话智能体首版规格，用户故事 44、46、47、48、49、50、51、53、54、55、56、57。

- [x] 每次上传形成属于当前会话的独立附件，原文件保存在本机，业务关系与处理状态持久化；重新进入该会话可继续使用。
- [x] 支持 TXT 与 Markdown，后端执行每条消息最多五个文件、单文件最多 20 MB 的限制，超限及暂不支持的类型明确拒绝。
- [x] 显示上传、处理、可用或失败状态，无法读取或尚未处理的内容不被说成已理解。
- [x] 用户可对文本提问并获得对应文件及段落或可识别位置的引用，资料处理使用的云端调用全部受预算约束。
- [x] 检索按当前会话过滤，资料索引独立于 Mem0；新会话需要重新上传，不提供跨会话选择旧附件的入口。
- [x] 同一原文件在不同会话上传形成独立关系；测试覆盖会话隔离、重新进入、重复上传、数量与大小边界、引用和解析失败。
- [x] 接口测试使用真实 PostgreSQL 与可控外部替身；少量浏览器测试验证真实上传动作与状态展示，相关启动及数据位置说明随功能更新。
- [x] 本任务涉及的启动、配置、数据位置和能力边界说明与实现同步更新。
- [x] 所有新增或修改的函数、方法、构造函数、箭头函数和回调函数都有中文用途说明注释，逻辑改变时同步更新注释。
- [x] 分别记录受控替身测试和真实服务验收结果；缺少凭据或尚未执行的真实请求明确标为待验，不以替身测试通过冒充真实服务兼容。

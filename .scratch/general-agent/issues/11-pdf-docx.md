# 11: 文本 PDF 与 DOCX 阅读

**What to build:** 上传文本型 PDF 或 Word 文档，提问并定位页码或段落；清楚提示无法处理的内容。

**Blocked by:** 10 — 会话内上传文本并带出处回答。

**Status:** ready-for-agent

**规格覆盖：** 个人对话智能体首版规格，用户故事 42、43、52、53、54、55、57、60。

- [ ] 扩展既有上传与资料问答流程以支持文本型 PDF 和 DOCX，继续遵守单次五个、单文件 20 MB 的限制。
- [ ] 后端执行单份 PDF 最多 200 页的限制，覆盖上限内、恰好上限和超过上限。
- [ ] PDF 提取内容保留页码，DOCX 保留段落或可识别结构，引用能定位到实际读取的位置。
- [ ] 扫描版 PDF、空文本、损坏文件和解析失败有明确说明，不提供 OCR 或伪造已读取的文字。
- [ ] 说明复杂图表和内嵌图片需要单独上传为图片，不能将文字提取描述成已理解所有图像和排版。
- [ ] 真实数据库的接口测试与文件样本覆盖解析、定位、限制和失败，后续模型调用继续计量并遵守预算。
- [ ] 本任务涉及的启动、配置、数据位置和能力边界说明与实现同步更新。
- [ ] 所有新增或修改的函数、方法、构造函数、箭头函数和回调函数都有中文用途说明注释，逻辑改变时同步更新注释。
- [ ] 分别记录受控替身测试和真实服务验收结果；缺少凭据或尚未执行的真实请求明确标为待验，不以替身测试通过冒充真实服务兼容。

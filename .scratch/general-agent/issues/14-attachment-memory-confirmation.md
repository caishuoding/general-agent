# 14: 从附件提取记忆并确认归属

**What to build:** 明确要求从附件记住信息时，先核对信息属于谁和准备保存的事实，再确认写入。

**Blocked by:** 08 — 候选记忆与含义不明的变更确认；11 — 文本 PDF 与 DOCX 阅读；12 — 图片上传与视觉问答。

**Status:** ready-for-agent

**Completion:** complete

**规格覆盖：** 个人对话智能体首版规格，用户故事 37、38、39、40、41。

- [x] 只有用户明确要求时从当前会话已可用的附件提取记忆，支持已实现的文字文档及图片资料。
- [x] 预览逐项展示人物归属、具体事实与文件来源，确认前不进入正式 Mem0 记忆，也不参与跨会话召回。
- [x] 朋友、客户等他人的资料不会被默认认作用户本人经历；归属不清时先澄清，无法确定的内容不直接保存。
- [x] 用户确认后只写入批准的条目并保留来源关系；拒绝、重复点击、源文件已失效或写入失败时行为准确。
- [x] 聊天中明确要求保存的直接陈述保持直接保存规则，不因附件提取需要预览而增加重复确认。
- [x] 提取、预览与正式保存涉及的调用遵守预算；真实 PostgreSQL、Mem0 与受控外部响应测试覆盖人物归属、未批准不可召回、批准、拒绝及失败。
- [x] 本任务涉及的启动、配置、数据位置和能力边界说明与实现同步更新。
- [x] 所有新增或修改的函数、方法、构造函数、箭头函数和回调函数都有中文用途说明注释，逻辑改变时同步更新注释。
- [x] 分别记录受控替身测试和真实服务验收结果；缺少凭据或尚未执行的真实请求明确标为待验，不以替身测试通过冒充真实服务兼容。

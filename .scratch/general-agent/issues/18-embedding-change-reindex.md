# 18: 更换嵌入模型并重建检索索引

**What to build:** 更换嵌入模型或维度时明确重建受影响的索引，显示进度与失败状态，已有资料和记忆保持可追溯。

**Blocked by:** 13 — 长资料总结与多文件比较；15 — 删除会话或附件并处理关联记忆；16 — 按明确要求检索旧聊天。

**Status:** ready-for-agent

**Completion:** complete

**规格覆盖：** 个人对话智能体首版规格，用户故事 5、8。

- [x] 在已有工程方案采用向量检索的范围内，设置明确展示模型或维度变化影响的记忆、资料及历史消息集合；不新增面向用户的数据迁移工具。
- [x] 对每个索引记录模型与维度，禁止将新查询向量与旧空间混用；新配置在受影响集合可正确查询前，界面明确提示状态。
- [x] 重建有可查看的进度、暂停和失败状态；数据正文和来源关系保留，失败可恢复，不假报完成。
- [x] 重建只纳入有效、已批准且仍存在的数据；删除的来源、删除的记忆和未确认候选不会在重建后复活。
- [x] 所有重新嵌入和重试请求通过用量与预算边界，预算不足时停止发起新调用，用户明确允许后按既定范围继续。
- [x] 从应用接口结合真实 PostgreSQL 和 Mem0 验证模型及维度更换、不同集合的边界、删除后重建、重启恢复与预算暂停；维护相应配置和数据位置说明。
- [x] 本任务涉及的启动、配置、数据位置和能力边界说明与实现同步更新。
- [x] 所有新增或修改的函数、方法、构造函数、箭头函数和回调函数都有中文用途说明注释，逻辑改变时同步更新注释。
- [x] 分别记录受控替身测试和真实服务验收结果；缺少凭据或尚未执行的真实请求明确标为待验，不以替身测试通过冒充真实服务兼容。

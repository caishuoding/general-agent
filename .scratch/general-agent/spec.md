# 个人对话智能体首版规格

Status: ready-for-agent

Completion: complete（2026-10-15）。实现与受控验收完成；用户同意的真实服务待验项见最终记录。

## Problem Statement

用户需要一个日常可持续使用的个人对话智能体，能够完成问答和写作、理解聊天中上传的文件，并在新会话中继续运用稳定的个人偏好和背景。用户不希望每次都重复交代自己，也不希望助手把临时表达、他人的资料或附件正文误认定为个人事实。

长期记忆和附件需要有清晰且不同的使用规则。用户直接从 PostgreSQL 查看真实记忆数据，并通过聊天工具修改和删除记忆，避免删掉的记忆又从旧来源自动生成。附件应属于上传它的会话；联网搜索由模型根据当前请求按需自主调用，查询直接执行，不增加额外确认。

用户还需要在本机保存数据，自行配置云端模型与搜索服务，并查看服务返回的调用用量。应用面向个人本机使用，优先形成真实可用的完整流程。

## Solution

提供一个本机运行的 Web 应用：左侧管理会话，主区域支持流式聊天和附件上传，另设设置页面。应用不复制展示长期记忆列表，真实数据直接从 PostgreSQL 查看。应用采用 React 与 TypeScript 界面、Python FastAPI 后端和 PostgreSQL；数据库由 Docker Compose 在本机运行，前后端直接在本机运行，附件原文件保存在本机目录。

长期记忆使用 Mem0。Mem0 根据当前获准处理的用户消息自动判断新增、更新和删除；用户直接查询 PostgreSQL 查看正式记忆及来源，通过聊天工具修改或删除。助手回答和附件正文不进入自动记忆输入。删除记忆与删除来源分别处理，并提供会话关联记忆的删除选择。

支持文本型 PDF、DOCX、TXT、Markdown、PNG 和 JPEG。用户可以总结、比较和追问资料，并获得文件引用；新会话使用同一文件需要重新上传。智谱联网搜索由模型作为普通工具按需调用，查询直接执行；附件或记忆中的个人信息不触发额外确认。

模型接入可配置，先支持 OpenAI 兼容的 Chat Completions，并分别验证文字、图片和工具调用能力。应用记录服务返回的 token 或 credits，但不维护价格、费用估算或消费额度。

## User Stories

### 本机使用与配置

1. 作为个人用户，我希望通过本机浏览器使用助手，以便在自己的电脑上完成日常任务。
2. 作为个人用户，我希望获得清楚的启动说明，以便能够自行启动数据库和应用。
3. 作为个人用户，我希望填写模型 API 地址、密钥和模型名称，以便使用自己选择的云端服务。
4. 作为个人用户，我希望分别验证模型的文字、图片和工具调用能力，以便知道当前配置能够完成哪些任务。
5. 作为个人用户，我希望能够修改模型连接配置，以便更换服务时继续使用已有会话和资料。
6. 作为个人用户，我希望搜索服务与模型服务分别配置，以便独立管理两个服务的接入信息。
7. 作为个人用户，我希望未配置搜索时仍能使用聊天、附件和记忆，以便逐步完成设置。
8. 作为个人用户，我希望知道数据库、附件和本机配置保存在哪里，以便理解数据的实际位置。

### 会话与回答

9. 作为个人用户，我希望新建独立会话，以便分开讨论不同任务。
10. 作为个人用户，我希望从会话列表回到旧会话继续讨论，以便延续原有上下文。
11. 作为个人用户，我希望通过聊天进行日常问答和写作，以便在同一个入口获得帮助。
12. 作为个人用户，我希望回答逐步显示，以便在生成完成前开始阅读。
13. 作为个人用户，我希望停止正在生成的回答，以便中止不再需要的执行。
14. 作为个人用户，我希望失败后能够重试，以便恢复被临时错误打断的任务。
15. 作为个人用户，我希望应用重启后已保存的会话仍然存在，以便持续使用历史成果。
16. 作为个人用户，我希望删除不再需要的会话及其附件，以便管理本机保留的资料。
17. 作为个人用户，我希望在模型连接失败或能力不足时看到明确说明，以便纠正配置或调整请求。
18. 作为个人用户，我希望前端只保留对话、附件和设置入口，不展示长期记忆数据。

### 长期记忆与来源

19. 作为个人用户，我希望明确说“记住某个事实”后直接保存，以便不用重复确认已经明确表达的意图。
20. 作为个人用户，我希望 Mem0 自动识别当前消息中的稳定事实和偏好，以便减少手动维护。
21. 作为个人用户，我希望直接查询 PostgreSQL 判断自动记忆是否完成，而不是依赖前端二次展示。
22. 作为个人用户，我希望通过聊天工具修改和删除自动产生的正式记忆，以便控制助手对我的长期认识。
23. 作为个人用户，我希望直接查询 PostgreSQL 中的真实记忆数据，以便知道 Mem0 实际保存了什么。
24. 作为个人用户，我希望明确要求更正记忆时调用记忆工具，以便纠正错误或过时的信息。
25. 作为个人用户，我希望明确要求更正记忆时直接更新，以便新事实及时替代旧事实。
26. 作为个人用户，我希望“最近在杭州”等含义不明确的表达先经过确认，以便助手不会把出差误当成搬家。
27. 作为个人用户，我希望新会话能自动使用相关的已保存记忆，以便减少重复介绍偏好和背景。
28. 作为个人用户，我希望记忆只在相关对话中使用，以便回答围绕当前问题展开。
29. 作为个人用户，我希望查看每条记忆的来源，以便判断这条信息的依据。
30. 作为个人用户，我希望删除记忆后它停止作为长期记忆使用，以便撤回不想再让助手记住的信息。
31. 作为个人用户，我希望删除的记忆不会从同一旧来源自动重新生成，以便删除决定持续有效。
32. 作为个人用户，我希望删除记忆时保留原聊天，以便仍可自行回看曾经的讨论。
33. 作为个人用户，我希望能够另行删除包含原文的来源，以便在需要时移除原聊天或附件内容。
34. 作为个人用户，我希望删除会话或附件前看到关联记忆，以便知道这次操作会影响什么。
35. 作为个人用户，我希望删除来源时默认一并删除由它产生的记忆，以便不必逐条寻找需要清理的内容。
36. 作为个人用户，我希望能够保留部分关联记忆并看到来源已删除的标记，以便保留仍有价值的信息且理解其来源状态。
37. 作为个人用户，我希望附件内容永远不被提取为长期记忆，以便资料中的他人信息不会进入我的个人记忆。
38. 作为个人用户，我希望“记住附件内容”仍只得到普通资料回答，不产生长期记忆。
39. 作为个人用户，我希望需要保存的事实必须在聊天消息中直接表达，以便长期记忆的输入边界清晰。
40. 作为个人用户，我希望删除附件时清理原文件和全部派生处理数据，以便不留下不可管理的内容。
41. 作为个人用户，我希望保存、修改或删除记忆失败时得到真实状态，以便不会误以为操作已经成功。

### 附件与资料问答

42. 作为个人用户，我希望上传文本型 PDF 并提问，以便理解报告和其他文字资料。
43. 作为个人用户，我希望上传 DOCX 并提问，以便处理 Word 文档中的文字内容。
44. 作为个人用户，我希望上传 TXT 或 Markdown，以便使用笔记和纯文本资料。
45. 作为个人用户，我希望上传 PNG 或 JPEG，以便让具备图片能力的模型理解图片。
46. 作为个人用户，我希望附件仅属于上传它的会话，以便清楚知道每段对话可以使用哪些文件。
47. 作为个人用户，我希望回到原会话后继续追问原附件，以便无需在同一会话反复上传。
48. 作为个人用户，我希望在新会话中重新上传文件后再使用它，以便保持会话之间的附件使用范围清晰。
49. 作为个人用户，我希望删除某个会话中的文件不会影响其他会话独立上传的文件，以便各个会话互不干扰。
50. 作为个人用户，我希望每条消息超过五个附件时得到明确提示，以便调整上传批次。
51. 作为个人用户，我希望单个文件超过 20 MB 时得到明确提示，以便缩小或拆分文件。
52. 作为个人用户，我希望 PDF 超过 200 页时得到明确提示，以便知道首版处理范围。
53. 作为个人用户，我希望扫描版 PDF、Excel 和音视频等本期不支持的类型得到清楚说明，以便选择其他资料形式。
54. 作为个人用户，我希望长文档显示处理状态，以便知道何时可以开始追问。
55. 作为个人用户，我希望解析失败或无法提取文字时得到说明，以便不会把缺失内容当作已经被理解。
56. 作为个人用户，我希望针对资料中的具体问题获得有依据的回答，以便快速定位相关内容。
57. 作为个人用户，我希望回答指出依据的文件及具体位置，以便核对引用是否准确。
58. 作为个人用户，我希望全文总结覆盖整份可处理的资料，以便不会把局部片段总结误当成全文总结。
59. 作为个人用户，我希望比较同一会话中的多份资料，以便找出不同文件之间的共同点与差异。
60. 作为个人用户，我希望知道文档内嵌图片和复杂图表需要单独上传为图片，以便理解文字提取的能力范围。
61. 作为个人用户，我希望删除附件后其派生检索内容也被清理，以便已移除的资料不会继续作为文件依据出现。

62. 作为个人用户，我希望助手能按需联网查询信息，以便获取模型已有知识之外的资料。
63. 作为个人用户，我希望联网回答附上可打开的来源链接，以便核对网络信息。
64. 作为个人用户，我希望联网搜索直接执行，即使查询包含附件或记忆中的个人信息也不需要额外确认。
65. 作为个人用户，我希望搜索停止或失败后不会继续使用迟到结果，以便控制实际执行状态。
66. 作为个人用户，我希望未配置搜索服务时得到配置提示，以便了解联网功能为什么暂时不可用。
67. 作为个人用户，我希望搜索失败时得到真实状态，以便不会把未完成的搜索当作已经查证的结果。

74. 作为个人用户，我希望估算费用与服务商实际账单明确区分，以便正确理解费用信息。

82. 作为个人用户，我希望聊天、资料处理、Mem0、嵌入和搜索产生的云端调用都记录服务返回的用量，以便核对完整执行过程。

84. 作为个人用户，我希望多轮工具调用和重试产生的真实调用也纳入统计，以便一次用户请求的成本不会被低估。

## Implementation Decisions

### 已确认的产品与技术约束

1. **范围与部署**：第一版面向个人本机使用。前端采用 React 与 TypeScript，后端采用 Python FastAPI；PostgreSQL 通过 Docker Compose 运行并使用持久化存储卷，前后端直接在本机运行，附件原文件本机保存。
2. **数据库与记忆系统**：PostgreSQL 是用户明确选择的数据库，Mem0 是用户明确选择的长期记忆实现。Mem0 自动判断记忆新增、更新和删除，应用负责来源、修改、删除与调用状态。
3. **领域概念**：会话、长期记忆、记忆条目、记忆来源、附件和文件引用按已有术语表定义使用。聊天记录、附件和长期记忆分别建模。
4. **应用职责**：组织会话执行、长期记忆、会话资料、联网搜索以及模型调用记录等 Module。调用者通过各自的 Interface 使用行为；Mem0 适配、来源判断与删除处理集中在长期记忆 Module 内。
5. **状态归属**：业务记录需要表达会话和消息、附件归属与处理状态、正式记忆标识、记忆来源、自动处理、修改或删除操作状态、用量与配置。不能通过把全部聊天或附件写成长期记忆来替代这些关系。
6. **记忆写入规则**：Mem0 只根据当前获准处理的用户消息自动判断新增、更新和删除；不建立候选记忆或逐条确认流程。
7. **记忆更正规则**：明确更正由 Mem0 或聊天记忆工具更新，旧值不再作为当前事实使用。
8. **跨会话使用**：已保存的相关记忆可在新会话自动使用，不要求逐次确认；附件仍严格按所属会话使用。
9. **删除记忆**：停止通过长期记忆使用该条目，阻止从同一旧来源自动重新生成，同时保留原聊天。删除记忆不意味着原聊天的相同信息在原会话回看时不可读。
10. **删除来源**：删除会话前列出关联记忆，默认一并删除，允许保留部分条目；保留项标明原始来源已删除。删除附件只清理文件及其派生检索内容。
11. **附件与记忆隔离**：附件内容不生成长期记忆。需要保存的事实必须由用户在聊天消息中直接表达；不保留附件记忆表或旧数据兼容逻辑。
12. **附件归属**：每次上传的附件属于当前会话。其他会话需要重新上传，不提供跨会话选择已有附件的文件库；删除一个会话及其附件不影响其他会话独立上传的文件。
13. **附件能力与限制**：支持文本型 PDF、DOCX、TXT、Markdown、PNG、JPEG。每条消息最多五个附件、单文件最多 20 MB、单份 PDF 最多 200 页，由后端执行限制并返回明确结果。
14. **解析与引用**：PDF 和 DOCX 主要依据可提取文字，复杂图表或内嵌图片需要单独作为图片上传。保留文件与页、段落或可识别位置的关系；失败和缺失内容不能被表述为已处理成功。
15. **长资料处理**：提供处理状态。具体问题查找相关内容，全文总结可以分段处理再汇总，不将局部检索结果冒充完整总结。
16. **联网搜索**：当前接入智谱 Web Search `search_std`，与模型配置分别管理，并作为普通模型工具自主调用。查询直接执行，附件或记忆中的个人信息不增加确认步骤；未配置或搜索失败时准确说明，不妨碍其他可用功能。
17. **模型连接**：首先支持 OpenAI 兼容的 Chat Completions。用户设置地址、密钥与模型名，首版先验证一套服务，分别核验文字、图片和工具调用能力，不保证任意兼容端点具有全部能力。
18. **用量覆盖**：调用状态及服务商返回的 token 或 credits 覆盖本应用全部相关云端调用，包括一次用户请求中的多轮调用、Mem0、嵌入、资料处理、搜索及重试。应用不估算价格或费用。
19. **交互契约**：会话列表与聊天主区域分开，提供设置页面；前端不展示长期记忆列表、正文、来源、召回结果或自动处理状态。回答逐步显示，可停止生成，失败后可重试。
20. **交付与代码规范**：提供启动说明与数据位置说明。所有新增或修改的函数、方法、构造函数、箭头函数和回调函数都须有用途说明注释，默认中文，修改逻辑时同步更新。

### 现有实现方案中的工程建议

以下内容来自此前提出的实现方案，属于实现基线建议，仍需锁定版本后验证；不将它们描述为用户已逐项确认或 SDK 已原生支持的能力。

1. 按数据本机持久化范围采用 Mem0 OSS，并以本机 PostgreSQL 的 pgvector 作为向量后端；资料使用独立检索集合，不进入 Mem0 的个人长期记忆集合。
2. 使用 Mem0 原生自动推理处理当前用户消息，并将正式新增、更新和删除映射到应用的稳定操作身份及来源记录；不另存候选内容。
3. 在长期记忆 Module 内提供 Mem0 历史存储的 PostgreSQL Adapter，覆盖历史、最近消息、初始化、关闭与重置等生命周期。该项是自定义集成建议，不是 Mem0 官方现成配置。
4. 删除流程验证正式记忆、派生索引和内部历史正文的处理，避免默认删除历史继续保留用户希望从记忆中移除的正文；防止旧来源自动恢复所需的标记不以保留原事实正文为前提。
5. 聊天与嵌入配置分别管理，允许服务支持时复用连接信息；显式记录嵌入模型及维度，切换后重建受影响索引，不混用不同模型的向量。
6. 模型和嵌入 Adapter 统一记录调用状态及返回用量，Mem0 内部请求不能绕过；初始化、批量操作和重试也需要覆盖。
7. 业务数据可采用 SQLAlchemy 与 Psycopg 访问，结构变更由版本迁移管理。数据库版本迁移属于实现机制，不增加本期面向用户的数据迁移工具。
8. 应用仅在本机地址提供访问；完整密钥由后端管理，设置读取返回配置状态或掩码，日志不记录密钥。关闭与本机持久化范围无关的 Mem0 默认遥测。

## Testing Decisions

用户已确认以下测试方案：主要通过应用对外接口验证用户可见行为，使用真实 PostgreSQL 与 Mem0、可控的外部模型替身；补充少量浏览器测试验证上传、来源删除和设置，并对 Mem0 自定义适配进行必要的契约验证。

1. **主要 Seam**：应用对外 Interface 是主要测试 Seam。测试通过用户可执行的操作提交请求、读取状态和结果，覆盖会话、附件、记忆、搜索及调用记录之间的完整行为，不为每个内部函数建立独立测试入口。
2. **好测试的标准**：以明确输入、外部可观察结果和持久化后的可用行为为断言。检验确认是否生效、来源是否准确、隔离是否成立、失败是否真实以及用量是否如实记录；不锁定提示词全文、私有方法调用顺序或内部对象布局。
3. **真实持久化与记忆**：集成测试使用真实 PostgreSQL 和 Mem0，避免用其他数据库或完全模拟的记忆系统替代关键语义。用受控外部 Adapter 返回确定的模型、嵌入与搜索响应，使网络波动和随机输出不影响规则验证。
4. **浏览器验证**：用少量高价值流程验证会话切换、附件上传、流式显示与停止、来源删除及设置状态。浏览器测试使用相同应用行为，不复制一套独立业务规则。
5. **额外的适配契约 Seam**：只针对 Mem0 自定义持久化和外部调用 Adapter 增加必要契约测试，覆盖初始化、写入、查询、修改、删除、重置、重启及错误恢复；这些验证补充主要应用测试，不能代替端到端产品行为。
6. **制定规格时的项目背景**：当时项目只有术语、需求、设计决定和实现方案文档，没有应用代码、既有测试或可复用测试 Seam，因此本规格先确定最高层的主要测试接口。后续实现与实际验证记录见 [集成记录](integration.md) 及各任务验收文档，不能把制定规格时的状态当成交付状态。
7. **真实服务验收**：配置实际服务后验证文字、图片、工具调用、嵌入与搜索，以及真实来源和用量响应。受控替身测试通过不代表真实服务已经兼容，尚未执行的真实调用不能标记为通过。

| 验收场景 | 可观察结果 |
| --- | --- |
| 新建、切换、重启后继续会话 | 已保存消息与附件关联可继续使用，流式或失败状态真实 |
| 明确要求保存记忆 | 条目保存成功后可查看，并在相关的新会话生效 |
| Mem0 自动记忆 | 根据当前用户消息完成新增、更新或删除；结果直接从 PostgreSQL 核对 |
| 明确更正记忆 | 新事实替换旧事实，失败时不虚报完成 |
| 删除记忆后重新查询 | 不再作为有效长期记忆召回，同一旧来源不会自动重建；原聊天仍按既定规则可回看 |
| 删除会话或附件 | 会话默认清理关联记忆且不展示正文；附件直接清理文件和派生数据 |
| 上传资料并要求提取记忆 | 不生成长期记忆，附件仍可用于当前会话问答 |
| 附件数量、大小与页数限制 | 验证上限内、恰好上限和超过上限的行为，超限明确拒绝 |
| 同一文件分别上传两个会话 | 各自独立使用，删除其中一份不影响另一份 |
| 新会话未上传旧附件 | 不通过普通回答或资料查询获得旧附件原文 |
| 文本、图片及无法解析的资料 | 支持的输入能够处理，缺失或失败被说明，不伪造已读取状态 |
| 长资料问答与全文总结 | 问答具有对应出处；全文总结不被局部片段替代 |
| 联网搜索及个人信息 | 由模型工具按需直接执行；结果有来源；停止或失败不伪造完成 |
| 服务未返回用量 | 调用记录保留空值，不把缺失数据计为零 |
| 未配置搜索服务 | 聊天、附件和长期记忆等其他能力仍可用 |
| Mem0、嵌入、批量调用和重试 | 全部经过统一调用记录，不从内部调用绕过 |
| 记忆操作或外部调用中途失败 | 不返回虚假成功；重试不会导致不符合用户意图的重复写入 |
| SDK 适配重启与重置 | 已约定的存储、删除与计费行为持续成立，不意外退回默认实现 |

## Out of Scope

- 多用户注册、共享账号体系及面向公众的服务。
- 手机原生应用、跨设备同步及云端托管部署。
- 自动发送邮件、修改外部系统和后台自主执行任务。
- 扫描版 PDF 的 OCR、Excel、音视频处理。
- 自动理解文字文档中的复杂图表、内嵌图片或任意复杂排版。
- 跨会话共享文件库、在新会话选择已有附件。
- 把助手回答或附件正文作为自动记忆输入，或把全部聊天直接写成长期记忆。
- 自行决定联网搜索。
- 自动备份以及面向用户的数据导入、导出与迁移工具。
- 第一版保证兼容所有模型服务商、任意嵌入模型或任意搜索服务。
- 完全离线的本地模型推理要求。
- 精确替代服务商账单，或保证整个服务商账户绝不超过应用内设置额度。

## Further Notes

- 本规格合成已有讨论；产品范围、PostgreSQL、Mem0 和 Docker Compose 的选择已明确，测试方案已在本轮确认。上一轮提出的 Mem0 历史存储、计费 Adapter 与具体嵌入接入仍属于工程建议和集成验证事项，不因写进规格就视为已经实现或测试通过。

- Mem0 历史及调用网关适配是早期集成验证重点。默认删除可能保留内部历史正文；应落实已确认产品规则，不静默放弃 PostgreSQL、Mem0、自动记忆或统一调用记录要求。
- 任务 01–20 的实现已按依赖集成，提供可运行应用、配置和启动说明、数据位置及分项验证记录；整体检查以 [集成记录](integration.md) 为准。任务 01 曾完成一次真实 DeepSeek 文字调用，其他未执行的真实服务兼容性、质量和账单验收仍标为待验，不用受控替身通过替代。

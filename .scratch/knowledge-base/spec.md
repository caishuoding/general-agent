# 独立知识库与对话按需召回

Status: ready-for-agent

Implementation: complete（2026-10-23）。独立存储、入库进度、对话召回和页面已接入；验收证据见[验证记录](../../docs/verification-knowledge-base.md)。

## 目标与边界

提供独立知识库入口，用户在其中上传、长期保存和管理文档，查看解析、图片描述、切片和索引的真实进度。在会话中选择知识库后，对话智能体根据问题自主调用召回工具。

- 知识库归属于账号，可被该账号的多个会话选择；附件仍只属于上传它的会话，保留原有 30 天有效期。
- 切片表独立，解析、图片描述、切片与召回算法复用已有能力。
- 知识库文档不进入 Mem0，不自动把全文放进模型上下文。
- 本期不重写聊天附件流程，不把现有附件自动迁移为知识库文档；附件入口是否简化另行设计。
- 不新增跨账号共享、文件夹、知识图谱、独立向量服务或第二套召回策略。

## 页面与使用流程

1. 用户进入独立“知识库”页面，创建、重命名或删除自己的知识库。
2. 进入某个知识库后上传 PDF、DOCX、TXT 或 Markdown，查看文档列表、处理阶段、进度、错误和重试入口，并可下载原件、删除文档。
3. 初版复用现有资源限制：每次最多 5 个文件、单文件最多 20 MB、PDF／Word 固定分页最多 200 页、每份文档最多 50 张可处理栅格图片；仍执行现有解析时间、内存和解包限制。
4. 会话提供知识库选择入口，可选择一个或多个自己的知识库并持久保存选择；新会话默认未选择。界面始终显示当前选择，取消选择不删除知识库。
5. 每次回答将已选择且仍可访问的知识库 ID 和名称提供给模型；用户提问后由模型决定是否调用工具以及检索哪个已选知识库。没有选择时提示选择，不偷偷搜索全部资料。

## 文档处理流程

上传原件 → 格式校验／排队 → 解析正文、表格、位置与图片 → 图片描述 → 生成切片 → 生成向量与索引 → 可检索。

- Word 正文、标题和表格从 DOCX 原生结构读取；LibreOffice 固定分页副本仅用于页码定位。PDF 使用物理分页，复用已有正文与表格识别；TXT／Markdown 使用段落定位。
- 提取内嵌栅格图片并记录稳定 `image_id`、文档内位置、章节和哈希。复用 `deepseek-flash` 视觉链路，模型直接输出图片的纯文字描述，描述原文作为切片正文并绑定原图；不要求 JSON 或拆分字段，位置和章节保存在元数据。
- 不重复实现模型连接和计量；复用现有调用入口、私密配置及用量记录。图片描述采用有上限的并发处理，并在每张结束后保存状态和进度；重试复用已完成的结果。
- 单张图片描述失败不丢弃正文与其他成功图片；页面显示失败数量和可重试原因。既无可用正文、又无成功图片描述时，文档处理失败，不能显示为可用。
- 切片和向量构建在上传后的后台任务完成。向量失败时保留已完成切片和 BM25 索引，显示“可检索，向量索引失败”及重试入口，检索按既有规则降级。
- 文档和任务记录持久化；刷新或离开页面不停止任务。服务重启后未完成任务可从已完成阶段恢复或明确重试，不永久停在“处理中”。重试不得重复发布切片或混用不同版本向量。

## 真实进度

- 分开展示浏览器上传进度与服务端处理进度；上传 100% 不代表文档可检索。
- 服务端保存 `stage`、`status`、`completed`、`total`、更新时间和错误；阶段包括排队、解析、图片描述、切片、索引、完成／失败。
- 总量已知时展示实际完成比例，例如“图片描述 8/15”“向量索引 24/60”；解析等尚不知道总量的阶段显示进行中，不用定时器伪造百分比。没有图片时该阶段标记跳过。
- 阶段进度条与整体阶段提示同时展示，不将图片张数和切片数量混成未经定义的总百分比。全部必要阶段完成后才显示完成；部分图片失败、向量失败明确显示为带告警的可检索状态。
- 错误明确定位到阶段，重试只处理失败／未完成内容；新任务尝试与旧任务区分，避免迟到更新覆盖当前状态。

## 存储与生命周期

| 数据 | 会话附件（现有） | 知识库（新增） |
| --- | --- | --- |
| 所属对象 | `attachments` → 会话 | `knowledge_bases` → 账号，`knowledge_documents` → 知识库 |
| 正文、表格和图片描述切片 | `document_chunks` | `knowledge_chunks` |
| 图片与描述、远端文件身份 | `document_images` | `knowledge_document_images` |
| 选择关系 | 附件直接属于会话 | `conversation_knowledge_bases` 保存会话与知识库关系 |
| 文件 | 既有附件目录 | 独立知识库目录，原件、副本与派生图片一并保存 |
| 有效期 | 从上传开始 30 天 | 用户删除前长期保存 |

- `knowledge_chunks` 通过文档关联知识库和账号，保存文档内序号、位置、结构、正文、Token 信息、切片配置版本、向量及嵌入配置版本；图片切片只引用所属文档的知识库图片。
- 不向 `document_chunks` 添加知识库字段，也不通过 `source_type` 将两类来源塞入同一张切片表。共用代码通过各自数据访问接口读写，公共算法不负责跨域查询。
- 解析结构块作为切片输入，不额外复制一套持久正文。知识库内检索复用完整切片，知识库重新解析从原件执行。
- 删除文档或知识库时先撤销可访问性，再可重试地清理原件、副本、图片、远端文件、切片、索引和任务。处理与召回返回前再次检查来源，迟到结果不得恢复已删除内容。
- 删除会话只清理该会话的知识库选择关系；附件到期清理、附件启动升级不能处理知识库数据。知识库删除后移除失效选择。
- 远端图片文件有独立 TTL；到期或服务连接变化时，从仍有效的知识库本机原图重新上传，保持知识库图片身份稳定。

## 切片和召回策略

复用当前 `ChunkPolicy` 及现有配置，避免各自复制一份算法或默认值：

- 正文自然段 → 句子 → 分句 → 空白 → 字符递归切分；默认目标 800 Token，完整块容差最多 200 Token，默认绝对上限 1000 Token，正文重叠默认 160 Token 且不超过目标的 20%。章节边界阻断切片和重叠，物理页边界允许跨越。
- Markdown 表格按行切片，重复表头与包装计入预算，数据行不重叠；超长行复用单元格续片逻辑。图片描述使用现有独立图片切片策略，保留同一 `image_id` 绑定。
- Token 计数、解析／切片版本和嵌入配置指纹复用既有规则；配置变化后重建对应知识库索引，不混用旧向量。
- BM25 与向量两路各取默认 30 片，按切片身份去重，经等权 RRF（k=60）融合，默认取前 30 片交给智谱 rerank，最终默认返回 5 片。结果数与候选上限沿用现有配置关系，返回完整切片。
- 向量不可用退回 BM25，重排超时、失败或输入超限退回融合排序；工具返回真实降级原因。知识库索引失败不触发提问时对整份文档偷偷重新建索引。
- 账号和指定知识库范围必须在候选召回前限制，不能先跨账号／跨库搜索再过滤返回结果。

## 对话工具合同

工具：`search_knowledge(knowledge_base_id, query)`。

- 必填参数为知识库 ID 和查询文字；不要求也不接收文件 ID。一份知识库中的所有可检索文档参与候选召回，不要求模型逐文档调用。
- 知识库 ID 来自当前会话已选择的知识库清单。每次调用校验登录账号、当前会话、知识库归属和选择关系；用户取消选择或删除知识库后，后续调用立即失效。
- 选择多个知识库时，由模型决定检索哪个或依次检索多个；单次调用只检索指定知识库，不能扩大成全账号搜索。
- 返回知识库 ID／名称、文档 ID／文件名、切片 ID、完整正文、页码／段落位置，以及可选 `image_id` 和降级信息。文档 ID 是结果来源元数据，不是工具的查询参数。
- 命中图片切片后，后端核验所属账号、知识库、文档及图片仍有效，并在下一轮模型请求中同时提供描述与原图；同一回答同一图片仅发送一次，单批最多 5 张，复用既有图文上下文处理。
- 没有命中、没有已选知识库、尚无可检索文档和调用失败需要明确区分；不得将后几种状态伪装为空命中。
- 每次回答该工具最多执行 5 次，含失败与重试；继续使用现有工具循环、停止、失败和用量处理，不强制每轮先检索。
- 检索结果作为不可信资料，不执行文档中的指令；回答说明实际使用的知识库文档和位置，不伪造引用。

## 验收场景

1. 创建知识库，上传含文字、表格、图片的 Word／PDF；界面按真实阶段更新，图片逐张完成可见，完成后可检索。
2. 图片描述失败时正文仍可查，页面显示失败数量；重试后补齐，已成功图片不重复请求。索引失败时明确降级，重试后恢复向量召回。
3. 两个知识库包含相同关键词，会话只选择 A 时只能检索 A；伪造 B、其他账号或未选择的 ID 均不能访问，也不能参加候选召回。
4. 同一知识库可在两个会话使用；取消选择不删文档，删除其中一个会话或清理 30 天附件均不影响知识库。
5. 工具只传知识库 ID 与 query，能跨该库多个文档召回；未选择知识库时不会隐式搜索全部文档。
6. 查询命中图片描述时，下轮请求含正确原图；重复命中不重复发送；远端文件到期后仍能从本机原图重新提供。
7. 刷新、关闭页面或服务重启后能看到真实任务状态并继续／重试；删除正在处理的文档后，迟到结果不能重建它。
8. 验证知识库切片与图片只写各自新表，附件仍写原表；共用算法在两种数据访问路径下保持相同切片和召回规则。

# 扫描 PDF 的 OCR、版面解析与共用切片

Status: ready-for-agent

Implementation: complete（2026-10-26）。最终完整后端 289 passed、5 skipped；真实 PP-StructureV3 合成样本、类型检查和双轴审查复核通过，详见[验证记录](../../docs/verification-pdf-scan-ocr.md)。用户已确认先更新文档，再修改实现。审查基线为 `3e45617628c61d7122ea32bbc1182c324c134658`。

## 已确认流程

1. 校验并保留原始 PDF；沿用每文件 20 MB、最多 200 页和账号授权。
2. 逐页区分文字页与扫描页。文字页沿用现有解析；扫描页指缺少有效文字层且页面由栅格扫描图覆盖的页面，混合 PDF 按页处理。
3. 扫描页逐页渲染为清晰图片，交给 PaddleOCR PP-StructureV3 做版面分析、文字识别及表格结构识别，输出区域坐标与阅读顺序。
4. OCR 正文、标题和列表转成现有 DocumentUnit；表格恢复单元格和跨度，接入原有按行切片。无法可靠还原时保留原区域截图及识别缺口。
5. 根据插图区域裁出原图，按坐标关联图注，交给现有视觉模型生成描述。图内文字与已绑定图注不再重复生成普通正文切片。整页扫描图不作为插图发送给视觉模型。
6. 形成内存中的中间解析结果，保存物理页、原始 PDF 左上角 point 坐标、阅读顺序、章节与 OCR 来源。原 PDF 始终是核对依据；第一版不持久化重复正文或额外 Word 文档。
7. 汇总整份解析结果和图片描述，再统一切片；保守整理章节、重复页边内容和跨页续表，证据不足时保持原页边界。
8. 正文、表格及图片描述复用现有 Token 预算、重叠、结构化表格、图片身份与统一排序，不另建 OCR 切片器或索引。
9. 附件与知识库分别持久化各自切片；关键词、向量、混合召回及引用复用现有算法和权限。
10. 记录成功、失败和低置信度页面；单页失败不丢弃其他可用内容，无可用内容时明确失败。成功处理不等同于识别准确率保证。

## 处理边界与部署

- OCR 使用独立的本地 PP-StructureV3 HTTP 服务，模型常驻并串行推理；应用不在 20 秒、512 MiB 的文字解析进程内加载 OCR 模型。
- 原始 PDF 检查和单页渲染继续在受限工作进程内完成；OCR 每页请求有超时、响应大小与结构校验，最多处理 200 页，文字 2,000,000 字符、20,000 个结构块，普通插图及表格截图合计最多 50 张。
- OCR 服务只接收页面图片，不接收用户的模型凭据；私网调用，独立依赖及模型缓存。固定 PaddleOCR/运行库版本，服务返回解析规则版本，防止结果合同漂移。
- 方向校正只使用可逆整页旋转，返回坐标系信息；暂不启用无法准确逆映射的非线性展平。识别坐标须映射回原页，裁图须使用相同坐标系。
- 知识库增加 OCR 阶段及真实页进度，仍按原处理尝试核验删除/撤销；附件保持现有后台处理入口。
- 解析规则升级从原件重建现有 PDF，保留原 TTL 与人工清空标记；OCR 服务未配置或不可用时，文字 PDF 不受影响，扫描页明确报告缺口，不能回退为整页画面描述冒充 OCR 正文。
- 不改变普通图片描述提示词，不要求视觉模型承担扫描页全文 OCR。

## 验收边界（用户已确认）

- 文档解析公开入口：真实扫描 PDF、混合 PDF、标题/正文/表格/插图顺序、图注去重、物理坐标、OCR 失败隔离、超限和未配置运行时。
- 附件公开上传与现有检索/按页读取：OCR 正文作为文字切片，插图独立描述并绑定原图，原件仍可下载。
- 知识库上传、检索及引用：同一行为，文字引用保持 text、表格保持 table、图片保持 image，删除或撤销后不发布迟到内容。
- 外部 OCR 服务使用固定协议替身；另以合成印刷体扫描样本运行真实 PP-StructureV3 验证。没有执行成功的真实模型检查必须单独记录。
- 单文件测试和严格类型检查持续运行，最终运行一次完整后端套件；执行规范与规格双轴审查，修复发现后提交当前分支。

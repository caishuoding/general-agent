# 对话主智能体与子智能体编排

## 目标与已确认范围

主智能体自主决定是否分工，通过异步工具创建多个子智能体，等待结果、补充任务或取消任务，最后统一回答用户。用户无需开启多智能体模式。普通问题保留直接回答路径，不增加关键词路由或每次必经的独立规划模型调用。

术语见 [GLOSSARY](../../GLOSSARY.md)，决策见 [ADR 0017](../../docs/adr/0017-main-and-subagent-orchestration.md)。主从默认共用当前文字模型配置，通过不同身份、系统提示、独立上下文与工具权限形成不同智能体；每个 `call_model` 都发出一次真实模型请求。

首版仅两层，子智能体不能创建下一级，也不彼此直接通信。子智能体在当前回答尝试内可继续接受任务，不跨用户消息或回答重试复活。首版只允许向空闲或已完成的子智能体追加任务；执行中追加返回结构化冲突，不隐式中断、不插入并发上下文。

## 完整执行图

实线为当前循环内的执行，虚线为后台提交或结果通知。创建工具不等待子任务完成；子任务只运行自己的工具图。

```mermaid
flowchart TD
    U[用户消息] --> P[prepare_context：历史、长期记忆、附件清单]
    P --> M
    subgraph MAIN[外层 agent 节点内：主智能体工具图]
        M[call_model：真实请求主模型] --> D{返回类型}
        D -->|业务工具| T[execute_tools：搜索、读取、记忆等]
        T --> TM[结果追加到主上下文]
        TM --> M
        D -->|spawn_agent| S[保存子智能体及执行轮次，提交任务]
        S --> ID[立即返回 agent_id、run_id、状态]
        ID --> M
        D -->|wait_agents| W[等待新结果；等待期间不调用模型]
        W --> R[返回新结果与可信来源，或超时状态]
        R --> M
        D -->|send_agent_message| F[给空闲子智能体新建执行轮次]
        F --> ACK[立即返回提交结果]
        ACK --> M
        D -->|cancel_agent| C[取消指定子任务]
        C --> CR[返回取消状态]
        CR --> M
        D -->|无工具调用| ANSWER[finish：返回主智能体回答]
    end
    S -.-> Q[有界任务队列：等待空闲名额]
    F -.-> Q
    Q -.-> A1
    Q -.-> B1
    subgraph A[子智能体 A：独立 State 与消息]
        A1[call_model：真实请求子模型] --> A2{有工具调用？}
        A2 -->|有| A3[执行获授权业务工具]
        A3 --> A4[结果追加到 A 上下文]
        A4 --> A1
        A2 -->|无| A5[finish：保存结果、证据与终态]
    end
    subgraph B[子智能体 B：独立 State 与消息]
        B1[call_model：真实请求子模型] --> B2{有工具调用？}
        B2 -->|有| B3[执行获授权业务工具]
        B3 --> B4[结果追加到 B 上下文]
        B4 --> B1
        B2 -->|无| B5[finish：保存结果、证据与终态]
    end
    A5 -.-> W
    B5 -.-> W
    ANSWER --> CLOSE[关闭分派并取消剩余子任务]
    CLOSE --> FINAL[finalize：核验引用，持久化正文及终态]
    FINAL --> UI[用户最终回答]
```

队列按任务所属智能体调度，一条任务只交给一个子智能体；图中 A、B 表示不同任务可并行。根图仍是 `prepare_context → agent → finalize`；调度器不是必须独立建成 LangGraph 节点。一个模型回复可以包含多个工具调用，创建调用依次返回 ID 即可让多个后台任务并行。单个智能体的上下文始终串行更新。

## 四个编排工具的合同

所有参数使用严格对象校验；账号、会话、回答尝试、父智能体、操作身份和模型配置由后端绑定，不接受模型指定。所有 ID 必须属于当前账号与回答尝试。工具失败作为结构化结果回传，不能因此绕过限额或静默创建替代任务。

### spawn_agent

参数：`title`（1–80 字符）、`task`（1–12000）、`context`（可选，最多 16000）、`expected_output`（1–4000）。

返回 `agent_id`、`run_id`、`status: queued`。在同一事务中验证根回答有效、预留创建额度、创建记录；提交后再调度。调度失败保存失败状态。幂等身份由后端绑定 `parent_run_id + model_round + tool_call_id`；重复执行同一调用返回原 ID，不重复占额度。内容相同但调用身份不同不自动合并。

创建成功后主模型带着工具结果继续执行，可自行使用业务工具、再创建子任务或等待，不自动等待子任务。

### wait_agents

参数：`agent_ids`（1–6 个，不重复）、`after_cursor`（可选，服务端返回的不透明游标）、`timeout_seconds`（默认 30，范围 0–30）。

等待任一目标出现尚未交付的终态结果，或超时、取消。返回新游标，以及各目标的 `agent_id`、`run_id`、`status`；新完成项额外包含 `result`、后端生成的 `sources` 或 `error`。目标已完成且未读取时立即返回；没有新结果且所有目标已结束时立即返回状态，不空等。

同一执行轮次的完整结果只交付一次；游标仅影响重复内容返回，不改变已交付记录。新增执行轮次产生新的结果版本。工具调用自身按调用身份幂等，重放保持原交付身份与结果版本，但每次返回（包括重放）均重新核验来源权限与有效性。来源撤销后不原样返回旧正文，返回 `source_invalidated` 状态，移除失效证据及依赖该证据的结论；无法可靠区分依赖时丢弃该轮完整结果。已进入运行上下文的失效材料也必须在下一模型请求前移除，无法安全清理时中止执行，不能只删 sources 而继续使用旧正文。等待不占子任务线程，不发模型请求，根取消会唤醒等待。超时仅返回状态，不取消子任务。主模型随后继续判断；反复超时仍受总轮数与时长限制。

### send_agent_message

参数：`agent_id`、`message`（1–12000 字符）。仅允许当前回答内最近一次执行已完成的子智能体继续工作；失败、取消、超时或已关闭的智能体不自动复活，需要主智能体重新创建。

保留该子智能体的已有任务、消息和工具结果，新建带独立操作身份的执行轮次；同一智能体最多一个 queued/running 执行，由事务与数据库约束保证。返回 `agent_id`、新 `run_id`、`status: queued`。运行中返回 `agent_busy`，不排入收件箱。最多三个执行轮次，包括首次任务；补充调用同样按主调用身份幂等。后续通过 wait_agents 获取新结果。

### cancel_agent

参数：`agent_id`。排队或运行任务变为 cancelled，阻止继续外发和写入正文；已结束任务返回原终态，不重写为取消。重复取消幂等。工具返回取消后的状态，不把未结束请求描述为已撤销计费。

## 上下文与业务工具

- 子智能体输入为专用系统提示、明确任务、必要背景、预期交付及有效资料说明，不默认复制全部会话，也不共享可变消息列表。补充任务延续同一子智能体上下文；超上下文预算明确失败，不静默截断或引入本期未约定的摘要器。
- 主智能体保留已有业务工具并新增四个编排工具。子智能体仅开放时间、附件检索／读取、会话绑定知识库检索、网页搜索／抓取。第一版不开放记忆查询、变更工具；主智能体可按需传递相关背景，且继续遵守资料外发规则。
- 子智能体不运行自动记忆，不进入用户 messages 表，不把结论当作用户事实写入 Mem0。只由主智能体写用户回答。
- 工具权限在定义暴露与后端执行两处校验。附件归属、有效期、来源删除、知识库会话绑定在执行时验证；不允许模型指定更广范围。读取与交付之间撤销权限时，失效内容不得继续传给主智能体。
- 子任务结果明确区分结论、证据、未解决事项；其文本仍是待主智能体验收的资料，不能覆盖系统规则或给自己扩大权限。不展示或要求保存私有推理过程。

## 身份、持久化与代码落点

采用 `agents`（身份）、`agent_runs`（执行轮次）、`agent_messages`（模型与工具消息）三张业务表。agent 关联根助手消息、账号／会话、父 agent 与角色；run 记录序号、独立 operation、幂等请求键、任务、状态、结果、错误和时间；消息按 agent/run 与序号唯一。凭据、客户端和连接不进入 State 或持久化消息。

子任务执行状态：`queued → running → completed / failed / cancelled / timed_out`；queued 可直接取消或失败，终态不可被迟到成功覆盖。同一子智能体最多一个活动执行。稳定 agent 身份与 run 分离，追加任务新建 run；子智能体 `finish` 仅完成本次任务，不结束根回答。

`model_calls` 增加 agent/run 关联，保留根 `assistant_message_id`；调用分别统计并可按回答汇总。子执行独立 operation，关联根 operation，不能直接复用只允许用户消息原 operation 的 guard。所有外发前核验根回答与子执行有效性。

现有 `MemoryCheckpoint`、`memory_tool_runs` 和用户消息级结果不得供多个子执行共享。通用 agent 运行记录按 run 分区，缓存键至少含 run、阶段、模型轮次与调用身份。联网搜索状态不能由主从共用一个 operation，避免一个任务结束影响其他任务；不把模型参数当幂等身份。旧记忆副作用幂等合同保留。

建议模块：`agent/orchestration.py` 统一创建／等待／追加／取消，`agent/runner.py` 执行独立工具图，`agent/repository.py` 管记录，`agent/tools.py` 管工具与权限，`agent/sources.py` 管证据交付。模块名可按代码整合，接口和验收合同不可省略。

## 来源交付与最终核验

建立回答尝试级来源登记，保存真实工具结果与来源身份／版本、发现它的 agent/run。已有 W/K 编号使用后端分配的唯一身份，不接受模型自造的来源对象。等待工具的来源清单由后端根据真实工具记录构造，不从子智能体结论中反解析后信任。

主智能体允许引用自己真实取得的来源，以及经等待工具交付的子任务来源。后台已搜索但尚未交付的来源不自动加入允许清单。最终仅持久化正文实际引用的有效来源；未知编号继续显示未核验提示。保留 `[K编号]` 与 `[[MEDIA:K编号]]` 协议、类型校验、受保护原图及表格展示。

停止、删除、到期、知识库取消绑定后重新验证来源；撤销来源不能通过缓存、追加任务或旧游标重新进入主上下文。图片、来源摘录及正文仍遵守原清理规则，新增记录必须纳入既有来源清理链路。

## 调度、预算与生命周期

- 单应用进程使用有界线程池和有界队列，数据库先提交、再提交任务。单回答并发最多 3、创建最多 6，每子智能体最多 3 次执行；主智能体不占子任务池。队列满返回明确的资源不足，不无界积累。
- 应用子任务总并发默认 6，账号子任务并发默认 3；同账号多会话也受共同限制。公平调度避免一个无空闲配额的账号堵住其他账号。排队与等待时间均计入总时限。
- 主智能体最多 24 次模型调用，每个子执行最多 12 次。根回答最多 96 次 agent 模型调用、24 次网页搜索／抓取，最长 600 秒；单子执行最长 180 秒。参数集中配置，根预算在外发前原子预留，失败的真实调用仍计数；实际 usage 按服务商返回记录。不声称这些限制是精确金额或 token 额度，首版不增加严格总 token 配额。
- 工具自己的次数及重试上限在各执行内保留，且不能绕过根预算。轮次耗尽返回明确失败；不因等待超时自动无限增加主模型轮次。
- 用户停止、根执行失败、主智能体完成最终回答、会话删除都关闭后续分派，取消所有活动子任务并唤醒等待。终态检查覆盖提交、外发、结果写入、交付和最终持久化。已发请求可以接收用量，不能恢复结果；不靠取消 Python future 保证业务取消。
- 超时计时器或监控负责在截止时设置终态并唤醒等待；阻塞网络线程受已有网络超时约束。停机时先取消与唤醒，再有界等待线程，不能无限 join。启动标记未完成执行为中断失败，不自动重发请求。
- 重试生成新回答尝试，不复活旧 agent。删除会话清理 agent 消息、任务和证据正文；历史调用仍按项目原有保留规则处理外键。

## 用户界面与传输

沿用现有消息 SSE 快照，在回答中增加 `agent_tasks` 简要列表：标题、agent/run ID、状态、简短结果或错误。默认折叠，展开显示任务、交付结果和可访问来源。详情经当前账号／会话授权按需加载，不在每个文字分片传送完整工作历史。

主回答之外不混入子智能体输出；不展示推理内容。刷新与断线重连从持久化记录恢复，切换会话关闭订阅但不取消任务。用户“停止生成”取消整个回答及全部子任务；首版不增加用户直接分派子任务入口。主从用量可在现有记录中辨认与汇总。

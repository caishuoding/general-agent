# 四个编排工具与有界并行调度

## 依赖与范围

依赖 [01 执行记录](01-execution-records.md)，落实[规格](../spec.md)中的四工具合同。创建立即返回 ID，等待不发模型请求，不占子任务线程；追加仅允许完成的子智能体，新建 run 延续原上下文；取消幂等。

## 验收

- 严格校验参数、账号与回答归属；spawn 与 send 按父执行、模型轮次和 tool_call_id 幂等。未知／跨回答 ID 不能读取或影响任务。
- 有界队列在提交失败／队列满时保存明确结果；真实并发不超过单回答、账号与应用限制，多会话不能绕过账号配额。等待不造成线程池死锁。
- wait 为零参数调用，交付当前回答任一子任务的新终态；同一 run 由持久化交付批次抑制重复正文，追加执行产生新交付。重放同一等待调用保持身份，但重新核验来源；失效时按规格清理相关正文与来源。
- send 在执行中返回 agent_busy，不偷偷排队；失败或取消执行不自动复活。completed 的补充任务保留上下文且受总执行轮次数限制。
- cancel 不重写既有终态，排队取消不再启动模型，运行取消阻止后续外发和业务写入。
- 按已确认的编排工具接口逐条 TDD，覆盖并发与竞态，避免测试调度器私有实现。

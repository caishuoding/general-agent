# 登录与后台账号管理规格

Status: ready-for-agent

Completion: implementation complete (2026-10-19); real cloud HTTPS deployment pending.

## Problem Statement

当前应用没有账号和登录，任何能够访问服务的人都可以使用全部对话、附件、记忆和管理配置。应用计划部署到公网云服务器，需要在不开放自助注册的前提下，由管理员预先创建账号，并确保每个账号的数据相互隔离。

管理员还需要一个独立管理端来创建、停用账号和重置临时密码，并能只读查看所有账号的会话、附件、记忆、搜索记录和调用用量。现有单用户数据在升级时先备份再清空，避免历史全局数据被错误归属给某个新账号。

## Solution

增加用户名密码登录、服务端登录会话和独立管理端。系统预置初始管理员 `admin / 123456`，所有账号首次登录必须修改密码；初始管理员改密前只允许通过服务器本机或 SSH 隧道登录。普通用户使用 `/` 聊天端，只能访问自己的对话数据；管理员使用 `/admin` 管理端，负责账号管理、跨账号只读查看和系统配置，不进入用户聊天界面。

模型、嵌入和搜索配置继续是全局配置，仅管理员可以修改。公网部署使用 Docker 运行应用、PostgreSQL 和 Mem0，Nginx 监听 `443` 并反向代理到 `127.0.0.1:8000`；没有域名时使用自签名证书。升级流程先备份现有业务数据，再清空会话、消息、附件、记忆、搜索和用量记录，保留现有服务配置。

## User Stories

### 登录与账号

1. 作为账号持有人，我希望使用用户名和密码登录，以便只有获得账号的人可以使用应用。
2. 作为首次登录的用户，我希望被强制设置新密码，以便管理员提供的临时密码不会长期有效。
3. 作为已登录用户，我希望主动退出，以便在共用设备上结束访问。
4. 作为已登录用户，我希望在不退出其他设备的情况下修改自己的密码，并在修改后让其他旧会话失效。
5. 作为被停用的账号持有人，我希望无法继续登录，以便管理员能够收回访问权限。
6. 作为用户，我希望系统不存在注册入口，以便账号只能由管理员创建。

### 管理端

7. 作为管理员，我希望创建普通用户或其他管理员，并设置临时密码，以便在没有邮件系统的前提下开通账号。
8. 作为管理员，我希望停用或重新启用账号，以便控制访问而不删除历史数据。
9. 作为管理员，我希望重置账号的临时密码并强制其下次登录改密，以便用户忘记密码时恢复访问。
10. 作为管理员，我希望系统阻止停用或降级最后一个有效管理员，以便后台不会失去管理者。
11. 作为管理员，我希望只读查看所有账号的会话、消息、附件、长期记忆、搜索记录和调用用量，以便排查问题。
12. 作为管理员，我希望下载用户附件，但不能代替用户发消息、修改记忆或删除用户内容，以便查看权限与写入权限分离。
13. 作为管理员，我希望查看他人内容时写入审计记录，以便知道谁在什么时候查看了什么。

### 数据隔离与升级

14. 作为普通用户，我希望只能看到自己的会话、附件、记忆和用量，以便不同账号的数据不会互相泄露。
15. 作为管理员，我希望自己的聊天数据也与其他账号隔离，后台查看能力不改变对话中的身份。
16. 作为部署者，我希望升级前自动生成数据库和附件备份，以便清空旧数据后仍可恢复。
17. 作为部署者，我希望升级后保留模型、嵌入和搜索配置，以便不需要重新填写服务密钥。
18. 作为部署者，我希望应用只通过 HTTPS 暴露，并且应用端口不直接对公网开放。

### 补充行为边界

19. 作为管理员，我希望用户名格式不合法时得到明确提示，以便创建账号时及时发现输入错误。
20. 作为管理员，我希望重复用户名被拒绝，以便每个账号都有稳定且唯一的登录标识。
21. 作为登录失败的用户，我希望只看得到统一的“用户名或密码错误”，以便系统不泄露账号是否存在。
22. 作为长时间未操作的用户，我希望会话过期后回到登录页，以便不会继续停留在失效的界面。
23. 作为已退出或被停用的用户，我希望旧的流式回答订阅和附件访问也立即失效，以便吊销会话不只是隐藏页面。
24. 作为修改密码的用户，我希望弱口令被拒绝并看到具体规则，以便能够设置符合要求的密码。
25. 作为被管理员重置密码的用户，我希望下次登录必须改密，以便临时密码不会长期有效。
26. 作为管理员，我希望后台不显示密码哈希、完整 API 密钥或会话令牌，以便管理权限不扩大为凭据泄露。
27. 作为管理员，我希望审计记录只能追加、不能在后台修改或删除，以便跨账号查看有可靠追溯。
28. 作为普通用户，我希望直接请求后台接口也被拒绝，以便隐藏后台入口不是唯一的安全边界。
29. 作为普通用户，我希望系统即使直接访问也不存在注册接口，以便账号只能由管理员创建。
30. 作为被停用的用户，我希望无法登录但历史数据仍被保留，以便账号可以被管理员查看或重新启用。
31. 作为管理员，我希望自己的聊天身份与其他账号保持隔离，以便后台跨账号查看能力不会污染自己的会话列表。
32. 作为部署者，我希望清空业务数据前备份可校验，并且备份失败时升级停止，以便不会在无备份的情况下丢失旧数据。
33. 作为部署者，我希望没有域名时仍能通过公网 IP 的 `443` 使用 HTTPS（自签名证书），以便登录流量不会以明文传输。
34. 作为管理员，我希望只能查看和下载用户内容，不能调用发送消息、修改记忆或删除用户内容的接口，以便查看权限不会变成写权限。
35. 作为已登录用户，我希望界面显示自己的用户名和退出入口，以便清楚当前使用的是哪个账号。

## Implementation Decisions

### 账号与角色

- 账号字段至少包含：稳定 UUID、用户名、密码哈希、角色、状态、是否必须改密、创建时间、更新时间、最近登录时间和最近改密时间。
- 用户名规则为 3–32 位小写字母、数字或下划线，大小写不敏感且全局唯一；不允许中文、空格和邮箱格式。
- 角色只有 `admin` 和 `user`。管理员只使用独立管理端，管理账号、查看所有用户内容和系统配置；普通用户只使用用户聊天端。
- 账号状态只有 `active` 和 `disabled`。停用立即吊销全部登录会话，但保留业务数据。
- 不提供物理删除账号。最后一个有效管理员不能被停用，也不能被降级为普通用户。

### 初始管理员与强制改密

- 数据库迁移预置用户名为 `admin` 的管理员，密码为 `123456`，标记为必须改密。开发和测试环境使用同一初始账号。
- 所有新账号首次登录都必须改密；管理员重置密码后，该账号也重新进入必须改密状态。
- 初始管理员完成首次改密前，登录只接受来自服务器本机或 SSH 隧道的请求。实现上只信任反向代理写入的来源地址；不带可信代理头的回环请求视为本机登录。
- 必须改密状态下，除读取当前账号、退出和修改密码外，其他业务接口返回明确的“请先修改密码”状态。

### 密码

- 密码使用 Argon2id 哈希，数据库中不保存明文或可逆密文。
- 新密码至少 10 个字符，不能与用户名相同，并拒绝常见弱口令；不要求大小写或符号组合，不做定期过期。
- 用户自行改密需要验证当前密码；改密成功后吊销该账号的全部旧会话，并建立当前浏览器的新的登录会话。
- 登录失败统一返回“用户名或密码错误”，不区分账号不存在、密码错误或账号停用。
- 本期不实现登录失败次数限制、账号锁定或验证码；这是已确认的风险接受项。

### 登录会话

- 会话使用服务端保存的不透明随机令牌；数据库只保存令牌哈希、账号标识和过期时间。
- 浏览器 Cookie 设置 `HttpOnly`、`Secure`、`SameSite=Lax`，有效期 7 天，路径限定为应用根路径。
- 登录成功时创建新会话；退出时删除当前会话；改密、管理员重置密码或停用账号时删除该账号全部会话。
- 所有非公开 API 都要求有效会话，并按当前账号过滤数据。静态前端页面和登录接口可以匿名访问，其他接口默认拒绝。

### 权限边界

- 普通用户只能访问归属于当前账号的会话、消息、附件、记忆、搜索记录和用量。
- 管理员不能调用用户聊天、附件、记忆和用量接口；跨账号查看只通过管理端只读接口完成。
- 后台只读接口不能调用发送消息、停止生成、修改记忆、删除会话或删除附件的写入逻辑。
- 管理员查看他人会话、消息、附件、记忆、搜索或用量时写入审计记录，记录管理员、目标账号、资源类型、资源标识、动作和时间。
- 模型、嵌入和搜索配置的读写接口仅管理员可访问；普通用户不需要读取这些配置。

### 模块边界

- 认证与账号模块负责凭据校验、密码哈希、服务端登录会话、强制改密和当前账号解析。
- 后台管理模块负责账号创建、停用或启用、临时密码重置、跨账号只读查询和管理员审计。
- 会话、附件、长期记忆、搜索和用量模块继续负责原有业务，但统一接收当前账号标识并按账号过滤。
- 前端分为用户端和管理端两个入口：`/` 提供普通用户聊天、强制改密和主动改密；`/admin` 提供独立管理员登录、账号管理、用户数据查看和系统配置。
- 部署配置增加反向代理、HTTPS、可信 Host 和首次改密前的本机访问限制。

### 数据归属与迁移

- `conversations` 增加非空 `user_id`，并建立按账号和创建时间的索引。
- 顶层业务记录增加账号归属：会话、调用记录、搜索请求、记忆动作、云操作和记忆召回必须能够按账号直接过滤；其余记录通过会话或所属动作关联。
- Mem0 的 `user_id` 使用账号 UUID 字符串，不再使用固定 `local-person`。自动记忆、召回、更正、删除和工具查询都必须使用当前账号标识。
- 升级前在应用数据目录下的专用备份目录生成带时间戳的备份，其中包含 PostgreSQL 导出和附件目录压缩包；不自动删除备份。
- 迁移清空现有会话、消息、附件记录与文件、长期记忆、来源、搜索、用量和相关操作记录；保留模型、嵌入和搜索配置文件。
- 附件原文件清空后，新附件仍按现有附件存储约定保存，归属由会话和账号决定。

### 接口边界

- 认证接口提供登录、退出、读取当前账号和修改自己的密码；登录请求携带 `expected_role`，用户端只接受普通用户，管理端只接受管理员。
- 后台账号接口提供账号列表、创建账号、停用或启用账号、重置临时密码；普通用户访问返回禁止访问。
- 后台只读接口按目标账号提供会话、消息、附件、记忆、搜索和用量的读取能力；附件下载单独记录审计。
- 现有会话、聊天、附件、记忆、搜索、来源删除和用量接口全部要求有效登录会话，并按当前账号过滤。
- 后台接口和普通用户接口都复用现有业务读取逻辑，不复制一套独立的数据规则。
- 最后一个有效管理员被停用或降级时返回冲突状态；用户名重复或格式错误时返回输入校验错误。

### 前端

- 未登录时只显示登录页，不加载会话列表或设置页。
- 必须改密时只显示改密页，并提供退出入口；完成改密后进入聊天界面。
- 用户端已登录界面显示当前用户名和退出入口，不显示管理端入口；管理员在用户端登录会被拒绝或转到管理端。
- 管理端提供账号列表、创建账号、停用或启用、重置密码，以及按账号查看会话、消息、附件、记忆、搜索和用量的只读入口。
- 普通用户不显示后台入口，也不显示模型、嵌入或搜索配置。

### 部署与 HTTPS

- 应用、PostgreSQL 和 Mem0 使用 Docker 运行；应用容器只绑定宿主 `127.0.0.1:8000`。
- Nginx 监听公网 `80/443`，把 `443` 请求反向代理到 `127.0.0.1:8000`；`80` 跳转到 `443`。
- 没有域名时使用包含 IP SAN 的自签名证书，浏览器会提示证书不受信任。
- 可信 Host 列表包含 `127.0.0.1`、`localhost`、`[::1]` 和公网 IP。
- 反向代理必须覆盖而不是透传客户端提供的来源头，确保初始管理员的本机登录判断可靠。
- 启动文档补充 Docker 启动、容器内首次改密、Nginx 443 配置、备份恢复和公网访问检查步骤。

## Testing Decisions

主要通过应用对外接口验证行为，使用真实 PostgreSQL 和受控 Mem0、模型替身；前端用浏览器测试覆盖用户端登录、强制改密、普通用户隔离和独立管理端关键路径。

### 测试 Seam

- 主 Seam 是 FastAPI 应用对外接口：测试通过登录、会话、附件、记忆、搜索和后台请求观察外部行为，不为认证服务或权限辅助函数另建内部测试入口。
- 持久化使用真实 PostgreSQL；模型和 Mem0 使用现有受控替身注入，保证登录、隔离和后台读取在接近真实的事务与存储语义下验证。
- 浏览器 Seam 是物理启动的应用加 Playwright，覆盖 `/` 用户端和 `/admin` 管理端的登录、强制改密、普通用户隔离和管理界面；它复用同一套应用接口，不复制业务规则。
- 不新增第三套内部 seam；公网 HTTPS、Nginx 和端口暴露通过部署 smoke check 验证。

### 测试原则与先例

- 好测试只断言外部可观察结果：能否登录、能否读取、是否被拒绝、会话是否失效、审计是否留下记录，以及迁移后数据是否正确清空或保留。
- 不锁定提示词全文、私有函数调用顺序、数据库行布局或前端组件内部状态。
- 现有会话、聊天、附件、记忆、搜索和用量测试已经采用“应用接口 + 真实 PostgreSQL + 受控模型/Mem0 替身”的先例；认证测试沿用同一模式。
- 现有 Playwright 测试已经采用物理启动应用和受控服务的方式；登录与后台测试沿用这一浏览器 seam。

1. **认证**：验证正确登录、错误密码、停用账号、会话过期、退出、改密后旧会话失效和管理员重置密码后的强制改密。
2. **初始管理员**：验证 `admin / 123456` 首次登录后必须先改密，改密前公网来源登录被拒绝，本机来源可以完成初始化。
3. **权限隔离**：用户 A 不能读取或修改用户 B 的会话、附件、记忆、搜索和用量；管理员不能调用用户聊天接口，只能在管理端只读查看 B 的内容。
4. **账号管理**：验证创建普通用户和管理员、停用与启用、重置密码、用户名唯一性，以及最后一个管理员保护。
5. **审计**：管理员查看他人内容后产生包含管理员、目标账号和资源标识的审计记录；未查看时不产生记录。
6. **迁移**：在包含旧会话、附件和记忆的测试库上执行升级，验证备份文件存在、业务数据被清空、配置被保留、初始管理员可用。
7. **Mem0 隔离**：不同账号的自动记忆、召回、更正和删除使用不同 `user_id`，互不读取。
8. **前端**：浏览器验证登录页、强制改密页、普通用户看不到后台入口、管理员可创建账号并查看他人只读内容。
9. **部署检查**：验证 Nginx 通过公网 IP 的 `443` 提供 HTTPS、应用端口不对公网开放、Cookie 带 `Secure` 和 `HttpOnly`。

## Out of Scope

- 自助注册、邀请码注册和公开账号申请。
- 邮箱找回、短信验证码、双因素认证和第三方登录。
- 登录失败次数限制、账号锁定、验证码和 WAF 规则。
- 用户配额、计费套餐、组织或租户隔离。
- 账号物理删除及其数据级联删除。
- 管理员代替用户发消息、修改记忆、删除会话或修改用户资料。
- 自有域名、ICP 备案和正式企业版多租户能力。
- 自动备份调度、备份轮换和面向用户的数据导出工具。

## Further Notes

- 架构决策与取舍见 [ADR 0010：预创建多账号、登录会话与管理员后台](../../docs/adr/0010-precreated-accounts-and-admin-console.md)。
- 初始密码 `123456` 是用户明确确认的生产环境初始凭据；它只作为首次改密前的引导账号存在。首次改密前必须保持公网登录关闭。
- 不做登录限流是用户明确接受的风险。公网暴露后仍可能发生持续暴力尝试；后续若改变决定，应优先在 Nginx 和应用层同时增加限流。
- 自签名 IP 证书只解决传输加密，不提供浏览器信任；正式部署或企业版仍应配置自有域名和正式证书。
- 现有数据清空属于不可逆业务操作；实现时必须先完成备份校验，再执行清空，并在文档中提供恢复步骤。
